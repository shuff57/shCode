## Software engineering action

**Read before attempting `1.1.13 Reading — Task Sets`.**

What you'll learn from it:

- A software engineering action is a named job inside a phase.
- "Define the requirements" is one example of an action that lives inside inception.
- Every action has a goal, and each phase contains several actions.

**Try it:** Run the block below to see one action you would expect inside each phase.

```js live plain
console.log("inception: define the requirements");
console.log("elaboration: design the architecture");
console.log("construction: code and build the software");
console.log("deployment: release to end users");
```

## Naming actions inside a phase

What you'll learn from it:

- An action answers *what job gets done* inside a phase, not how.
- An action is a named, recognizable piece of work — not the whole phase and not a single keystroke.

**Try it:** Log one action you would expect inside construction.

```js live plain
console.log("an action in construction: code and build the software");
```
