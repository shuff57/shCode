## The two namings, side by side

You have seen the lifecycle cut two ways this module, and they do not contradict each other. Part 4
asks you to line them up. Read this, then close it and answer in your own everyday words.

| Five phases (the `1.1.5` video) | What happens in it | Where it lives in the four activities (`1.1.6`) |
|---|---|---|
| **Design** (planning & requirements) | Work out what to build and how it should behave, before any code exists. | Split across **inception** and **elaboration** |
| **Development** (coding) | Write the actual code that makes the software work. | **Construction** |
| **Testing** | Check the software does what it should, and fix what it does not. | No activity of its own — an **umbrella activity** running across all four |
| **Deployment** | Release it so real people can actually use it. | **Deployment** |
| **Maintenance** | Keep updating, fixing and improving it after release. | No activity of its own — the work that continues **after deployment** |

The five-phase version simply gives testing and maintenance names of their own. Nothing is added or
removed; the same work is grouped differently.
