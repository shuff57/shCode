## What an umbrella activity is

**Read before attempting `1.1.11 Name That Umbrella`.**

What you'll learn from it:

- An umbrella activity is work that runs alongside *every* phase, not inside one.
- The six listed are training/communication, risk management, configuration management, quality management, architecture management, and security management.
- Umbrella activities belong to no single phase: they hold the whole project up.

**Try it:** The kitchen-cleanup analogy: the four phases are like cooking a meal, and umbrella activities are the cleanup that keeps the kitchen usable the whole time. Run the block below to log two umbrella activities and, for each, which phase you think it touches most.

```js live plain
console.log("quality management - touches: every phase");
console.log("risk management - touches: every phase");
```

## Why they belong to no single phase

What you'll learn from it:

- An umbrella activity never *starts and ends*: it runs the whole project.
- Training, quality, security, and the rest apply whether you are planning, designing, coding, or shipping.

**Try it:** Change the block to list a different umbrella activity (like security management) and a phase you think it touches most.

```js live plain
console.log("security management - touches: deployment");
```
