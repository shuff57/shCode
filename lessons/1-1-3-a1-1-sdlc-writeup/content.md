## The five phases, before you start

This is the same lifecycle the `1.1.5` video walks through. It is here in writing too, so you are
never stuck waiting on a video to load. Read it, then close it and write the phases in your own
everyday words — copying these sentences back will not pass criterion 2.

| # | Phase | What happens in it | Why it matters |
|---|-------|--------------------|----------------|
| 1 | **Design** (planning & requirements) | Work out what to build and how it should behave, before any code exists. | A wrong decision here is cheap to change now and expensive to change later. |
| 2 | **Development** (coding) | Write the actual code that makes the software work. | This is the phase people picture when they hear "programming" — and it is only one of five. |
| 3 | **Testing** | Check the software does what it is supposed to, and fix what it does not. | Users find the bugs you do not. Testing decides which of you finds them first. |
| 4 | **Deployment** | Release it so real people can actually use it. | Software nobody can reach has no value, however good the code is. |
| 5 | **Maintenance** | Keep updating, fixing and improving it after release. | Most of a product's life is spent here, not in development. |

**How this maps to the four phases you read about in `1.1.6`.** Design covers the book's
*inception* and *elaboration*; development is *construction*; deployment is *deployment* in both.
The five-phase version simply gives **testing** and **maintenance** names of their own instead of
folding them into umbrella activities and post-release work.
