## Plan before you build

Every game in this unit gets a plan first. A plan is not code. It is a short list that says what the game is made of, so the first thing you type is the right thing.

**Pocket, in one paragraph.** A pool game is five parts: a table, a cue ball, a pointer you can pull back from, a way to describe the shot, and a rule for when the ball stops. For each part, ask: does the game have to *remember* something about it from frame to frame (where the ball is, its speed, how many shots)? If so, that is a variable, and the plan names it.

There is no wrong answer. A plan you can say in plain words is worth more than a clever one.

Write your response in the box below. Short sentences or a numbered list both work. Aim to cover:

1. At least four parts of the game.
2. At least two things it must remember between frames.
3. What you would build first, and why.
4. One part you are unsure about.
