## Plan before you build

Every game in this unit gets a plan first. A plan is not code. It is a short list that says what the game is made of, so the first thing you type is the right thing.

**The scene you already have.** In 5.2.24 you built a pinball scene: gravity, a few things for the ball to bounce off, a bouncy ball, and a key that puts the ball back at the top. It looks like pinball, but nothing is at stake. (5.3.0 let you play the finished game; if you are short of ideas, play it again.) This module turns it into a game by adding four things: a goal to aim at, a score that counts, a way to lose, and a way to start again.

**What a plan lists.** Break the game into parts: the things it has (a ball, bumpers, a goal) and the things it does (counting, ending, restarting). Then, for each part, ask whether the game has to *remember* something about it from one moment to the next, such as a score. A thing the game remembers is a variable, and a good plan names it.

Write your response in the box below. Short sentences or a numbered list both work. Aim to cover:

1. At least four parts of the game.
2. At least two things it must remember.
3. What you would build first, and why.
4. One part you are unsure about.
