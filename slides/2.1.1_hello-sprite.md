## What is q5play?

- Built on **q5.js** (a tiny, fast p5.js-compatible engine).
- Adds **Box2D physics** — collisions, gravity, joints.
- Runs entirely in your browser. No installs.

## The setup / draw skeleton

```js
function setup() {
  // runs ONCE when the program starts
}

function draw() {
  // runs EVERY FRAME — about 60 times per second
}
```

- Key mental model: `setup()` builds the world. `draw()` animates it.
- Common beginner bug: putting `new Sprite()` in `draw()` — makes 60 sprites/second.

## Our first sketch (live code)

```js
function setup() {
  new Canvas(400, 400);
}

function draw() {
  background('#222');
  new Sprite(200, 200, 40, 40);
}
```

- Run. Gray canvas, square in the middle.
- Ask class: "What's wrong with putting `new Sprite` inside `draw()`?"
- Hoist the sprite out → store in a variable.

## Hoisting the sprite

```js
let player;

function setup() {
  new Canvas(400, 400);
  player = new Sprite(200, 200, 40, 40);
  player.color = 'deepskyblue';
}

function draw() {
  background('#222');
}
```

- One sprite, created once, rendered automatically every frame.
- `.color`, `.pos`, `.vel`, `.rotation`, `.layer` — properties you can read or assign.

## The frame loop (whiteboard)

- **60 frames per second.**
- `draw()` runs once per frame.
- `vel.x = 4` moves the sprite 4 pixels per frame = **240 pixels per second**.
- On a 400-px canvas that's 1.67 seconds to cross.

## AP CSP connection — how q5play reached your browser

- DNS looked up the server IP.
- HTTP request went out over TCP.
- Server sent back HTML + JavaScript.
- Your browser executed the code. Sprite appeared.
- All in milliseconds.

## Session 2 — Keyboard input

## kb.pressing — the input primitive

```js
if (kb.pressing('left'))  player.vel.x = -4;
else if (kb.pressing('right')) player.vel.x = 4;
else                        player.vel.x = 0;
```

- **Returns true every frame while the key is held.**
- Why the `else` branch? If you skip it, `vel.x` stays at its last value — sprite drifts forever.

## Why not arrow keys?

- Arrow keys **also scroll the browser iframe**.
- Use WASD for in-app labs. Arrow keys only when you're sure they won't fight page scroll.

## Live demo — Make it Move

```js
function draw() {
  background('#222');

  if (kb.pressing('a')) player.vel.x = -4;
  else if (kb.pressing('d')) player.vel.x = 4;
  else player.vel.x = 0;

  if (kb.pressing('w')) player.vel.y = -4;
  else if (kb.pressing('s')) player.vel.y = 4;
  else player.vel.y = 0;
}
```

- Run. Hold W → up. Hold D → right. WASD moves smoothly.

## Screen coordinates

- **Y increases downward** (not like math class!).
- Up = negative Y. Down = positive Y.
- Don't fight it — `vel.y = -4` moves up.

## Common bugs to watch for

1. Forgot `background()` → trails everywhere.
2. Forgot else-to-zero → sprite drifts.
3. Used `vel.x = 50` → launched off-screen. Try 2–6.
4. Put `new Sprite()` inside `draw()` → 60 sprites per second.
