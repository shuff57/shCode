# Module 3.2: Parameters and Return Values

## Module Goal
Students pass values into a function and hand a result back with `return`, and can say why a function that prints is not the same as a function that returns.

## Pre-requisite snapshot
Module 3.1 (Functions: Definition and Calls) complete.

## Post-requisite snapshot
Students write functions that take parameters and return values: the shape every later chapter is built from.

## Learning Objectives

Students will be able to:
1. Write a function with a parameter and explain that a parameter is a name that receives a value when the function is called (3.2.2–3.2.4).
2. Tell a parameter from an argument, and point to each in a definition and at a call site (3.2.5).
3. Call a function with several arguments in the right order, and explain why swapped arguments give a wrong answer with no error (3.2.7, 3.2.9).
4. Predict what a parameter holds when its argument is missing (`undefined`), and write a default parameter (3.2.7, 3.2.8).
5. Trace the values of the parameters through a call on a flow chart (3.2.10).
6. Use `return` to hand a value back, and use the returned value in a variable or an expression (3.2.11–3.2.13).
7. Explain that `return` ends the function, and write an early-return guard clause with no `else` (3.2.14, 3.2.15).
8. Explain the difference between printing and returning, and fix a function that prints when it should return (3.2.16–3.2.18).
9. Pass the value one function returns into another function, in either order (3.2.20–3.2.23).
10. Tell a local variable from a global one, and predict where a variable can be read, including the `ReferenceError` (3.2.24, 3.2.25).
11. Write small functions that return a decision or a total: `findMax`, `isEven`, `largest`, `sumToN` (3.2.26–3.2.28).

## Topics Covered

*Getting values in*
- Parameter, argument, definition and call site
- Argument order (positional matching) and the silent bug of swapped arguments
- A missing argument is `undefined`; the default parameter

*Getting a value out*
- `return`: sends a value back and ends the function
- The return value in a variable, an expression or another call
- Early return and the guard clause
- Printing is not returning; the missing return that produces `undefined`
- Calls nested inside calls; chaining two functions

*Where variables live*
- Local and global scope, and the `ReferenceError`

*Practice shapes*
- A comparison that returns the larger value; the remainder operator for even or odd
- A `for` loop with a running total and one `return` after the loop

## Prerequisites

- Module 3.1 (Functions: Definition and Calls): defining a function, calling it, and why functions exist.
- `if` / `else` and comparison operators (Module 2.1), `for` loops (Module 2.2), `%` and string indexing `word[0]` (Modules 1.2 and 2.2).

## Vocabulary

| Term | Definition |
|---|---|
| Parameter | A name in a function's definition that acts as a variable inside the body |
| Argument | The actual value handed in when the function is called |
| Return value | The value a call produces, usable in a variable or in a larger expression |
| undefined | What a call produces when the function finished without a return, and what a parameter holds when its argument is missing |
| Default parameter | A fallback written with = in the definition, used only when the argument is missing |
| Early return | Returning as soon as the answer is known, instead of branching with else |
| Missing return | The usual cause of undefined when the computation itself was correct |
| Scope | The region of a program where a variable is visible and usable |
| Local variable | A variable declared inside a function, usable only there |
| Global variable | A variable declared outside every function, usable anywhere |

## Teacher Notes

**Misconceptions to look for**
- **Print versus return.** The most common one in the module. The student's function prints the right answer, so it looks correct, but the next line gets `undefined`. Ask: "Where did the value go after the console showed it?" 3.2.12, 3.2.16 and 3.2.18 are built for this; do not skip them.
- **`undefined` from a missing return.** A student whose result is `undefined` almost always has the right arithmetic and no `return`. Have them read the function top to bottom and find the word.
- **Parameter versus argument.** Students use the words interchangeably. Ask which one is written in the definition and which one at the call. It matters when they read a hint or an error.
- **Argument order.** Swapped arguments raise no error, and for addition the answer is even right. Use `findRectangleArea` or a subtraction to show a wrong result with no warning.
- **Code after a `return`.** A student writes a `console.log` after `return` and wonders why it never runs. This is 3.2.14. A `return` inside a loop also ends the whole function on the first round, which is why `sumToN` returns after the loop.
- **Scope.** Students expect a variable made inside a function to be readable afterwards. The `ReferenceError` in 3.2.25 is the lesson, not a mistake to rescue them from.
- **Calling without using the result.** `triple(5);` on its own line returns 15 and throws it away. The student sees nothing and thinks it failed.

**What to look for while circulating.** A student stuck on a counted lab for more than one meeting: read the failing requirement's hint with them before touching their code. The hint says how to think about it; the test message says what is wrong.
