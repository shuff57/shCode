# Unit 3.2 — Shapes & Composition

**Quarter 3 · Weeks 3–4 · ~6 contact hours**
**Environment:** shPlay in-app editor (three.js facade, `preview: 'shplay'`).

## Theme

"Now that you can transform a Cube, meet the other five shapes." Module 3.2 introduces the five remaining shPlay primitives — Sphere, Plane, Cone, Cylinder, and Torus — plus the `random()` helper for variety, and the **anchor offset** pattern for multi-body orbital math. Where Module 3.1 mastered transforms on a single Cube, 3.2 masters **composition**: combining shape variety, coordinated positions, and orbital math to build a recognizable animated scene.

## Module Project: Solar System

Sun + Earth + Moon orbiting via `frameCount`-driven `Math.cos`/`Math.sin`, black space background, color differentiation per body, plus a **4th body of the student's choice** (Mars, Jupiter, a comet, etc.) as the creative element. The project integrates every concept from the module: multiple Spheres, orbit math, anchor offsets, and rotation.

## Key constraint

**Module 3.2 introduces 5 new primitives + random() + multi-shape composition.** It does NOT re-teach `parent()` (introduced in 3.1.B4) — it remains available but is not a learning target in this module.

## Concepts taught (new in 3.2 vs 3.1)

1. `Sphere(x, y, z, radius)` — the radius parameter
2. `Plane(x, y, z, width, height)` — flat rectangular surface, used as a floor
3. `Cone(x, y, z, radius, height)` — tapers to a tip, tip points +Y by default
4. `Cylinder(x, y, z, radius, height)` — uniform radius, no taper
5. `Torus(x, y, z, ringRadius, tubeRadius)` — two distinct radius parameters
6. `random(min, max)` — returns a float in [min, max); use in setup() for stable placement
7. Multi-shape scene composition — coordinating positions across many shape types
8. Anchor offsets — using one shape's `.position` as the base for another's orbit
9. Why orbital math uses `cos` for x and `sin` for z — unit-circle parameterization

## Concepts re-applied from 3.1

- `.position`, `.rotation`, `.scale`, `.size` — all primitives share the same transform API
- `radians(deg)` — used in orbit angle calculations
- `background('#000')` — black space background established in each frame
- `frameCount` — drives time-based rotation and orbit speed
- `parent(child, parentObj)` — available but not a new learning target

## SLO Focus

- Composition mastery: combining multiple shape types in a coherent scene
- Orbital math: `cos`/`sin` parameterization of circular motion around a moving anchor
- Creative extension: 4th body demonstrates student agency within the system

## Inter-module bridges

- **3.1 → 3.2:** Module 3.1 mastered transforms on a single Cube. Module 3.2 takes that same transform knowledge and applies it to five new primitive shapes — the API is identical, only the constructors differ. Students carry `.position`, `.rotation`, `.scale`, and `radians()` forward with zero relearning.
- **3.2 → 3.3:** Module 3.3 (OOP Foundations) introduces wrapping shapes inside ES6 classes. The Solar System multi-body code from 3.2 is the ideal refactoring target — converting each body (Sun, Earth, Moon, Planet) into a class with its own `update()` method.
