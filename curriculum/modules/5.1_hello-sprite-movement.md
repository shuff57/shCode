# Module 5.1: moSHion Foundations

**Quarter 2 · Weeks 10–11 · ~7 contact hours**
**Environment:** moSHion in-app editor (built on q5.js + Box2D physics).

## SLO Focus
- Reinforces **SLO 3** (design/implement/test in a visual context)
- Applies Q1 control structures (conditionals, loops) to interactive programs: first time students use their language skills for something that moves on screen

## Unit Goal
Students can build a minimum-viable moSHion sketch from scratch: a canvas, a controllable sprite, keyboard input, and basic physics. They understand the frame loop (`setup()` runs once, `draw()` runs every frame) and can predict what a `vel.x = 4` assignment does. By end of W11, the "wow, I made a thing that moves!" moment has landed.

## Inter-module bridges
- **2.1.1 → 2.1.2:** Keyboard input + velocity from W10 stays; W11 layers physics (gravity, bounciness) on top.
- **Module 5.1 → Unit 2.2:** By end of W11 students have called `new Sprite(...)` dozens of times without any formal explanation of classes: deliberate setup for the OOP reveal in W12.

## Pre-requisite snapshot (entering this unit)
- Completed Q1 (variables, types, conditionals, loops, functions, arrays).
- Comfortable reading and writing ~30-line console.log programs.
- Can follow camelCase + class style guide.

## Post-requisite snapshot (exiting this unit)
- Can write a moSHion sketch with canvas, sprite, keyboard input, and basic physics from memory.
- Uses `kb.pressing(...)` correctly including the else-to-zero pattern.
- Understands that `vel` is pixels-per-frame at ~60 fps.
- Has instantiated at least 3 objects without being told they're using OOP.
