# Module 5.3: Project — Pinball

**Quarter 2 · the first build · after §5.2 Physics Feel**

## SLO Focus
- **SLO 3:** the module's artifact is a complete, playable game built from the physics the previous two modules taught.
- Reinforces **SLO 2** and **SLO 4**.

## Module Goal
Students take the pinball scene they already built in 5.2.14 and turn it into a game: something to aim at, a score that counts an event rather than a frame, a way to lose, and a way to start again. Everything is built with functions, variables and sprite properties — **no classes anywhere in this module**.

## Pre-requisite snapshot
§5.2 complete: gravity, static bodies, `colliding()`, edge- versus level-triggered input, bounciness and friction, `applyForce`, and the pinball scene at 5.2.14.

## Post-requisite snapshot
Can build a small complete game from parts, and can say what a score is counting. Ready for §5.4, the second build.

## Note
**Not a book section, and no classes.** This is the first of the three game builds the owner set out on 2026-10-29: functional game design at 5.3–5.5, OOP game design at 5.6, writing your own classes at 5.7–5.8.

**10 lessons** (`5.3.1`–`5.3.10`) in folders `5-3-pinball-*`. The `5-3-1`–`5-3-36` folders
belong to the old 5.3 and are still in use by what is now 5.6, so this build takes its own
prefix — no id collides with a folder a student's progress is already keyed on.

### The one idea this module is really about
A collision is not an event. `colliding()` is true on every frame two sprites touch, so `if (ball.colliding(bumper)) score += 1` adds sixty points a second. The fix — remember whether you were touching *last* frame — is the same edge-versus-level distinction 5.2.5 taught for keys, one layer down. 5.3.4–5.3.7 build the whole lesson around it.
