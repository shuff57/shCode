# Module 5.4: Project — Flappy

**Quarter 2 · the second build · after §5.3 Pinball**

## SLO Focus
- **SLO 3:** the module's artifact is a complete, playable game.
- Reinforces **SLO 2** and **SLO 4**.

## Module Goal
Students plan, build and playtest a flapping-bird game with functions, variables, arrays and sprite properties. The new idea is a world that scrolls: obstacles are built on a timer, kept in an array, and deleted when they leave. **No classes anywhere in this module.**

## Pre-requisite snapshot
§5.3 complete: the state flag, the edge-versus-level pattern for a score, and the restart that puts back everything a round owns. Arrays from 3.3.

## Post-requisite snapshot
Can build, track and remove a changing set of sprites, and can say what a restart has to put back. Ready for §5.5, the third build.

## Note
**Not a book section, and no classes.** Second of the three functional game builds (5.3–5.5). The array is injected where the game needs it (5.11.1), not taught up front, following the CodeHS rollout described in `CODEHS-SEEDING.md`.

**The five-step close** (decided 2026-10-30, `codehs-review/PLACEMENT.md`): the module opens with a written plan (5.10.1) and plays out with a playtest-and-reflect (5.12.3) before the check, both AI-graded like the Snake build (5.13.1, 5.16.1). Added in a retrofit, so the lesson folders `5-4-flappy-plan-*` and `5-4-flappy-playtest-*` carry no number and every other title moved up.

**11 lessons** (`5.10.1`–`5.12.5`) in folders `5-4-flappy-*`.

**Two conventions in every starter from 5.11.2 on** (round-2 review, 2026-10-30). `draw()` opens with `bird.x = 100; bird.vel.x = 0;`, because a kinematic pipe that touched the bird used to carry it off the left edge for good (x = -2429 after 24 s, score frozen at 0), and in 5.12.2 the bird kept sliding after the freeze. All words on screen (score, pipe count, Game over) are drawn in `drawTop()`, which runs after the sprites, because text drawn in `draw()` sat under the pipes. 5.11.1 teaches both before the first lab.

**Grading notes** (round-4 review, 2026-10-30). The starter's `bird.vel.x = 0` must never satisfy a card: 5.12.2's freeze card (r4) wants gravity at 0 and a vel.x of 0 that is not the bird's (or the pipes stepped by hand inside the playing gate), so a crash that leaves the pipes sliding stays red. 5.12.2 r5 also accepts the flag on the spawn line itself (`if (playing && frameCount % 90 === 0)`). 5.11.2 r2 wants the push inside the beat's `if` (not after an empty one), and r3 wants the delete and splice inside an `if` that tests a pipe's `x`; splice-first and forward loops with `i--` still pass.

### The one idea this module is really about
A game with many things alive at once has to keep track of them: build them, find them again, and delete them in two places (the screen and the array). 5.11.1–5.11.2 build the lesson around the backwards `splice` loop.

## Unit-level assessments
5.10.1 (a written plan) and 5.12.3 (a playtest and reflection) are AI-graded, 0 points, and deliberately lenient: any answer that gestures at the question counts. 5.12.4 is a short check, following the CSP habit of closing a content module with one quiz. 5.12.5 closes on challenges, graded by one card that any one of the three challenges turns green.
