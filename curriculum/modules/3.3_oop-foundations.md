# Unit 3.3 — OOP in 3D — Foundations

**Quarter 3 · Weeks 5–6 · ~6 contact hours**
**Environment:** shPlay in-app editor (three.js facade, `preview: 'shplay'`).

## Theme

"The class syntax you learned in Unit 2.2 works identically in 3D — only the body changes." Module 3.3 transfers the Unit 2.2 OOP pattern to shPlay 3D. Students replace `this.sprite = new Sprite(...)` with `this.shape = new Sphere(...)` (or any single primitive), then apply the same constructor/method/instance patterns they already know to create reusable 3D objects.

## No Module Project

The Robot project lives in **3.4 OOP Composition**. Module 3.3 covers single-shape OOP foundations only and unlocks via lesson completion (green-to-advance). Students who complete every lesson in 3.3 are ready for the multi-shape composition and `parent()` API work in 3.4.

## Key constraint

**Module 3.3 uses ONLY single-shape class wrappers.** Each class wraps exactly one 3D primitive via `this.shape = new ShapeType(...)`. Multi-shape composition (`this.body`, `this.head`, `this.armL`, etc.) and the `parent()` API are deferred to Module 3.4 OOP Composition.

## Concepts taught in 3.3

1. Single-shape class wrap — `this.shape = new Sphere(x, y, z, radius)` as a data member
2. `this.shape` — the convention for referencing the wrapped shape inside methods
3. Constructor with 3D coordinates — passing `(x, y, z)` parameters to place each instance
4. Methods that mutate position — `this.shape.position.x += 0.02`
5. Methods that mutate rotation — `this.shape.rotation.y += 0.03`
6. Methods with parameters — `setColor(c)` sets `this.shape.color = c`
7. The `update()` pattern — per-frame logic inside the class; `p.update()` in `draw()`
8. Methods that return data — `isAbove(y)` returns `this.shape.position.y > y`
9. A method calling another method — `spin()` calls `this.recolor()`
10. Multiple instances — two or more `new Planet(...)` at different positions
11. Array of instances — `let planets = []; planets.push(new Planet(...))`
12. Looping over an array — `for (let p of planets) p.update()` in draw
13. Loop mutation — setting `.shape.color` on each instance in a loop
14. When OOP — repetition (many objects) and reuse (per-instance state)

## Concepts re-applied from Unit 2.2

- `class Name { constructor() {} }` — unchanged JavaScript syntax
- `this` — unchanged semantics; refers to the current instance
- Methods — `this.methodName()` pattern identical to Unit 2.2
- `new ClassName(...)` — same instantiation syntax
- The `for...of` loop pattern from Module 2.3

## SLO Focus

- Transfer: apply known OOP syntax to a new context (3D shapes instead of sprites)
- Single-concept drills: each lab isolates one new OOP capability in 3D
- Arrays + loops: combine instances and iteration to manage many objects

## Inter-module bridges

- **3.2 → 3.3:** Module 3.2 ended with the Solar System — many Sphere objects scattered across setup() and draw(). Module 3.3 shows students how to refactor each body (Earth, Mars, Moon) into a `Planet` class with its own `orbit()` or `update()` method. The same multi-body scene becomes more readable with OOP.
- **3.3 → 3.4:** Module 3.3 establishes the single-shape wrapper pattern. Module 3.4 (OOP Composition) extends it: a class can wrap multiple shapes (e.g. `this.body = new Cylinder(...)`, `this.head = new Sphere(...)`) and use the `parent()` API to attach them. The Robot project in 3.4 is the culminating application of multi-shape OOP.
