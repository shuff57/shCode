# Module 1.3 — Documentation and Coding Conventions

**Quarter 1 · Week 3 · Environment: browser DevTools console**

## SLO Focus
- Reinforces **SLO-2** — structured, conventional, readable code.

## Module Goal
Students choose clear descriptive names, explain why reusing a variable for
different purposes makes code harder to debug, follow the class style guide
for naming and layout, comment what is not obvious, and write a README.

## Pre-requisite snapshot
Module 1.2 (Variables and Data Types) complete.

## Post-requisite snapshot
Students write readable, consistently-styled, documented code. **The class
style guide (`curriculum/resources/class-style-guide.md`) is handed out this
week and is the grading rubric for every code assignment after it.**

## Note
Book §1.3 Documentation and Coding Conventions (229 lines). Ships as a
20-lesson sequence, matching module 1.1's density.

### The book covers less than this module does

Book §1.3 has only **two** subsections — 1.3.1 Naming Variables Well and
1.3.2 Reuse or Create? Comments, indentation, spacing, braces and READMEs are
**not in the book at all**; they come from `curriculum-plan.md` §1.3 and the
class style guide. So this module is deliberately wider than its book
section, and that is not drift — it is the plan's own scope.

Numbering runs in two blocks for the same reason as module 1.2: `1.3.1`–`1.3.5`
were built earlier (slides, camelCase, layout, comments, and A1.3.2), and
`1.3.6`–`1.3.20` were appended 2026-08-16 rather than interleaved. No 1.3
lesson currently carries `lesson_state` rows, but appending keeps folder ids
stable for free, and the order still reads: conventions first, then the
book's depth on naming, then reuse, then the README and A1.3.1.

### Two things deliberately not built

- **JSDoc.** `curriculum-plan.md` §1.3 lists "JSDoc-style function
  documentation (introduce now, reinforce all year)". Students have not met
  functions yet — those arrive in §3.1 — so a JSDoc lesson here would be
  teaching `@param` for a construct that does not exist to them. The style
  guide already marks JSDoc as *enforced from Week 6*. Build it against §3.1.
- **The AP CSP open-source/licensing discussion** in the plan is a
  teacher-led in-class activity with no in-app slot, same as §1.2's binary
  worksheet.

**Known inconsistency, not fixed here:** `class-style-guide.md`'s deductions
table is written in points ("-1 pt per instance"), which predates the
move to mastery grading. Every lesson in this module carries `points: 0`.
The style guide needs a pass to match; that is a curriculum-author call, not
a build one.
