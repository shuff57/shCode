# Unit 2.5 — State and Persistence

**Quarter 2 · Week 16 · ~3.5 contact hours**
**Environment:** q5play in-app editor.

## SLO Focus
- **SLO 2** (state machines as structured programming)
- **SLO 3** (File I/O primary artifact — A16.1 persistent storage)
- Covers the Butte outline topic **File I/O (secondary location after W8 FileReader)**

## Unit Goal
Students add the two things that transform a "sketch that runs" into a "game that has a shape": persistent storage (high scores survive reload) and a state machine (menu → play → win/lose → menu). This unit is the last hard prerequisite for the W18 capstone — students cannot ship a capstone without these.

## Inter-module bridges
- **Unit 2.4 → 2.5.1:** The W15 platformer gets "save your high score" and "menu/win/lose screens" bolted on during this week.
- **Unit 2.5 → Unit 2.6 → Unit 2.7:** After state and persistence, students have every building block needed for the capstone. W17 adds advanced mechanics (joints) as polish.

## Pre-requisite snapshot
- Has a W15 game to bolt state + save onto (continuity from Unit 2.4).
- Comfortable with `switch` statements (Q1 W4 conditionals).
- Knows `JSON.stringify` / `JSON.parse` concept from Q1 (if not, introduce here).

## Post-requisite snapshot
- Can save and retrieve data with `storeItem` / `getItem` — and correctly handle the string→number coercion.
- Has exported game data as a `.json` file download.
- Has implemented a 3+ state machine using `switch` in `draw()`.
- Understands why `loadJSON` goes in `preload()`.
