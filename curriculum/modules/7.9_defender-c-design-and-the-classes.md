# Module 7.6: Project — Defender, Part C (classes clean it up)

**Quarter 2 · the capstone's third part · after §7.5 Defender, Part B**

## SLO Focus
- **SLO 3:** the module's artifact is the complete, playable Defender.
- **SLO 2:** the same game rebuilt with classes: `Bullet`, `Enemy` and `Spawner`.

## Module Goal
Students rebuild their Part B game as three classes with the same behaviour, then playtest it, check it, give it sound and extend it. The new idea is **refactoring**: same game, same numbers, rules moved to the objects that own them. The three parallel arrays become one array of `Enemy` objects, the nested hit loop loses every `splice` and its `break`, and the wave globals become one `Spawner`. **No groups and no `extends`**: 6.1 teaches groups.

## Pre-requisite snapshot
§7.5 complete: parallel arrays kept in step, a nested hit loop that splices safely, waves with a pause, and the 7.8.3 drift bug found and fixed. From 7.3: `takeHit` with a floor, `isAlive()`, a method whose parameter is another object, `filter`, `static spawned`.

## Post-requisite snapshot
Can refactor working procedural code into classes without changing what it does, keep removal in one place, use one object's method on another, own a timer inside a class, reset a class variable on restart, and load a sound once and play it from the method where its event happens. Ready for 6.1, where a `Group` does the list-keeping.

## Note
**Not a book section.** The third and last part of the Defender capstone (7.4 ship and shots, 7.5 enemies and waves, 7.6 classes). Spec: `codehs-review/CAPSTONE-SPEC.md` §6. It closes the capstone with the written playtest-and-reflect (7.11.1, AI-graded), a sound-effects lab (7.11.3) and the challenges (7.11.4).

**10 lessons** (`7.9.1`-`7.11.4`) in folders `5-11-defender-*`. Each lab's starter is the previous lab's solution with one class skeleton added (7.9.4 starts from the Part B final), and each solution was checked to play exactly as Part B did: the same autopilot run gives the same score, base and wave after 7.9.4, after 7.10.1 and at the end. Folder names are D1 ids and never move, so the sound lab is `5-11-defender-sound-lab-sound-effects` and the challenges keep `5-11-defender-9-challenges-make-it-yours` under the number 7.11.4.

**Sound is one lab, not a module.** 7.11.3 starts from the 7.10.2 game and teaches its own API on the page (`loadSound()` once in `setup()`, `.play()`, `.volume`, `.rate`, the browser's no-sound-before-a-key rule, and an optional `masterVolume()` mute key). The two sounds play from methods the student already wrote: `zap.play()` in `Bullet`'s constructor, which runs once per shot, and `boom.play()` in `Enemy`'s `takeHit()` when that hit leaves it with no hp. Both load `/moshion/assets/coin.wav`, the second at `rate = 0.5`. The three cards are lax on names, quotes and placement (beside `new Bullet(...)` in `fire()`, or under any `if` on `isAlive()`/hp, also count) and strict only on the path, because a wrong path fails silently.

**Words on screen go in `drawTop()`**, the convention 5.4 set and Part A repeated: the score, the wave, the base and the game-over lines (now with "enemies faced") are drawn there, after the sprites, so no enemy can cover them.

**The checklist, said aloud.** `Spawner` answers "no" to 7.2.18's first question (there is only one). 7.9.1 says so and gives the reason it is a class anyway: its facts change together, so a restart is one line, `spawner = new Spawner()`, that cannot forget a piece. 7.9.2 asks for it and 7.11.2 q6 checks it.

### The one idea this module is really about
**Finished in one place.** Inside the frame, objects only change their own state (`takeHit`, `land`, `spend`); nothing is spliced inside a loop. Once, at the end of the frame, each list is cleared in two places, in order: `remove()` every finished one (the screen), then `filter` to keep the alive ones (the list). 7.9.3 teaches it and 7.9.4-5.11.5 use it.

## Unit-level assessments
7.11.2 is a seven-question check. 7.9.2 and 7.11.1 are the AI-graded plan and playtest, 0 points, and deliberately lenient like 5.5's: any answer that gestures at the question counts. 7.11.3, the sound lab, is 0 points with three cards (a sound loaded in `setup()`, a sound per shot, a sound when a shot finishes an enemy). 7.11.4 closes on challenges, graded by one card that any one of the three challenges turns green.
