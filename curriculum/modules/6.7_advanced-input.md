**Quarter 2 · ~2 contact hours**

## SLO Focus
- **SLO 3** primary (implement + debug a complex interactive system)

## Unit Goal
Students read the cursor, tell a held button from a one-shot click, drag a sprite
without fighting the physics engine, and drive two players from one keyboard with
independent key schemes and independent state. `bounciness` is taught here because
the two-paddle example needs a ball that pushes back. Joints, `applyForce` and the
slingshot composition are Module 6.8.

## Inter-module bridges
- **Unit 6.6 → 6.7:** state machines are assumed, not retaught; the two-paddle
  example leaves flow control to the student.
- **Unit 6.7 → 6.8:** hit-testing (6.7.6) and drag (6.7.9, 6.7.10) are the two
  halves the slingshot pattern composes with a joint. 6.8 cites them directly.

## Pre-requisite snapshot
- Classes (5.3, 5.4), groups (6.1), animation/camera (6.4), saves (6.5), state
  machines (6.6).
- Mouse input and `bounciness` have NOT been formally taught before this unit.

## Post-requisite snapshot
- Can read the cursor (`mouse.x` / `mouse.y`) and tell held from one-shot
  (`mouse.pressing` vs `mouse.presses`).
- Can hit-test a sprite against the cursor.
- Can drag a sprite (snap pos to cursor + zero vel).
- Can drive two players from one keyboard with two key schemes and two sets of
  state variables.
- Can tune push-collision feel with `sprite.bounciness`.

## Unit-level assessments
None at unit close. The graded lab for this material is 6.8.14 Pong-Sumo, which
also needs a joint and therefore sits at the end of Module 6.8.
