# Unit 1.1 — Foundations

**Quarter 1 · 9 class days across 5 sub-modules · ~15.75 contact hours (9 days × 1.75 hrs/day)**
**Environment:** Browser DevTools console (no install).

Book-aligned as of 2026-08-11: this unit is book Chapter 1 in full, one sub-module per book
section (§1.1–§1.5), per `sub-module-spec-conventions.md` §0. Each sub-module's own spec is
the build target — this file is the unit-level index and SLO map, not a build doc.

## SLO Focus

- **Introduces SLO 1** (software life-cycle) — primary in 1.1.1, evidence artifact A1.1.
- **Introduces SLO 2** (coding conventions and structured style foundations) — primary in
  1.1.2, 1.1.3, 1.1.4; reinforced in 1.1.5.
- **Reinforces SLO 3** — in 1.1.2 (first real labs).
- **Introduces SLO 4** (process as algorithm / computational thinking) — reinforced in
  1.1.1, primary in 1.1.5, evidence artifact A5.1.

## Unit Goal

Students understand what programming *is* and where it sits in a software project's
lifecycle; can run JavaScript in the browser console and know JavaScript's eight data
types; write code that follows consistent naming and documentation habits from day one;
can name the major programming paradigms and explain why JavaScript supports all three;
and can plan a program before typing it — decomposing a problem, writing pseudocode, and
debugging deliberately with `console.log` rather than by guessing.

## Inter-module bridges

- **1.1.1 → 1.1.2:** The `console.log` habit from 1.1.1 is the delivery mechanism for
  every 1.1.2 type-inspection example (`console.log(typeof x)` and friends).
- **1.1.2 → 1.1.3:** Knowing the eight data types is a prerequisite for judging whether a
  variable name is descriptive — 1.1.3's naming examples lean on type vocabulary from 1.1.2.
- **1.1.3 → 1.1.4:** The naming/reuse discipline from 1.1.3 recurs as a running example in
  1.1.4's procedural-vs-OOP contrast (the same `book` object, read two ways).
- **1.1.4 → 1.1.5:** 1.1.4's "structured programming" reading (sequence, selection,
  repetition) is the direct setup for 1.1.5's pseudocode/flowchart content, which plans
  programs using exactly those three structures.
- **Unit 1.1 → Unit 1.2:** 1.1.5's algorithm/pseudocode readings (pre-control-flow, sequence
  only) are deliberately revisited post-control-flow at Unit 1.2 slots `1.2.17`–`1.2.19`
  (see `1.1.5_program-design-tools.md` Context for why this is spaced repetition, not
  duplication) — that's where pseudocode finally gets to branch and loop.

## Pre-requisite snapshot (student knowledge entering this unit)

None. First unit of the course.

## Post-requisite snapshot (what students have after this unit)

- Can name the four SDLC phases and classify a task into the correct one.
- Can open browser DevTools, run JS statements, and read `console.log` output.
- Knows JavaScript's eight data types and can use `typeof` to check one.
- Can declare variables with `let`/`const`, using descriptive camelCase names and avoiding
  variable reuse.
- Can write single-line and block comments.
- Can name the three major programming paradigms and explain what "multi-paradigm" means.
- Can decompose a problem, write simple pseudocode, read a flowchart, and knows what
  recursion and a base case are.
- Can read the three parts of a browser error message and use labeled `console.log` calls
  to debug a wrong-answer (non-crashing) bug.
