# Module 3.1: Functions: Definition and Calls

**Quarter 1 · Week 7 · Environment: browser DevTools console**

## Module Goal
Students identify function calls in a program, define a **parameterless** function
that outputs strings, and describe the benefits of using functions (modularity,
reusability, maintainability). Parameters, return values, scope, and pass by
value/reference are explicitly **not** this module's job — see the Note below.

## Pre-requisite snapshot
Unit 2 (Control Flow) complete.

## Post-requisite snapshot
Students can read a program and point to every function call in it, write and
call a function of their own that takes no input and returns nothing, and
explain in their own words why breaking code into named functions is worth
doing. Module 3.2 (Parameters and Return Values) picks up from here.

## Note

Book §3.1 Functions: Definition and Calls. Currently **7 lessons**; target **18** per
the 2026-09-15 build pass (17 in the first pass, plus `3.1.14 Chart What You Built`
added the same day after a user follow-up asked for flowchart coverage on the new
refactor lab).

**The Module Goal above was wrong until this pass.** It used to claim §3.1 covers
"parameters and return values... scope... pass by value vs reference" — that was
leftover prose from the pre-2026-08-16 combined "1.3 Functions and Data" unit spec,
never corrected when 3.2 (Parameters and Return Values) and 3.6 (Pass by
Value/Reference) were split out. The book's own §3.1 learning objectives are narrower:
identify calls, define a *parameterless* function, describe benefits. Fixed above.

**Three existing lessons preview 3.2/3.4 on purpose, not by mistake.** `3-1-8-lab-findmax-iseven`,
`3-1-9-lab-sum-to-n`, and `3-1-10-functions` all require parameters and return values —
outside §3.1's own scope, and they carry `1.3.1g`/`1.3.1h` comments dating them to the
old combined unit. They were not reassigned to 3.2 when the split happened, unlike
`3-1-3` through `3-1-7`, which *were* renumbered into 3.2 and 3.6 in the 2026-09-13
build. Rather than move these three now (which would touch 3.2's and 3.4's already-built
numbering — out of scope for a §3.1 density pass), this build keeps them in place and
reframes them honestly: retitled "Preview: …" and resequenced to the end, after 3.1's
own parameterless content is complete. This mirrors what the book itself does — Example
3.1.4 hands the reader a 4-parameter `calcDistance()` and says outright "those are
parameters, and they are the whole subject of Section 3.2. For now, notice only what
they bought you." Moving these three into 3.2/3.4's numbering is a legitimate follow-up,
just a separate one.

**3.1.12's missing partner lab, now built.** `3-1-7a-a3-1-0-flowchart-gate`'s own
content describes itself as "the gate for the refactor lab" and names the two functions
a correct solution will contain — `decideGrade`, `printAdvice` — but no lesson calling
itself that refactor lab existed anywhere in the lesson tree. `3-1-19-lab-refactor-grade-advisor`
(3.1.13) is it: it takes `2-1-38-a2-1-1-grade-advisor`'s program (Module 2.1) and has
the student decompose it into exactly those two named, parameterless functions, reading
`score`/`attendance`/`lateAssignments` from outer scope rather than taking them as
arguments — keeping the lab inside §3.1's no-parameters boundary the same way the gate's
own content does.

**Folder numbers do not match title numbers for the carried-over lessons.** `3-1-2a-reading-the-function-call-shape`
and `3-1-7a-a3-1-0-flowchart-gate` keep their historical slugs because `lesson_state.lesson_id`
is the folder name and renaming one orphans student progress; only their `title` numbers
moved (to 3.1.11 and 3.1.12). The ten net-new lessons above are minted at slugs
