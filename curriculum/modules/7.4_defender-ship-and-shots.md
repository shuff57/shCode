# Module 7.4: Project — Defender, Part A (ship and shots)

**Quarter 2 · the capstone, part one of three · after §7.3 Inside a Class**

## SLO Focus
- **SLO 3:** the module's artifact is a playable game: a ship, shots, one drone, a base with hp, game over and restart.
- Reinforces **SLO 2** and **SLO 4**.

## Module Goal
Students build a playable base for Defender: a ship that stays on screen, shots on a cooldown that are cleaned up, one drone that scores when it is shot, a base that loses hp when the drone lands, game over and restart. All functions and arrays: **no classes and no groups.** 7.5 grows it into many enemies and waves, still procedurally; 7.6 rebuilds it with classes.

## Pre-requisite snapshot
§7.3 complete, and with it 5.4 and 5.5's arrays of sprites, the delete-and-splice pairing, the `playing` flag, a `startRound()` that puts back everything a round owns, and words drawn in `drawTop()`.

## Post-requisite snapshot
Can rate-limit an action with a countdown variable, test two sprites with `overlaps()`, remove a hit sprite from the screen and the array on the frame it hits, and run a round with lives, game over and restart. Ready for §7.5 (Part B).

## Note
**Not a book section.** The first of three modules that build one game (7.4, 7.5, 7.6; spec in `codehs-review/CAPSTONE-SPEC.md`). It keeps the five-step close of 5.3-5.5: `7.4.1` is an AI-graded written plan for the whole three-part game; the playtest-and-reflect comes once, at the end of Part C (7.6.7).

**8 lessons** (`7.4.1`-`7.4.8`) in folders `5-9-defender-*`. The names used here (`BASE_Y`, `ship`, `base`, `bullets`, `cooldown`, `score`, `baseHp`, `playing`, `moveShip()`, `fire()`, `moveBullets()`, `startRound()`) are fixed across all three parts, so 7.6.1 can compare the before and after line for line.

**Everything moves by hand inside `if (playing)`**, so game over is one `playing = false` with no freeze code (7.4.2 says why, against 5.4.8's frozen pipes). **Words on screen go in `drawTop()`**, the convention 5.4 set, so no shot or drone can cover the score or Game over.

### The one idea this module is really about
A timer you start yourself. `frameCount % n` ticks on its own, whatever happens; a cooldown is set when something happens (a shot) and counts down to 0 before the action may happen again. 7.4.2 teaches it, 7.4.3 lets the student turn the number, and 7.4.4 asks for it. `overlaps()`, taught properly in 7.4.5, is the second idea: a level-triggered test that works on pass-through sprites, which is why the shot has to leave on the frame it hits.
