# Module 2.1.1 — Hello Sprite and Movement

> **Week 10 · Q2 q5play Foundations · 3.5 contact hours (2 sessions) · Environment: q5play in-app editor**
> **SLO focus:** Reinforces SLO 3. First week students use the in-app q5play editor after a quarter of console.

## Context

First week of Q2. Students arrive with strong console-JS foundations and low visual-programming exposure. This module is deliberately about the "wow moment" — get a controllable sprite on screen by end of Session 1. The conceptual lift is understanding the **frame loop**: `setup()` runs once, `draw()` runs every frame at ~60 fps. Once students internalize that, everything else in Q2 builds on it.

**Do NOT:**
- Explain classes yet (`new Sprite()` is used without explanation — deliberate setup for W12).
- Allow complex physics discussions (gravity, bounciness come next week).
- Let students set `vel.x = 50` — they'll launch sprites off-screen. Enforce "small numbers, 2–6 is plenty."

---

## Learning Objectives

Students will be able to:
1. Create a canvas with `new Canvas(width, height)`.
2. Create a sprite with `new Sprite(x, y, w, h)` and set its color/rotation/layer.
3. Structure a q5play sketch around `setup()` (once) and `draw()` (every frame).
4. Drive sprite movement with `kb.pressing('left' | 'right' | 'up' | 'down')` and `vel.x/y`.
5. Explain why setting `vel.x = 0` in the else branch matters (sprite drifts otherwise).
6. Explain the frame loop: `draw()` runs ~60 times per second.

## Topics Covered
- q5play program skeleton: `setup()`, `draw()`, optional `update()`.
- `Canvas(width, height)`.
- `Sprite(x, y, w, h)` and its properties: `color`, `pos`, `vel`, `rotation`, `layer`.
- `background(color)` inside `draw()` (must be first thing each frame).
- Keyboard input: `kb.pressing(key)` — level-triggered, returns boolean each frame.
- Setting velocity: `player.vel.x = 4` (pixels per frame).
- Screen coordinates: y-axis flipped vs math (up = negative y).

## Prerequisites

- Can follow class style guide.

## Worked Examples (teacher-led in class)

### Worked Example 1 — Minimum sprite program (10 min, Session 1)
Type live on the projector. Type EVERY character; no copy-paste.
```js
function setup() {
  new Canvas(400, 400);
}

function draw() {
  background('#222');
  new Sprite(200, 200, 40, 40);
}
```
Run. Point at the gray canvas and the square. Ask: "What if I wanted the sprite to stay the same each frame instead of getting redrawn?" → student aha → hoist the sprite out of `draw()`.

Evolve the code live:
```js
let player;

function setup() {
  new Canvas(400, 400);
  player = new Sprite(200, 200, 40, 40);
  player.color = 'deepskyblue';
}

function draw() {
  background('#222');
}
```
Physics engine draws `player` automatically — no explicit render call.

### Worked Example 2 — Keyboard movement (10 min, Session 2)
Extend the Session 1 code:
```js
function draw() {
  background('#222');
  if (kb.pressing('left'))  player.vel.x = -4;
  else if (kb.pressing('right')) player.vel.x = 4;
  else player.vel.x = 0;
}
```
Run. Hold arrow keys. Show what happens if you OMIT the else branch (sprite drifts forever once released).

**Task:** Build a "sprite playground" in the in-app editor.

**Requirements:**

## Vocabulary

| Term | Definition |
|------|-----------|
| **Canvas** | The drawing area set up by `new Canvas(w, h)` |
| **Sprite** | A q5play object representing a visual, physics-aware entity |
| **Frame** | One iteration of the `draw()` loop — happens ~60 times per second |
| **Velocity (`vel`)** | Speed in pixels per frame; `vel.x = 4` = move right 4 px each frame |
| **Frame rate** | Frames per second (fps); q5play targets 60 |
| **Level-triggered input** | `kb.pressing(k)` — true *while* key is held |

---

## Teacher Notes

- `vel.x`/`vel.y` are **pixels per frame**. At 60 fps, `vel.x = 4` = 240 px/s. Students who pick `50` will launch sprites off-screen instantly. Enforce "2–6 is plenty."
- Omitting `vel.x = 0` in the else branch is the #1 bug this week. Watch for it.
- Some students will try `player.x = ...` — show that `player.pos.x` works, but `vel` is the idiom for controlled motion.
- Do NOT explain `new` or classes yet. Students can type `new Sprite(...)` by muscle memory — that's perfect setup for W12.
- The arrow keys scroll the editor iframe on some platforms. Recommend WASD as the default control scheme for all labs.
