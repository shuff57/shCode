# Module 2.7.1 — Joints and Advanced Input

> **Q2 Advanced Mechanics · 3.5 contact hours (2 sessions) · Environment: shplay in-app editor**
> **SLO focus:** SLO 3 primary — implement + debug a complex interactive system. Final content unit before the capstone.
> **Audience:** introductory CS students. Mouse input, joints, `applyForce`, and `bounciness` are all new in this unit (none of them have been introduced in prior shplay units). **Granularity bar applies** (`sub-module-spec-conventions.md` §2a): one new concept per lesson.
>
> **Renumber note:** Was 2.6.1 before Unit 2.5 was split into 2.5 (Game Saves) + 2.6 (Game States). Cascaded to 2.7.1.

## Context

Three big ideas in this unit:
1. **Mouse input** — `mouse.x` / `mouse.y` give you the cursor position every frame; `mouse.pressing()` and `mouse.presses()` mirror the keyboard's held / one-shot split.
2. **Joints** — Box2D constraints (`DistanceJoint`, `HingeJoint`) let two sprites move *together* in a physically plausible way. Most students won't fully master joints — aim for "understand enough to pick one for the capstone."
3. **The slingshot pattern** — the high-value composition for this unit. Joint at length 0 between an anchor and a ball, drag the ball with the mouse, on release remove the joint and `applyForce` along the stretch vector. It shows up in dozens of classic games and pulls together every concept introduced here.

A17.1 (Two-Player Pong-Sumo) is the unit's mastery artifact. It exercises two-player input, physics-driven push-collisions (`bounciness`), score state, a win condition, and at least one joint somewhere (boundary chain, moving obstacle, or attached paddle).

**Audience.** Per the granularity bar, every reading and try-it owns exactly **one** atomic concept; integration happens only inside the slingshot worked example (2.7.21) and A17.1 (2.7.26). Mouse input gets its own cluster *before* joints because the slingshot needs both.

**Do NOT:**
- Require all three joint types — only `DistanceJoint` and `HingeJoint` are mainline; `SliderJoint` is challenge-only.
- Use `mouse.pressing(...)` for a one-shot click — it fires every frame the button is held; that's `mouse.presses(...)` territory.
- Author `applyForce` examples without showing the **direction** computation (vector from sprite → target). The most common student bug is `applyForce(50, 50)` with no relationship to the drag — they get a constant launch instead of a slingshot.
- Compound joints + mouse + force into the same reading. The slingshot composition lives in **exactly one** worked example (2.7.21).
- Skip `bounciness` introduction — A17.1 requires it, and it hasn't been formally taught in prior units (it was cut from 2.1.2 scope).

> **Cross-unit handoffs:** state machines from **Unit 2.6** structure A17.1 (title → play → win → reset). Saves from **Unit 2.5** are NOT required here — A17.1 is a single-session lab, not a persistent game.

## Learning Objectives

Students will be able to:
1. Read the cursor position via `mouse.x` and `mouse.y`.
2. Detect a held mouse button with `mouse.pressing()` and a one-shot click with `mouse.presses()`.
3. Hit-test a sprite against the mouse cursor using `world.getSpriteAt(mouse.x, mouse.y)`.
4. Drag a sprite with the mouse — snap `sprite.pos` to the cursor and zero its velocity each frame the drag is active.
5. Create a `DistanceJoint` between two sprites and explain what it constrains.
6. Create a `HingeJoint` between two sprites and explain what it constrains.
7. Remove a joint at runtime with `joint.delete()`.
8. Apply a one-frame impulse with `sprite.applyForce(fx, fy)`.
9. Compute a 2D vector from sprite A to sprite B (`dx = b.pos.x - a.pos.x`, similar for `y`) and use it as a force direction.
10. Compose joint + drag + release + force into a working slingshot.
11. Wire two players to separate key schemes (WASD vs arrow keys) with independent state.
12. Set `sprite.bounciness` to tune push-collision feel.
13. Ship a two-player game with a state-machine flow (title → play → win → reset) and at least one joint used somewhere.

## Topics Covered

Each bullet is a single atomic concept and corresponds 1:1 to a Numbered Lesson List slot.

**Mouse input:**
- `mouse.x` / `mouse.y` — cursor position every frame.
- `mouse.pressing()` — held (true every frame the button is down).
- `mouse.presses()` — one-shot (true only on the frame the button goes down).
- Hit-testing a sprite with the mouse — `world.getSpriteAt(mouse.x, mouse.y) === sprite`.

**Drag pattern (no joint, no release):**
- Snap `sprite.pos` to `mouse.x` / `mouse.y` while the drag is active.
- Zero `sprite.vel.x` / `sprite.vel.y` while dragging to stop physics from fighting the snap.

**Joints:**
- `DistanceJoint(a, b, opts)` — fixed-length tether.
- `HingeJoint(a, b, opts)` — rotational pivot.
- `joint.delete()` — release the constraint at runtime.

**Forces & impulses:**
- `sprite.applyForce(fx, fy)` — one-frame impulse.
- Vector from A → B = `(b.pos.x - a.pos.x, b.pos.y - a.pos.y)` — the geometry the slingshot needs.

**Slingshot composition (one lesson):**
- Joint length-0 anchor + drag + on-release `joint.delete()` + `applyForce(dx * k, dy * k)`.

**Two-player + push-collision:**
- Two key schemes, independent per-player state.
- `sprite.bounciness` for the "Pong push" feel.

### WE2 — Drag a sprite (2.7.10)

```js
let s;
let dragging = false;

function setup() {
  new Canvas(400, 400);
  s = new Sprite(200, 200, 40, 40);
}

function draw() {
  background('#222');
  if (mouse.presses() && world.getSpriteAt(mouse.x, mouse.y) === s) {
    dragging = true;
  }
  if (!mouse.pressing()) dragging = false;
  if (dragging) {
    s.pos.x = mouse.x;
    s.pos.y = mouse.y;
    s.vel.x = 0; s.vel.y = 0;
  }
}
```

### WE5 — Launch with applyForce (2.7.19)

```js
let ball, target;
function setup() {
  new Canvas(500, 400);

  target = new Sprite(400, 100, 30, 30);
```

### WE6 — Slingshot (2.7.21, migrated from shplay-slingshot)

```js
let ball, anchor, joint, dragging = false;
function setup() {
  new Canvas(500, 400);
  world.gravity.y = 10;
  anchor = new Sprite(100, 300, 10, 10);
  anchor.collider = 'static';
  ball = new Sprite(100, 300, 20, 20);
  joint = new DistanceJoint(anchor, ball);
  joint.length = 0;
}
function draw() {
  background('#222');
  if (mouse.pressing() && world.getSpriteAt(mouse.x, mouse.y) === ball) dragging = true;
  if (dragging) {
    ball.pos.x = mouse.x; ball.pos.y = mouse.y;
    ball.vel.x = 0; ball.vel.y = 0;
  }
  if (!mouse.pressing() && dragging) {
    dragging = false;
    let dx = anchor.pos.x - ball.pos.x;
    let dy = anchor.pos.y - ball.pos.y;
    joint.delete();
    ball.applyForce(dx * 5, dy * 5);
  }
}
```

## Vocabulary

| Term | Definition |
|------|-----------|
| **`mouse.x` / `mouse.y`** | Cursor position in canvas coordinates this frame |
| **`mouse.pressing()`** | True every frame the button is held down |
| **`mouse.presses()`** | True only on the frame the button is first pressed (one-shot) |
| **Hit-test** | Checking whether a point (here, the cursor) is inside a sprite |
| **Drag pattern** | Snap `sprite.pos` to the cursor + zero `sprite.vel` while a drag is active |
| **Joint** | A Box2D constraint linking two sprites |
| **DistanceJoint** | Fixed-length tether (rope, rod) |
| **HingeJoint** | Rotational pivot (door, arm) |
| **SliderJoint** | Linear track (challenge-only in this unit) |
| **`joint.delete()`** | Release the constraint at runtime |
| **`applyForce(fx, fy)`** | Apply a one-frame impulse — the engine integrates it into motion |
| **Force vector** | `(b.pos.x - a.pos.x, b.pos.y - a.pos.y)` — direction from A to B |
| **Slingshot pattern** | Joint with `length = 0` + drag + on-release `joint.delete()` + `applyForce` along the stretch vector |
| **`bounciness`** | Per-sprite restitution: 0 = dead thud, 1 = nearly lossless |
| **Two-player local** | Two independent input schemes on the same keyboard (e.g. WASD vs arrows) |

## Teacher Notes

- **The slingshot is the lesson that pulls the unit together.** Spend extra time on 2.7.21. Once a student can build a slingshot, they can build A17.1 and they have a viable capstone path.
- **Joints intimidate students.** Frame them as "two sprites that have to move together" — then `DistanceJoint` is "stay this far apart" and `HingeJoint` is "pivot around this point." That's enough for capstone-grade usage.
- **The direction-vector reading (2.7.18) is the unit's most-skipped prerequisite.** If a student's slingshot launches in a constant direction, they skipped the math. Re-read 2.7.18 with them.
- **`mouse.pressing` vs `mouse.presses` is the new presses-vs-pressing.** Same trap as 2.3.13 / 2.3.14 with the keyboard. Demo the difference live: held click spawns 60 sprites per second; one-shot spawns one per click.
- **A17.1 is structurally a 2.6.1 game.** The title → play → win flow uses the state-machine pattern from Unit 2.6. If a student's A17.1 has no state machine, they're missing the integration moment Unit 2.6 was built for — send them back to 2.6.1 worked examples before they keep building.
- **Two-player games are capstone-friendly.** If a student is stuck on capstone ideas, point at Pong-Sumo — they already have a working one.
- **Day 2 second hour is capstone kickoff.** Reserve 25 min for A18.1 rubric walk-through and design-doc handout so students have a head start.
