# Module 1.1.1 — What Is Programming / Software Lifecycle

> **Week 1 · Q1 Console Fundamentals · 3.5 contact hours · Environment: browser DevTools console**
> **SLO focus:** SLO 1 primary (A1.1 written artifact); SLO 4 introduced.

## Context

First module of the course. Students arrive with no assumed programming experience. This week is deliberately **low-syntax** — the goal is building mental models for *what code is* and *what the software lifecycle means*. Hands-on work is limited to running pre-written `console.log` statements. The written SDLC assignment (A1.1) is the dual-enrollment SLO 1 documentation artifact and must be preserved.

**Do NOT:**
- Introduce variables, conditionals, or functions this week.
- Mention q5play, JSCAD, or any downstream tool.
- Let syntax questions dominate class time — redirect to "we'll cover that next week."

---

## Learning Objectives

Students will be able to:
1. Define, in their own words, what a program is and what a programming language is.
2. Name the five phases of the software development life-cycle (design, development, documentation, testing, maintenance) and describe what happens in each.
3. Open the browser DevTools Console in Chrome/Firefox/Edge and identify the prompt, output area, and clear button.
4. Type a `console.log(...)` statement and explain what happened when it ran.

## Topics Covered
- What is code? What is the computer actually doing when it runs code?
- Why are there so many programming languages? (Brief survey.)
- The software development life-cycle: design → development → documentation → testing → maintenance.
- Introduction to the browser DevTools Console as a coding environment.
- `console.log()` as the first JavaScript statement.

## Lessons (in-app)

Build the following in-app lessons for this module:

### NEW: `q1-console-hello`
- **Path:** `lessons/q1-console-hello/`
- **Type:** lesson (not assignment)
- **Preview mode:** `console`
- **Estimated minutes:** 15
- **Description:** Run your first `console.log` statements. No variables, no syntax depth.
- **Required files:** `script.js` (starter), `lesson.json` (metadata + steps + requirements)
- **Starter code (`script.js`):**
  ```js
  // Your first program!
  // Click Run to see the message below appear in the Output panel.

  console.log("Hello, world!");
  ```
- **Steps (students work through these in order):**
  1. Click Run. Confirm you see "Hello, world!" in Output.
  2. Change the text inside the quotes to your own name. Click Run again.
  3. Add a second `console.log` line that prints today's date as plain text.
  4. Add a third `console.log` that prints the result of a simple calculation like `2 + 2` (no quotes around the calculation — let JavaScript compute it).
- **Requirements (auto-graded regex — 4 items, 10 pts each):**
  1. At least 3 `console.log(...)` calls exist in the file. Regex: `console\.log\s*\([\s\S]*?\)` — count ≥ 3.
  2. At least one `console.log` call contains a quoted string. Regex: `console\.log\s*\(\s*["'].*?["']\s*\)`.
  3. At least one `console.log` call contains an arithmetic expression with `+`, `-`, `*`, or `/` and no quotes around it. Regex: `console\.log\s*\(\s*[^"'][^)]*[+\-*/][^)]*\)`.
  4. Output is non-empty when the lesson runs. (Enforced by harness.)
- **Passing score:** 30 of 40.

## Worked Examples (teacher-led in class)

### Example 1 — "Hello Console" live demo (10 min)
1. Open DevTools on the projector.
2. Type `console.log("hello")` — press Enter. Point at output.
3. Change to `console.log("Mr. Smith's 4th period class")` — discuss quotes as "the thing inside is treated as text."
4. Type `console.log(5 + 3)` — discuss "no quotes means it's math."
5. Ask: "What do you think happens if I type `console.log("5" + "3")`?" Run it. Discuss quickly; tell them "we'll explain this next week."

### Example 2 — SDLC applied to Gmail (15 min)
Draw the 5-phase cycle on the board. For each phase, ask students to guess what happened at Gmail:
- **Design** — whiteboard sessions on what problem they're solving (email that doesn't fill up)
- **Development** — engineers writing the code
- **Documentation** — user help docs + internal engineering docs
- **Testing** — what happens before a new feature ships (automated + beta testers)
- **Maintenance** — the emails you get about "scheduled maintenance," bug fixes, new features

Then ask students to name another app and walk through it as a class.

## Challenges (optional stretch, not required)

- **Challenge 1:** Using ONLY `console.log` (no variables), print a 3-line ASCII banner with your name. Submit a screenshot of the Output.
- **Challenge 2:** Pick an app or service you use daily. Write a 3–5 sentence guess about which SDLC phase its engineering team is in RIGHT NOW and why. Extra credit: post on the class discussion board.
- **Challenge 3 (for students who finish early):** In DevTools, type `document.title` and press Enter. What did you see? Try `document.body.innerText.length`. Report back what you found — don't worry about understanding it yet.

## Assignments

### A1.1 — Software Lifecycle Writeup (Written, graded — SLO 1 PRIMARY ARTIFACT)

**Weight:** Counts toward Written category (10%).
**Estimated time:** 45–60 min outside class.
**Format:** 1 page (300–500 words), typed, PDF upload.

**Prompt:**
> In your own words, describe the software development life-cycle. Your writeup must name and explain all five phases (design, development, documentation, testing, maintenance). Then pick one real-world software product you use and walk through how you think it went through each phase. Be specific — name features, guess at problems engineers had to solve, imagine what testing looked like.

**Rubric (20 pts):**
| Criterion | Pts |
|-----------|-----|
| All 5 phases named | 5 |
| Each phase explained in your own words (not dictionary quotes) | 5 |
| A specific real-world app is chosen and walked through all 5 phases | 5 |
| Writing is clear, organized, and within word count | 3 |
| Submitted on time, correct file format | 2 |

**SLO mapping:** SLO 1 primary documentation artifact. Teacher retains file.
