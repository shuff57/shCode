# Module 2.2.1 — Classes and Objects via q5play

> **Week 12 · Q2 OOP · 5.25 contact hours (3 sessions) · Environment: q5play in-app editor**
> **SLO focus: SLO 2 PRIMARY (A12.2 written OOP-vs-procedural comparison — dual-enrollment evidence artifact).**
> **Granularity: this is an intro-level unit. Each lesson ships exactly one new concept.**

## Context

This is the SLO 2 anchor module. For two weeks students have typed `new Sprite(200, 200, 40, 40)` without understanding what `new` does or what `Sprite` is. This week: the reveal. Every q5play primitive — `Canvas`, `Sprite`, `Group` — is an instance of a class. Students will write their first class (`Enemy`, `Collectible`), see `this` in action, and compare procedural vs OOP approaches side-by-side. A12.2 written response is the **retained teacher artifact for dual-enrollment SLO 2 documentation**.

**Audience.** Beginning students in an introductory CS course. Most are seeing OOP for the first time. The unit is deliberately *over-granular*: each lesson introduces exactly one new concept, isolates it in a runnable demo or a single-step lab, and only then composes with prior concepts. The integration lesson (2.2.8 Enemy class) does not appear until every individual piece — constructor, `this`, properties, each method shape, composition, cleanup — has been built and practiced separately.

**Do NOT:**
- Go deep on inheritance, polymorphism, or `super()` — name them in 2.2.12a, defer practice to downstream courses.
- Turn A12.2 into a code assignment — it's a written reflection. Keeping it written is the SLO 2 requirement.
- Skip the "you've been using classes" framing; it lands the concept emotionally.
- Bundle two new concepts into one lesson. If a lesson needs to introduce two ideas, split it. The granularity is the pedagogy.
- Pre-write the answer in starter scaffolds. Per `sketch-lesson-conventions.md` §3 and `lab-assignment-conventions.md` §2, `// STEP N:` comments describe tasks in plain English; they never paste the line of code that completes them.

## Learning Objectives

Students will be able to:
1. Use the words *class* and *instance* correctly and explain how they relate.
2. Explain what `new ClassName(...)` does mechanically (allocate object → run constructor → return).
3. Write a `constructor` that stores its arguments on `this`.
4. Read and write properties on an instance with dot notation, and explain why two instances have independent state.
5. Substitute the variable on the left of the dot for `this` inside a method body and predict output.
6. Write a method of each shape: no params, with params, returning a value, and one that calls another `this.method()`.
7. Explain why a class wraps a `Sprite` (composition) instead of inheriting from `Sprite`.
8. Mutate a wrapped sprite's properties from inside a method, and clean it up with `this.sprite.delete()`.
9. Store many instances in an array, iterate the array, and dispatch a method on each element.
10. Compare a procedural (parallel-arrays) and an OOP (array-of-instances) solution to the same problem.
11. Apply a 3-question checklist to decide whether a given problem warrants a class.

## Topics Covered

Each bullet is a single atomic concept. One lesson per bullet (some bullets pair vocabulary + practice across two lessons — see Numbered Lesson List for the full mapping).

**Vocabulary**
- *Class* — blueprint for objects.
- *Instance* — a specific object built from a class.
- `new` — operator that allocates + runs constructor + returns the instance.
- `constructor` — the special method `new` calls; receives args, stores them on `this`.

**State on instances**
- *Property* — data stored on `this`.
- Reading a property — `instance.prop`.
- Writing a property — `instance.prop = value`.
- Two instances have independent property values.

**The `this` keyword**
- `this` as a noun — "the instance the method was called on."
- `this` as a pronoun — substitution rule: replace `this` with the variable on the left of the dot.

**Methods, by shape**
- Method declaration syntax (no `function` keyword).
- Method with no parameters.
- Method with parameters.
- Method that returns a value.
- Method that calls another `this.method()`.

**Composition with q5play primitives**
- Why we wrap a `Sprite` (`this.sprite = new Sprite(...)`) instead of inheriting from it.
- Mutating `this.sprite.x` from inside a method.
- Object cleans up after itself — `this.sprite.delete()`.

**Many instances**
- Three instances stored in three named variables.
- Many instances stored in an array.
- Looping over an array of instances and dispatching a method per element.

**Procedural vs OOP**
- Procedural pattern — parallel arrays + helper functions taking an index.
- OOP pattern — array of instances, each with its own state + behavior.
- Decision rule — 3-question checklist for choosing OOP.

**Reserved-vocabulary-only (no implementation this week)**
- Encapsulation, inheritance, polymorphism. Named in 2.2.12a; practice deferred to downstream courses.

## Worked Examples (teacher-led)

### Worked Example 1 — "You've been using classes" reveal (10 min)
In DevTools (F12) with a running q5play sketch:
```js
> player
Sprite { ... }

> player.constructor.name
"Sprite"

> player.color
"deepskyblue"

> player.color = "red"
> // canvas updates immediately — the property is live
```
Key teaching beat: "The thing called `Sprite` is a **class**. `player` is an **instance**. Everything you've done with `.color`, `.vel`, `.pos` is property access. What you're about to learn is how to write your own `Sprite`-like thing."

### Worked Example 2 — Write an Enemy class live (15 min)
```js
class Enemy {
  constructor(x, y, hp) {
    this.x = x;
    this.y = y;
    this.hp = hp;
    this.sprite = new Sprite(x, y, 30, 30);
    this.sprite.color = 'red';
  }

  damage(n) {
    this.hp -= n;
    if (this.hp <= 0) {
      this.sprite.remove();
    }
  }

  render() {
    this.sprite.text = String(this.hp);
  }
}

let enemy;

function setup() {
  new Canvas(400, 400);
  enemy = new Enemy(200, 200, 10);
}

function draw() {
  background('#222');
  enemy.render();
  if (kb.presses('space')) enemy.damage(1);
}
```
Run. Press space 10 times. Enemy disappears. Discuss what `this` means on each line.

### Worked Example 3 — Procedural vs OOP side-by-side (15 min)
Project the R2 handout. Same problem written two ways:

**Procedural (parallel arrays):**
```js
let enemyX = [];
let enemyY = [];
let enemyHP = [];

function spawnEnemy(x, y, hp) {
  enemyX.push(x); enemyY.push(y); enemyHP.push(hp);
}

function damageEnemy(i, n) {
  enemyHP[i] -= n;
  if (enemyHP[i] <= 0) {
    enemyX.splice(i, 1); enemyY.splice(i, 1); enemyHP.splice(i, 1);
  }
}
```

**OOP (array of instances):**
```js
let enemies = [];

class Enemy { /* same constructor + damage as Worked Example 2 */ }

function spawnEnemy(x, y, hp) {
  enemies.push(new Enemy(x, y, hp));
}

// damage is a method on the instance:
// enemies[0].damage(5);
```

Ask the class: Which is easier to read? Add a new property (e.g., `element`) — which is easier? Delete an enemy — which has fewer places to update?

## Vocabulary

| Term | Definition |
|------|-----------|
| **Class** | A template for creating objects — defines properties and methods |
| **Object / Instance** | An actual object built from a class, with its own property values |
| **Constructor** | The special method that runs when `new ClassName(...)` is called |
| **`this`** | Inside a method, refers to the instance the method was called on |
| **Method** | A function defined inside a class that operates on instances |
| **Property** | A value stored on an instance (`this.color = "red"`) |
| **Instantiate** | To create a new instance with `new ClassName(...)` |
| **Procedural programming** | Organizing code around functions that operate on shared data |
| **Object-oriented programming (OOP)** | Organizing code around objects that bundle data + behavior |
| **Encapsulation** | (Vocabulary only this week) Bundling data + behavior into a single unit |
| **Inheritance** | (Vocabulary only) A class can extend another class |
| **Polymorphism** | (Vocabulary only) Different classes can respond to the same method name |

### 2.2.3a — The `new` operator

- **Concept isolated:** `new` allocates an empty object, runs the constructor with `this` bound to it, and returns it.
- **Try it:** runnable block defines `class Tag { constructor(label) { this.label = label; } }`, instantiates `new Tag('hello')` and `new Tag('world')`, prints both `.label` values to the on-canvas console. Reader changes one argument and re-runs.
- **Pass criterion:** student predicts the output of `new Tag('a').label` before running.

### 2.2.3b — `constructor` and its parameters

- **Concept isolated:** `constructor(x, y)` receives the arguments from `new ClassName(x, y)` and stores them on `this`.
- **Try it:** runnable block with `class Point { constructor(x, y) { this.x = x; this.y = y; } }`. Reader instantiates `new Point(3, 4)` and `new Point(0, 0)` and prints both `.x` values. Then changes the constructor body to *not* assign `this.y` and observes that `.y` is `undefined`.
- **Pass criterion:** student explains in one sentence what would happen if `constructor` were missing entirely.

### 2.2.4a — Properties: data on `this`

- **Concept isolated:** a property is data stored on a single instance via `this.name = value` inside a method (typically the constructor).
- **Try it:** runnable block — `class Box { constructor(c) { this.color = c; } }`. Two boxes, two colors. Reader adds a third property (`this.size = 40`) and uses it in a `q5` `square()` call.
- **Glossary rows:** *Property*, *Instance state*.
- **Pass criterion:** student can name three properties of a `Sprite` (e.g. `color`, `pos`, `vel`).

### 2.2.4b — Lab: Read a property

- **Type:** q5play (lesson). Single concept: read `instance.prop`.
- **Starter shape:** scaffold ships `class Box { constructor() { this.color = 'red'; this.size = 40; } }` and `let b; function setup() { new Canvas(200, 200); b = new Box(); } function draw() { background('#222'); /* STEP 1: print b.color and b.size to the on-canvas console using console.log */ }`.
- **Pass criterion:** regex `console\.log\s*\(\s*b\s*\.\s*(color|size)` matches in `draw`.
- **Time:** 5 min.

### 2.2.4c — Lab: Write a property

- **Type:** q5play (lesson). Single concept: assign `instance.prop = value`.
- **Starter shape:** continues from 2.2.4b. Scaffold has the same `Box` class and instance. `// STEP 1:` instructs the student to change `b.color` to a different color when the user presses the space bar.
- **Pass criterion:** regex `b\s*\.\s*color\s*=` matches AND `kb\.presses` appears in `draw`.
- **Time:** 5 min.

### 2.2.4d — Lab: Two sprites, two property values

- **Type:** q5play (lesson). Single concept: each instance owns its property values; mutating one never affects another.
- **Starter shape:** scaffold has `class Box { constructor(c) { this.color = c; } }` and instructs the student to instantiate `b1 = new Box('red')` and `b2 = new Box('blue')`. Render each as a `Sprite` colored by `this.color`. `// STEP N:` instructs: change only `b1.color` and confirm `b2.color` is unaffected.
- **Pass criterion:** two distinct `new Box(` calls AND only one of the two instance variables is reassigned in the test step.
- **Time:** 8 min.

### 2.2.5 — `this` is a noun

- **Concept isolated:** `this` always refers to one specific thing — the instance the method was called on.
- **Try it:** runnable block — `class Greeter { constructor(name) { this.name = name; } greet() { return 'hi ' + this.name; } }`. Two greeters, two `.greet()` calls, two different return values, both rendered on canvas.
- **Pass criterion:** student answers "what does `this` point to inside `greet()` when called on `g1`?" with "`g1`".

### 2.2.5a — Worked example: `this` is a pronoun (substitution rule)

- **Concept isolated:** to read a method body mentally, replace every `this` with whatever variable is on the left of the dot at the call site.
- **Read-along:** projected `class Counter { constructor() { this.n = 0; } tick() { this.n += 1; } }`. Step through `c1.tick()` rewriting the method body in place as `c1.n += 1`. Then step through `c2.tick()` rewriting it as `c2.n += 1`. Same code, different substitution.
- **Pass criterion:** student rewrites a third method (`Counter.double() { this.n *= 2; }`) under the call `c1.double()` with the substitution applied.

### 2.2.7a — Methods: functions that live on a class

- **Concept isolated:** method declaration syntax — inside a class body, methods are written without the `function` keyword.
- **Try it:** runnable block — minimal `class Point { distanceTo(other) { … } }`. Reader removes the `function` keyword from a (deliberately broken) version and watches it work; adds it back and observes the syntax error in the on-canvas console.
- **Glossary rows:** *Method*.
- **Pass criterion:** student can identify methods vs properties in a 6-line class body.

### 2.2.7b — Lab: Method with no params

- **Concept isolated:** a method that takes no arguments and mutates `this`.
- **Starter shape:** scaffold ships `class Counter { constructor() { this.n = 0; } /* STEP 1: write tick() that adds 1 to this.n */ }` plus a `setup`/`draw` that displays `c.n` and calls `c.tick()` on space-bar press.
- **Pass criterion:** regex `tick\s*\(\s*\)\s*\{[^}]*this\.n\s*\+=` (or `\+\+`) inside the class body. Behavioral check: pressing space increments the on-canvas number.
- **Time:** 8 min.

### 2.2.7c — Lab: Method with parameters

- **Concept isolated:** a method that takes arguments and uses them.
- **Starter shape:** continues from 2.2.7b. Scaffold has `// STEP 1: add an addBy(n) method that adds n to this.n`. Driver code maps keys 1/2/3 to `c.addBy(1)`, `c.addBy(2)`, `c.addBy(3)`.
- **Pass criterion:** regex `addBy\s*\(\s*\w+\s*\)` matches AND that parameter is referenced inside the method body.
- **Time:** 8 min.

### 2.2.7d — Lab: Method that returns a value

- **Concept isolated:** a method that returns a value the caller uses.
- **Starter shape:** continues from 2.2.7c. Scaffold has `// STEP 1: add isHigh() that returns true if this.n > 10`. Driver code colors the displayed number red when `c.isHigh()` returns true.
- **Pass criterion:** regex `isHigh[\s\S]*return\s+this\.n\s*>` matches.
- **Time:** 8 min.

### 2.2.7e — Lab: Method calling another `this.method()`

- **Concept isolated:** a method invokes another method on the same instance via `this.other()`.
- **Starter shape:** continues from 2.2.7d. Scaffold has `// STEP 1: add bigStep() that calls this.addBy(5) and then returns this.isHigh()`.
- **Pass criterion:** regex `bigStep[\s\S]*this\.addBy\s*\(\s*5\s*\)[\s\S]*return\s+this\.isHigh\s*\(\s*\)` matches.
- **Time:** 8 min.

### 2.2.7f — Why `this.sprite`, not `extends Sprite`

- **Concept isolated:** when wrapping a q5play primitive, prefer composition (`this.sprite = new Sprite(...)`) over inheritance (`class Enemy extends Sprite`). Wrap until you've mastered the wrapped class.
- **Try it:** projected side-by-side comparison of two snippets that both make a 30×30 red enemy. Inheritance version uses `extends Sprite` and a `super(...)` call; composition version uses `this.sprite = new Sprite(...)`. The reading argues only the composition version: the wrap is an *explicit boundary* — students see the q5play API surface (`this.sprite.color`, `this.sprite.delete()`) instead of inheriting opaque parent behavior.
- **Glossary rows:** *Composition*, *Inheritance* (vocab only).
- **Pass criterion:** student answers "If I want a HealthBar, do I inherit from Sprite or wrap one as `this.sprite`?" with "wrap, because…" reasoning.

### 2.2.7g — Lab: Mutate `this.sprite.x` from a method

- **Concept isolated:** reaching *through* composition — a method on the wrapper class can read or mutate a property of the wrapped sprite.
- **Starter shape:** scaffold ships `class Mover { constructor(x, y) { this.sprite = new Sprite(x, y, 30, 30); } /* STEP 1: write moveRight(dx) that adds dx to this.sprite.x */ }`. Driver code calls `m.moveRight(2)` while the right arrow is held.
- **Pass criterion:** regex `moveRight[\s\S]*this\.sprite\.x\s*\+=` matches.
- **Time:** 8 min.

### 2.2.7h — Lab: Cleanup with `this.sprite.delete()`

- **Concept isolated:** the wrapper class is responsible for cleaning up its wrapped sprite.
- **Starter shape:** scaffold ships `class Bubble { constructor(x, y) { this.sprite = new Sprite(x, y, 20); } /* STEP 1: write pop() that calls this.sprite.delete() */ }`. Driver code calls `b.pop()` on click.
- **Pass criterion:** regex `pop[\s\S]*this\.sprite\.delete\s*\(\s*\)` matches.
- **Time:** 6 min.

### 2.2.10a — When to reach for OOP (3-question checklist)

- **Concept isolated:** decision rule. Three yeses → class. Q1: more than one of this thing? Q2: each has its own state? Q3: each has its own behavior tied to that state?
- **Try it:** four scenarios — (a) tracking the player's score, (b) managing five spawning enemies, (c) one configuration object loaded once at boot, (d) a single timer that ticks every frame. Reader applies the checklist and justifies each verdict. Answer key in a collapsed `<details>` block at the bottom.
- **Glossary rows:** *Decision rule*, *State + behavior*.
- **Pass criterion:** student correctly classifies all four scenarios and matches the answer key.

### 2.2.12a — Encapsulation, inheritance, polymorphism (vocabulary only)

- **Concept isolated:** name three OOP terms students will hear in downstream courses; do *not* practice them.
- **Body:** one paragraph per term. Each definition uses one Q1/Q2 example for grounding (encapsulation: "the Counter class kept `n` private inside; outside code only reads it through methods"). Closes with: *"You will not write `extends`, `super`, or override methods this year. If a future course asks you to, you'll already have the vocabulary."*
- **Glossary rows:** *Encapsulation*, *Inheritance*, *Polymorphism*.
- **Pass criterion:** student can give a one-sentence definition of each term in their own words.
