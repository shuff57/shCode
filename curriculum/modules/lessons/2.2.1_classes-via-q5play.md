# Module 2.2.1 — Classes and Objects via q5play

> **Week 12 · Q2 OOP · 3.5 contact hours (2 sessions) · Environment: q5play in-app editor**
> **SLO focus: SLO 2 PRIMARY (A12.2 written OOP-vs-procedural comparison — dual-enrollment evidence artifact).**

## Context

This is the SLO 2 anchor module. For two weeks students have typed `new Sprite(200, 200, 40, 40)` without understanding what `new` does or what `Sprite` is. This week: the reveal. Every q5play primitive — `Canvas`, `Sprite`, `Group` — is an instance of a class. Students will write their first class (`Enemy`, `Collectible`), see `this` in action, and compare procedural vs OOP approaches side-by-side. A12.2 written response is the **retained teacher artifact for dual-enrollment SLO 2 documentation**.

**Do NOT:**
- Go deep on inheritance, polymorphism, or `super()` — name them, defer practice to downstream courses.
- Turn A12.2 into a code assignment — it's a written reflection. Keeping it written is the SLO 2 requirement.
- Skip the "you've been using classes" framing; it lands the concept emotionally.

---

## Learning Objectives

Students will be able to:
1. Define a class with `constructor()` and instance methods.
2. Instantiate objects with `new` and access properties/methods with dot notation.
3. Explain what `new Sprite(x, y, w, h)` does at the language level.
4. Recognize the `this` keyword inside a method and explain what it refers to.
5. Compare a procedural and an OOP solution to the same problem.
6. Identify when OOP is more appropriate than procedural code.

## Topics Covered
- Class syntax: `class Name { constructor(...) { ... } method() { ... } }`
- `this` keyword — refers to the instance inside a method.
- Instance vs class (blueprint vs built object).
- Properties vs methods.
- `new` operator — what it actually does (allocate + call constructor).
- Every q5play primitive is a class instance — `Sprite`, `Group`, `Canvas`.
- Procedural pattern: parallel arrays + helper functions taking an index.
- OOP pattern: array of instances, each with its own state + behavior.
- Vocabulary only (no implementation required): encapsulation, inheritance, polymorphism.

## Prerequisites
- Modules 2.1.1 and 2.1.2 complete (muscle memory with `new Sprite(...)`).
- Q1 W6–7 functions complete (parameters, return values, scope).

## Worked Examples (teacher-led)

### Worked Example 1 — "You've been using classes" reveal (10 min)
In DevTools (F12) with a running q5play sketch:
```js
> player
Sprite { ... }

> player.constructor.name
"Sprite"

> player.color
"deepskyblue"

> player.color = "red"
> // canvas updates immediately — the property is live
```
Key teaching beat: "The thing called `Sprite` is a **class**. `player` is an **instance**. Everything you've done with `.color`, `.vel`, `.pos` is property access. What you're about to learn is how to write your own `Sprite`-like thing."

### Worked Example 2 — Write an Enemy class live (15 min)
```js
class Enemy {
  constructor(x, y, hp) {
    this.x = x;
    this.y = y;
    this.hp = hp;
    this.sprite = new Sprite(x, y, 30, 30);
    this.sprite.color = 'red';
  }

  damage(n) {
    this.hp -= n;
    if (this.hp <= 0) {
      this.sprite.remove();
    }
  }

  render() {
    this.sprite.text = String(this.hp);
  }
}

let enemy;

function setup() {
  new Canvas(400, 400);
  enemy = new Enemy(200, 200, 10);
}

function draw() {
  background('#222');
  enemy.render();
  if (kb.presses('space')) enemy.damage(1);
}
```
Run. Press space 10 times. Enemy disappears. Discuss what `this` means on each line.

### Worked Example 3 — Procedural vs OOP side-by-side (15 min)
Project the R2 handout. Same problem written two ways:

**Procedural (parallel arrays):**
```js
let enemyX = [];
let enemyY = [];
let enemyHP = [];

function spawnEnemy(x, y, hp) {
  enemyX.push(x); enemyY.push(y); enemyHP.push(hp);
}

function damageEnemy(i, n) {
  enemyHP[i] -= n;
  if (enemyHP[i] <= 0) {
    enemyX.splice(i, 1); enemyY.splice(i, 1); enemyHP.splice(i, 1);
  }
}
```

**OOP (array of instances):**
```js
let enemies = [];

class Enemy { /* same constructor + damage as Worked Example 2 */ }

function spawnEnemy(x, y, hp) {
  enemies.push(new Enemy(x, y, hp));
}

// damage is a method on the instance:
// enemies[0].damage(5);
```

Ask the class: Which is easier to read? Add a new property (e.g., `element`) — which is easier? Delete an enemy — which has fewer places to update?

## Vocabulary

| Term | Definition |
|------|-----------|
| **Class** | A template for creating objects — defines properties and methods |
| **Object / Instance** | An actual object built from a class, with its own property values |
| **Constructor** | The special method that runs when `new ClassName(...)` is called |
| **`this`** | Inside a method, refers to the instance the method was called on |
| **Method** | A function defined inside a class that operates on instances |
| **Property** | A value stored on an instance (`this.color = "red"`) |
| **Instantiate** | To create a new instance with `new ClassName(...)` |
| **Procedural programming** | Organizing code around functions that operate on shared data |
| **Object-oriented programming (OOP)** | Organizing code around objects that bundle data + behavior |
| **Encapsulation** | (Vocabulary only this week) Bundling data + behavior into a single unit |
| **Inheritance** | (Vocabulary only) A class can extend another class |
| **Polymorphism** | (Vocabulary only) Different classes can respond to the same method name |
