# Sub-Module 1.1.2 — Variables and Data Types

> **Book §1.2 · 2 class days · Environment: browser console · Q1 Unit 1.1 Foundations**
> **SLO focus:** Introduces SLO 2 (structured programming foundations via variable + type discipline) primary; reinforces SLO 3.
> **Granularity bar:** each lesson ships exactly one new concept.

## Context

This is where students start writing real code instead of just running teacher-provided lines. The book's §1.2 is entirely about JavaScript's **eight data types** — a closed, enumerable list that pays off for the rest of the year every time a bug turns out to be a type mismatch. The book introduces `let`/`const` casually, without ever teaching the syntax (its very first example is `let message = "hello";`), so this sub-module opens with a short shCode-authored bridge lesson on declaring variables before the book's own content can make sense.

The audience is intro-level: most students have never thought about a value having a "type" as a distinct concept from its content. The one-concept-per-lesson rule is a hard rule here — `typeof null` returning `"object"` is exactly the kind of surprising fact that needs its own moment, not a footnote buried in a bundled reading.

**Do NOT:**
- Teach `if`/`else`, loops, or functions. Booleans appear here only as a *value* (`true`/`false`), not as something you branch on — that's Unit 1.2.
- Skip `BigInt` or `Symbol` because they feel advanced. The book gives each its own subsection precisely because "eight types" is the thing students should walk away able to recite; skipping one breaks the count.
- Let `typeof null === "object"` go unremarked. It is the single most memorable fact in this section — treat it as a feature of the lesson, not an aside.
- Introduce arithmetic operators or type coercion as book content — they are not part of book §1.2. They appear here as shCode-authored bridge material (see Topics Covered), clearly separated from the book-sourced concepts.

## Learning Objectives

Students will be able to:

1. Declare a variable with `let` or `const` and explain when to choose each.
2. Identify the eight basic JavaScript data types and give an example of each.
3. Explain what "dynamically typed" means, with an example.
4. Name the three special numeric values (`Infinity`, `-Infinity`, `NaN`) and say when each appears.
5. Explain what `BigInt` is for and how to create one.
6. Distinguish the three string quote styles and explain what makes backticks different.
7. Use a boolean value and explain where booleans usually come from (comparisons).
8. Distinguish `null` from `undefined` and say when to use each.
9. Explain the difference between a primitive type and the `object` type.
10. Use the `typeof` operator and name its one famous bug.
11. Predict the result of a `+`-based type-coercion expression (e.g. `"5" + 3`).
12. Use at least two arithmetic operators and one comparison operator correctly in a program.

### Reading content guidance

#### R0 — Declaring Variables with `let` and `const` (carry-over, see In-App Lessons)

- **Topic 1: `let` vs `const`** — read before any other reading in this sub-module.
  - `let` declares a reassignable variable; `const` declares one that cannot be reassigned.
  - Default to `const`; switch to `let` only when the value needs to change.
  - Reassigning a `const` throws a `TypeError` immediately.
  - **Try it:** already present in the carried-over content — declare a `let` and a `const`, print both, reassign the `let`.
- **Glossary rows:** `variable`, `declaration`, `assignment`, `let`, `const`, `TypeError`.

#### R1 — Numbers and Special Values (`1-1-20-reading-numbers` or similar; see §Numbered Lesson List)

- **Topic 1: The `number` type** — read before the arithmetic bridge reading (R10).
  - Covers both integers and floating-point values in one type.
  - Arithmetic operators (`+ - * /`) are mentioned here only as a preview; R10 is where they're taught.
  - **Try it:** log an integer, then reassign the same variable to a decimal and log it again — mirrors book's opening `let n = 123; ... n = 12.345;` example.
- **Topic 2: Special numeric values** — same reading, second half.
  - `Infinity`, `-Infinity`, and `NaN` are still `number`-type values, not errors.
  - `1 / 0` produces `Infinity`; `"not a number" / 2` produces `NaN`.
  - Math never crashes the program — worst case is `NaN`, and execution continues (book's "Math in JavaScript is safe" Insight Note).
  - **Try it:** log `1 / 0`, log `Infinity` directly, log `"not a number" / 2` — matches book Definition 1.2.1's own examples.
- **Glossary rows:** `number`, `Infinity`, `NaN`.

#### R2 — BigInt (`1-1-2X-reading-bigint`)

- **Topic 1: Why `number` has a ceiling, and what BigInt is** — single-topic reading (book §1.2.2 is short and self-contained).
  - `number` cannot safely represent integers past `±(2^53 − 1)`.
  - Appending `n` to an integer literal creates a `BigInt`.
  - BigInt is for cryptography, precise timestamps, and anywhere exact large integers matter — not everyday code.
  - **Try it:** log `9007199254740991 + 3` (imprecise) next to `9007199254740991n + 3n` (exact) — book's own Try It Now 1.2.2 comparison.
- **Glossary rows:** `BigInt`.

#### R3 — Strings and Quote Types (`1-1-2X-reading-strings-quotes`)

- **Topic 1: The three quote styles** — read before R4 (string methods).
  - Double and single quotes are "simple" quotes and behave identically.
  - Backticks are "extended" quotes — only they support `${...}` embedding.
  - There is no separate single-character type in JavaScript; a string of length 1 is still just a `string`.
  - **Try it:** log the same sentence three ways — double quotes, single quotes, and a backtick template embedding a variable — then show that `"the result is ${1+2}"` in double quotes prints the literal text, not `3`.
- **Glossary rows:** `string`, template literal (informal — full glossary entry lives with R4).

#### R4 — String Methods in Practice (carry-over, see In-App Lessons)

- **Topic 1: Template literals as the default string-building tool** — reinforces R3 practically.
- **Topic 2: `.length`, `.toUpperCase()`, `.toLowerCase()`, `.includes()`** — same reading, second half.
- Both already present verbatim in the carried-over content; no new authoring needed.
- **Glossary rows (existing):** `template literal`, `interpolation`, `${}`, `method`, `.length`, `.toUpperCase()`, `.includes(x)`.

#### R5 — Boolean (`1-1-2X-reading-boolean`)

- **Topic 1: `true` and `false`, and where they come from** — single-topic reading.
  - Exactly two values: `true` and `false`.
  - Booleans are frequently the *result* of a comparison, not just a value you write directly.
  - **Try it:** log a literal boolean, then log the result of `4 > 1` — book's own two examples.
- **Glossary rows:** `boolean`.

#### R6 — The `null` Value (`1-1-2X-reading-null`)

- **Topic 1: `null` means "intentionally nothing"** — single-topic reading.
  - `null` is a standalone type with exactly one value.
  - It means "this variable intentionally has no value right now" — not a broken reference.
  - **Try it:** declare a variable set to `null`, log it, then log `typeof` of it (foreshadows R9 — the result is the famous `"object"` bug, but don't explain the bug yet, just notice it).
- **Glossary rows:** `null`.

#### R7 — The `undefined` Value (`1-1-2X-reading-undefined`)

- **Topic 1: `undefined` means "never assigned"** — single-topic reading.
  - A declared-but-unassigned variable is automatically `undefined`.
  - Insight Note: never assign `undefined` yourself — use `null` when you want to say "intentionally empty."
  - **Try it:** declare a variable with no value, log it and its `typeof` — matches book Try It Now 1.2.6.
- **Glossary rows:** `undefined`.

#### R8 — Objects and Symbols (`1-1-2X-reading-objects-symbols`)

- **Topic 1: Primitive vs. object, previewed** — single-topic reading, deliberately brief (book itself defers depth to a later chapter).
  - Everything covered so far (number, bigint, string, boolean, null, undefined) is a **primitive** — holds exactly one value.
  - `object` is different: it stores collections of data. `symbol` makes unique identifiers, mostly for advanced object work.
  - **Try it:** create a small object literal (`{ title: "...", pages: 200 }`) and log `typeof` of it — book's own Try It Now 1.2.7.
- **Glossary rows:** `object`, `primitive type`.

#### R9 — The `typeof` Operator (`1-1-2X-reading-typeof`)

- **Topic 1: `typeof` reveals a value's type — and one famous bug** — single-topic reading, capstone of the type list.
  - `typeof x` (or `typeof(x)`, same thing) returns a string naming the type.
  - `typeof null` returns `"object"` — a known 25+-year-old bug kept for compatibility. `null` is not actually an object.
  - `typeof` of a function returns `"function"`, even though functions are technically objects too — flag as trivia, don't dwell (functions aren't taught yet).
  - **Try it:** run `typeof` against one value of every type covered this sub-module, in one block — deliberately the capstone Try-it that ties the whole reading arc together.
- **Glossary rows:** `typeof`.

#### R10 — Arithmetic Operators and Type Coercion (carry-over, see In-App Lessons)

- **Topic 1: The six arithmetic operators** — read after all eight types are known (coercion only makes sense once "type" is a real concept).
- **Topic 2: Type coercion and the `+` trap** — same reading, second half.
- Both already present verbatim in the carried-over content; no new authoring needed.
- **Glossary rows (existing):** `operator`, `expression`, `type coercion`, `+ overload`, `left-to-right evaluation`, `%`.

## Worked Examples (teacher-led)

### Worked Example 1 — Type Detective (10 min)

Book-inspired capstone, run after R9 (`typeof`). Project the console and run `typeof` against one value of every type covered this sub-module, one line at a time, asking students to predict each result before revealing it:

```js
console.log(typeof 42);          // "number"
console.log(typeof 10n);         // "bigint"
console.log(typeof "hi");        // "string"
console.log(typeof true);        // "boolean"
console.log(typeof null);        // "object" — the bug, called out again here
console.log(typeof undefined);   // "undefined"
console.log(typeof { a: 1 });    // "object"
```

Land on the `null` bug a second time — it's worth repeating since it directly contradicts what students just learned about `null` being its own type.

## Vocabulary

| Term | Definition |
|---|---|
| variable | A named container for a value, declared with `let` or `const`. |
| dynamically typed | A property of a language where a variable's type is checked at runtime and can change; JavaScript is dynamically typed. |
| number | A data type for integers and floating-point values, including `Infinity`, `-Infinity`, and `NaN`. |
| BigInt | A data type for integers of arbitrary length, created by appending `n` to a number. |
| string | A data type for text, written with double quotes, single quotes, or backticks. |
| template literal | A backtick string that supports `${...}` embedding of variables and expressions. |
| boolean | A data type with exactly two values, `true` and `false`. |
| null | A standalone type meaning "intentionally no value." |
| undefined | A standalone type meaning "not yet assigned a value." |
| primitive type | A data type that holds exactly one value (number, bigint, string, boolean, null, undefined, symbol). |
| object | A non-primitive type that stores collections of data. |
| typeof | An operator that returns a string naming a value's type; famously returns `"object"` for `null`. |
| type coercion | JavaScript automatically converting a value to a different type, most visibly via `+`. |

## Teacher Notes

- **The `null`-is-`"object"` bug is the single most memorable fact in this sub-module.** It surfaces twice by design (R6's foreshadow, R9's explanation, Worked Example 1's repeat) — don't compress this into one mention.
- **`let`/`const` syntax is not book content.** The book assumes it. Don't skip R0 even though it feels like review for a fast class — some students will hit this sub-module never having declared a variable themselves.
- **Type coercion (R10) is deliberately last.** It only makes sense once "type" is a settled concept; teaching it before the type list creates confusion about *why* `"5" + 3` is surprising.
- **Objects and Symbols (R8) is intentionally thin.** Resist the urge to over-explain — the book itself defers depth to a later chapter, and going deep here breaks the one-concept-per-lesson pacing for no payoff.
- **The two carried-over labs (A2.1, A2.2) are integration checkpoints, not new concepts.** Per the granularity bar, at most one integration lesson belongs per session — these two together close out the sub-module rather than each closing a single day.
- **`1-1-2-reading-data-types` still exists in `lessons/`.** Do not point students at it once this sub-module ships — it duplicates R1/R5/R6/R7/R9's coverage in bundled form. See the In-App Lessons "Not carried over" note for the retirement plan.
