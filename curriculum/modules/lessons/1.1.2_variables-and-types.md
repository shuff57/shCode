# Module 1.1.2 — Variables and Data Types

> **Week 2 · Q1 Console Fundamentals · 3.5 contact hours (2 sessions) · Environment: browser DevTools + in-app `variables-and-types` and `operators-expressions` lessons**
> **SLO focus:** SLO 2 intro (structured programming foundations via variable + type discipline). Reinforces SLO 3 via first real labs.

## Context

Week 2 is where students move from "watching code run" to "writing code that remembers things." Variables and types are the bedrock — students who don't internalize `let`/`const` and the four primary types struggle every week after. Type coercion (especially `"5" + 3`) is the single biggest gotcha in JavaScript and must be addressed head-on rather than avoided.

This module also carries the **Week 2 AP CSP Discussion on binary number systems** — a required AP CSP touch-point that fits naturally because "every variable you declare is stored as bits."

**Do NOT:**
- Introduce conditionals, loops, or functions. Save them for W4+.
- Let `var` take more than 30 seconds of class time — explain it exists, move on.
- Mix up `=` (assignment) and `===` (equality) — hold `===` until W4.

---

## Learning Objectives

Students will be able to:
1. Declare variables using `let` and `const`, and explain when to choose each.
2. Identify and use the four primary JS data types: **number**, **string**, **boolean**, **null/undefined**.
3. Write expressions using arithmetic operators (`+`, `-`, `*`, `/`, `%`, `**`).
4. Use basic string methods (`.length`, `.toUpperCase()`, `.toLowerCase()`, `.includes()`).
5. Predict output of simple type-coercion expressions (`"5" + 3`, `"10" - 3`, etc.).
6. Apply naming conventions (camelCase, descriptive names).
7. Explain sequential processing: code executes top-to-bottom, one statement at a time.

## Topics Covered
- `let` vs `const` vs `var` — keep `var` brief.
- Numbers, strings, booleans, null, undefined.
- Arithmetic operators + operator precedence.
- String concatenation vs template literals (lead with template literals).
- String methods: `.length`, `.toUpperCase()`, `.toLowerCase()`, `.includes()`, `.indexOf()`, `.slice()`.
- `typeof` operator.
- Naming conventions: camelCase, descriptive names.
- Sequential processing: default execution flow (before branching/loops change it).
- **AP CSP:** Binary number systems — how computers store data.

## Worked Examples (teacher-led in class)

### Worked Example 1 — "Design-spec variables" live coding (10 min)
Project the console. Build up this program live:
```js
let width = 250;
let height = 150;
let depth = 75;
const material = "PLA";
const isWaterproof = false;

console.log(`Part is ${width} × ${height} × ${depth} mm`);
console.log(`Material: ${material}, waterproof: ${isWaterproof}`);
```
Discuss: Why `const` for `material` but `let` for dimensions? Why template literals? What's `false` vs `"false"`?

### Worked Example 2 — Type coercion gotcha (10 min)
Type each of these live and ask students to predict before running:
```js
console.log("5" + 3);       // "53" (string concatenation wins)
console.log("5" - 3);       // 2 (subtraction forces numeric)
console.log("10" * "2");    // 20 (math forces numeric)
console.log(5 + 3 + "px");  // "8px" (left-to-right eval)
console.log("px" + 5 + 3);  // "px53" (still left-to-right!)
```
Key teaching point: `+` is overloaded. Every other operator coerces to number.

### Worked Example 3 — `typeof` reveals types (5 min)
```js
let age = 17;
let name = "Jordan";
let enrolled = true;
let nothing = null;
let notSet;

console.log(typeof age);      // "number"
console.log(typeof name);     // "string"
console.log(typeof enrolled); // "boolean"
console.log(typeof nothing);  // "object" — famous JS bug, briefly mention
console.log(typeof notSet);   // "undefined"
```

## Vocabulary

| Term | Definition |
|------|-----------|
| **Variable** | A named container for a value |
| **Declaration** | The statement that creates a variable (`let x = 5`) |
| **Assignment** | Setting a variable's value (`x = 10`) |
| **`let`** | Keyword for declaring a reassignable variable |
| **`const`** | Keyword for declaring a read-only variable |
| **Data type** | The kind of value: number, string, boolean, null, undefined, object |
| **Number** | Any numeric value: `5`, `3.14`, `-42` |
| **String** | Text value in quotes: `"hello"` or `'hello'` or `` `hello` `` |
| **Boolean** | `true` or `false` |
| **`null`** | Intentional "no value" |
| **`undefined`** | "Hasn't been set yet" |
| **Template literal** | String with backticks allowing `${expression}` interpolation |
| **Concatenation** | Joining strings with `+` |
| **Type coercion** | JavaScript automatically converting between types (often unexpectedly) |
| **`typeof`** | Operator that returns the data type of a value |
| **camelCase** | Naming style: `firstWord` then `eachNewWordCapitalized` |

## Teacher Notes

- **Type coercion will confuse students.** Address it directly (Worked Example 2). Ignoring it now = bug magnet for months.
- **Template literals are easier than concatenation.** Lead with them; treat `+` concat as a historical alternative.
- **`var` gets 30 seconds max.** "It exists, we use `let` and `const` instead. Older code you read may have it. Moving on."
- **Students who write `=` expecting equality** need to be caught now — it will plague W4 conditionals otherwise.
- **Naming conventions are style-guide material** (formalized in W3). Introduce camelCase now so W3 feels like codification, not a new burden.
- **Binary discussion should feel tied-in**, not bolted on. Segue: "You just made a variable that stores 17. The computer stores that as `00010001`. Every variable is bits."
- **Pacing note:** Session 1 is heavier on new concepts; Session 2 is heavier on hands-on practice. If running short, cut Activity 11 (Running Speed) — Sporting Goods Shop covers the same territory.
