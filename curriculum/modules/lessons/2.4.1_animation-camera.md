# Module 2.4.1 — Animated Sprites and Camera

> **Week 15 · Q2 Animation & Camera · 3.5 contact hours (2 sessions) · Environment: q5play in-app editor**
> **SLO focus:** Reinforces SLO 3. Adds polish and scale needed for a capstone-worthy game.

## Context

Week 15 transforms a static-canvas sketch into a scrolling world with animated characters. Two big ideas: **sprite animations** (swap frames based on state) and **camera** (world larger than canvas, view follows the player). Camera math confuses students until they see it visually — lead with the analogy "the world doesn't move, your window does." This module also hosts the AP CSP discussion on digital image representation (sprite = pixel grid + RGBA).

**Do NOT:**
- Go deep on sprite sheets — q5play's `addAni(name, url1, url2, ...)` with individual image frames is the simpler default.
- Teach parallax scrolling — that's stretch material.

---

## Learning Objectives

Students will be able to:
1. Attach and switch animations on a sprite (`addAni`, `changeAni`).
2. Use `camera.x` / `camera.y` to move the viewport.
3. Implement a camera that follows the player.
4. Apply smoothing using `lerp()`.
5. Use `layer` to control render order.
6. Explain that the camera is a coordinate transform, not a "real" object.

## Topics Covered
- Sprite animations: `sprite.addAni('walk', frame1, frame2, ...)`, `sprite.changeAni('idle')`.
- Single-frame art: `sprite.image`.
- `camera.x`, `camera.y` — move the viewport.
- Camera-follow: `camera.x = player.x - canvas.w / 2`.
- Smoothing with `lerp(current, target, t)`.
- Layers: `sprite.layer = N` — higher = drawn on top.

### Reading content guidance

Both readings split into two `## <Topic>` subsections per `reading-conventions.md` §3 — each with a `js live` Try-it block and one row contributed to the closing glossary.

#### R1 — Animation (`2-4-3-reading-animation`)

- **`externalLink`:** `/docs/q5play/animation` (the in-app `Animation` chapter).
- **Topic 1: Registering animations with `addAni` + the active animation** — read before `2.4.5 Animated Sprites Sandbox`.
  - **What you'll learn from it:** `sprite.addAni(name, frame1, frame2, …)` registers a named animation; the *first* `addAni` call also becomes the sprite's active animation; you can register multiple (e.g. `idle`, `run`) and pick one with `changeAni(name)`; `frame1…N` can be image URLs OR — for in-class without art assets — placeholder colored rectangles drawn separately while a single-color `sprite.color` stands in.
  - **Try it:** spawn one sprite, `addAni('idle', …)` and `addAni('run', …)` (placeholder colors are fine); each frame, if `kb.pressing('right')` call `changeAni('run')`, else `changeAni('idle')`. Student edits the velocity and watches the active animation flip.
- **Topic 2: Frame timing + single-frame art (`sprite.image`)** — read before `2.4.5 Animated Sprites Sandbox`.
  - **What you'll learn from it:** `sprite.animation.frameDelay = N` slows the cycle (higher N = slower); for single-image sprites use `sprite.image = '…'` instead of `addAni`; `changeAni` is a no-op if the named animation isn't registered, so register *before* you switch.
  - **Try it:** take the Topic 1 sketch, set `sprite.animation.frameDelay = 12` while `running`, and observe the cadence change. Student edits `frameDelay` to find a value that "feels right."
- **Glossary rows from §Vocabulary:** `Animation`, `Frame (animation)`, `Layer`.

#### R2 — Camera (`2-4-7-reading-camera`)

- **`externalLink`:** `/docs/q5play/camera` (the in-app `Camera` chapter).
- **Topic 1: Moving the viewport with `camera.x` / `camera.y`** — read before `2.4.8 Worked Example — Camera Follow`.
  - **What you'll learn from it:** `camera.x` and `camera.y` are the *center* of the view; assigning them shifts what the canvas displays without moving any sprite; the canonical follow pattern is `camera.x = player.pos.x` (or with offset `player.pos.x - canvas.w / 2 + offset` if your origin is top-left); the world doesn't move, the camera does.
  - **Try it:** one player sprite at `(100, 200)`, a wide static ground from `x = 0` to `x = 2000`, and `kb.pressing('right')` adds to `player.vel.x`. Each frame, `camera.x = player.pos.x`. Student walks right and watches the world scroll past.
- **Topic 2: Smoothing with `lerp` + render order with `layer`** — read before `2.4.9 Worked Example — Smooth Camera with lerp`.
  - **What you'll learn from it:** `lerp(current, target, t)` returns a value `t`-fraction of the way from `current` to `target`; small `t` (0.05–0.1) gives a smooth lag, large `t` (0.5+) snaps quickly; assigning `sprite.layer = N` sets the draw order (higher = drawn on top), useful for HUD vs. world.
  - **Try it:** replace the Topic 1 hard-follow with `camera.x = lerp(camera.x, player.pos.x, 0.1)`. Add a second sprite with `sprite.layer = 100` showing the score in the corner. Student edits the lerp `t` and observes the difference between `0.05`, `0.1`, and `0.5`.
- **Glossary rows from §Vocabulary:** `Camera`, `Parallax`, `lerp()`.

## Worked Examples

### Worked Example 1 — Animate a sprite (10 min)
Use placeholder colored squares as "frames" — students can swap in image URLs later.
```js
let player;

function setup() {
  new Canvas(400, 300);
  player = new Sprite(200, 250, 40, 40);

  // Without real images, use colors as placeholder "frames"
  // Students will later supply image URLs
  player.addAni('idle', 'img/idle.png');
  player.addAni('run',  'img/run1.png', 'img/run2.png');
  player.changeAni('idle');
}

function draw() {
  background('#222');
  if (kb.pressing('right')) {
    player.vel.x = 4;
    player.changeAni('run');
  } else {
    player.vel.x = 0;
    player.changeAni('idle');
  }
}
```

### Worked Example 2 — Camera follow (10 min)
```js
let player, world;

function setup() {
  new Canvas(400, 300);
  world = new Group();  // platforms
  for (let x = 0; x < 2000; x += 200) {
    let platform = new Sprite(x, 280, 150, 10);
    platform.collider = 'static';
    world.push(platform);
  }
  player = new Sprite(100, 200, 30, 30);
  world.gravity.y = 15;
}

function draw() {
  background('#224');
  // Camera follows player horizontally
  camera.x = player.pos.x - canvas.w / 2 + 100;
  // Simple movement
  if (kb.pressing('right')) player.vel.x = 5;
  else if (kb.pressing('left')) player.vel.x = -5;
  else player.vel.x = 0;
}
```

### Worked Example 3 — Smooth camera (5 min)
```js
camera.x = lerp(camera.x, player.pos.x - canvas.w / 2, 0.1);
```
Increase `0.1` → snappier; decrease → laggier. Show the feel difference live.

## Challenges

- **Challenge 1:** Add a parallax background — a second set of sprites at a lower `layer` that moves slower than the foreground.

## Vocabulary

| Term | Definition |
|------|-----------|
| **Animation** | A sequence of frames played in order to create the illusion of motion |
| **Frame (animation)** | One image in the sequence |
| **Camera** | The viewport offset — moving it scrolls the view |
| **Parallax** | Different layers moving at different speeds for depth illusion |
| **`lerp()`** | Linear interpolation — `lerp(a, b, t)` returns a value between a and b |
| **Layer** | The draw order — higher numbers draw on top |

## Teacher Notes

- Camera math confuses students. The flashlight analogy lands: "The room (world) is dark and full of stuff. Your flashlight (camera) points at one patch at a time."
- `lerp(current, target, t)` with small t (0.05–0.1) gives smooth camera follow that doesn't feel glued.
- Students without image assets can still pass A15.1 using colored sprites — just document the animation-state change clearly in code.
- AP CSP discussion on image representation fits naturally here — sprites are literally pixel grids with RGBA values.
