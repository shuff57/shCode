# Sub-Module 1.1.1 — Software Lifecycle

> **Book §1.1 · 2 class days · Environment: browser console · Q1 Unit 1.1 Foundations**
> **SLO focus:** Introduces SLO 1 (lifecycle) primary; reinforces SLO 4 (process as algorithm).
> **Granularity bar:** each lesson ships exactly one new concept.

## Context

This is the first sub-module students meet, and it is deliberately conceptual. The book
teaches the *shape* of a software project — four phases, the activities that run alongside
them, and how a single job breaks into a task set — before any syntax. Students who skip
this arrive at chapter 2 able to write a loop but unable to say what part of a project they
are in.

The audience is intro-level: most students have never seen a formal process model. The
one-concept-per-lesson rule is a hard rule here, not a guideline.

**Do NOT:**
- Bundle the four phases, umbrella activities and task sets into one "software lifecycle"
  reading. That is the exact failure the granularity bar exists to prevent — students end
  up with vocabulary they cannot use.
- Go deep on syntax. The two `prompt`/`console.log` lines in Example 1.1.1 are a vehicle
  for showing what "construction" means, not a JavaScript lesson.
- Teach Agile. The book closes §1.1 by pointing forward to it; §1.2 owns it.
- Grade the written assignment on writing quality. A1.1 assesses whether the student can
  describe the lifecycle, not whether they can write an essay.

## Learning Objectives

Students will be able to:

1. Name the four framework activities and state what happens in each.
2. Classify a given project task into the correct framework activity.
3. Define umbrella activities and give two examples.
4. Explain why umbrella activities belong to no single phase.
5. Define a software engineering action.
6. Define a task set (workflow) and relate it to an action.
7. Write a task set for a given action.
8. Define an SDLC methodology.
9. Name the four Ps and explain why two projects elaborate the same framework differently.
10. Define a prescriptive process model.
11. State one strength and one weakness of prescriptive models.
12. Judge whether a prescriptive model fits a described project, with a reason.

### Reading content guidance

#### R1 — The Four Phases (`1-1-4-reading-four-phases`)

- **Topic 1: What a process model is** — read before `1.1.5 Classify the Task`.
  - Teams do not build in random order; a process model says what happens when.
  - Every model uses the same four phases; what changes is how much each one gets.
  - **Try it:** print the four phase names in order with `console.log`, one per line.
- **Topic 2: The four phases named** — inception, elaboration, construction, deployment.
  - What each phase produces, in one line each.
  - **Try it:** log a one-word guess for which phase `console.log("hi")` belongs to, then
    reveal.
- **Glossary rows:** `process model`, `framework activities`, `inception`, `elaboration`,
  `construction`, `deployment`.

#### R2 — Umbrella Activities (`1-1-7-reading-umbrella`)

- **Topic 1: What an umbrella activity is** — read before `1.1.8 Name That Umbrella`.
  - The six listed: training/communication, risk management, configuration management,
    quality management, architecture management, security management.
  - Why they belong to no single phase — the kitchen-cleanup analogy.
  - **Try it:** log two umbrella activities and, for each, which phase you think it touches
    most.
- **Glossary rows:** `umbrella activities`.

#### R3 — Actions and Task Sets (`1-1-9`, `1-1-10`)

- **Topic 1 (`1-1-9`): Software engineering action** — a named job inside a phase.
  - "Define the requirements" is an action inside inception.
  - **Try it:** log one action you'd expect inside construction.
- **Topic 2 (`1-1-10`): Task set / workflow** — the checklist one action needs.
  - Each task produces a real work product, checked before moving on.
  - Task sets vary by project; activities usually overlap rather than run independently.
  - **Try it:** log three tasks for the action "test the greeting app".
- **Glossary rows:** `software engineering action`, `task set (workflow)`.

#### R4 — SDLC and the Four Ps (`1-1-13`, `1-1-14`)

- **Topic 1 (`1-1-13`): SDLC methodology** — a process model following the generic framework.
  - Why teams use one: efficiency, lower risk, predictability, captured best practice.
  - **Try it:** log the four objectives.
- **Topic 2 (`1-1-14`): The four Ps** — problem, project, people, product.
  - The same framework is elaborated differently depending on them.
  - **Try it:** log the four Ps and one sentence on what each changes.
- **Glossary rows:** `SDLC methodology`, `four Ps`.

#### R5 — Prescriptive Models (`1-1-16`, `1-1-17`)

- **Topic 1 (`1-1-16`): Prescriptive process model** — an orderly, prescribed sequence.
  - Waterfall, prototyping, spiral, RUP named as examples only.
  - "Prescriptive" means *it tells you what to do*, nothing fancier.
  - **Try it:** log the four objectives a prescriptive model helps a team hit.
- **Topic 2 (`1-1-17`): Where they break** — rigid, inflexible, poor fit for changing
  requirements. The rigid-recipe analogy.
  - **Try it:** log one project type that suits a prescriptive model and one that does not.
- **Glossary rows:** `prescriptive process model`.

## Worked Examples (teacher-led)

### Worked Example 1 — A JavaScript App Through the Four Phases (10 min)

Book Example 1.1.1. Amara builds a greeting app; walk all four phases, ending in code.

```js
const name = prompt("What is your name?");
console.log("Hello, " + name + "!");
```

Beat per phase: inception sets the goal, elaboration writes the requirement and sketches
the plan, construction is these two lines, deployment is opening the page and seeing it run.
Say out loud that the code is one phase out of four — students over-weight construction.

### Worked Example 2 — A Task Set for Debugging a JavaScript Loop (10 min)

Book Example 1.1.2. Action: "debug the loop." Task set: reproduce, inspect the condition,
trace by hand, fix, retest. Emphasise that each task yields a work product that gets checked.

## Challenges (optional stretch)

- Take an app you use daily and write one sentence per phase describing how it probably went.
- Pick an umbrella activity and argue which phase would suffer most without it.
- Write a task set for "add a second question to the greeting app," then actually do it.

## Assignments

### A1.1 — Describe the Software Development Lifecycle (written, AI-graded)

- **Type:** written response. Primary SLO 1 evidence artifact — retain.
- **Est. time:** 45 min, out of class.
- **Task:** In about one page, describe the four framework activities in your own words.
  Then pick one real software product you use and walk it through all four phases, saying
  what you think happened in each.
- **Requirements:** all four phases named and described; one named real product; one
  concrete sentence per phase for that product; at least one umbrella activity mentioned
  by name.
- **Pass criteria:** every requirement present. Mastery-graded — resubmit until green.
  Not scored on prose quality.

### A1.2 — Console Setup Check (lab)

- **Type:** console lab. Support artifact.
- **Est. time:** 15 min.
- **Task:** Open the browser console, run five provided `console.log` statements, then
  modify two of them to print your own text.
- **Requirements:** all five run without error; two modified statements produce different
  output than the originals.
- **Pass criteria:** all-green Submit gate.
- **Buildable** since 2026-08-11 (`lab-assignment-conventions.md` §7 — console-environment convention).

## Vocabulary

| Term | Definition |
|---|---|
| process model | A plan for what happens when in a software project. |
| framework activities (phases) | The four generic activities every process model includes: inception, elaboration, construction, deployment. |
| inception | The planning phase where goals and overall scope are defined. |
| elaboration | The phase where requirements are analyzed and architecture is designed. |
| construction | The phase where the software is coded and built from the design. |
| deployment | The phase where software is released in usable form to end users. |
| umbrella activities | Activities running alongside every phase — training, risk, configuration, quality, architecture, security management. |
| software engineering action | A named job inside a phase, such as "define the requirements." |
| task set (workflow) | All the tasks required to accomplish one software engineering action. |
| SDLC methodology | A software process model that follows the generic framework of activities. |
| four Ps | Problem, project, people, product — the factors a framework is elaborated around. |
| prescriptive process model | A model advocating an orderly, prescribed sequence of activities. |
