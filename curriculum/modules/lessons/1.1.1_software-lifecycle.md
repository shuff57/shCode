# Module 1.1.1 — What Is Programming / Software Lifecycle

> **Week 1 · Q1 Console Fundamentals · 3.5 contact hours (2 sessions) · Environment: browser DevTools console + in-app `sdlc-overview` lesson**
> **SLO focus:** SLO 1 primary (A1.1 written artifact). SLO 4 intro (first JS statements).

## Context

First module of the course. Students arrive with no assumed programming experience. This week is deliberately **low-syntax** — the goal is building mental models for *what code is* and *what the software lifecycle means*. Hands-on work is limited to reading and running `console.log` statements. The written SDLC assignment (A1.1) is the dual-enrollment SLO 1 documentation artifact and must be preserved in the teacher's evidence binder.

**Do NOT:**
- Introduce variables, conditionals, or functions this week.
- Mention shplay, JSCAD, or any downstream tool.
- Let syntax questions dominate class time — redirect to "we'll cover that next week."

---

## Learning Objectives

Students will be able to:
1. Define, in their own words, what a program is and what a programming language is.
2. Name the five phases of the software development life-cycle (design, development, testing, deployment, maintenance) and describe what happens in each.
3. Distinguish software from hardware with examples.
4. Open the browser DevTools Console in Chrome/Edge/Firefox and identify the prompt + output area.
5. Type and run `console.log(...)` statements — strings, arithmetic, string concatenation, boolean comparisons.

## Topics Covered
- What is code? What is the computer actually doing when it runs code?
- Software vs hardware.
- Why are there so many programming languages? (Brief survey.)
- The software development life-cycle: design → development → testing → deployment → maintenance.
- Introduction to the browser DevTools Console as a coding environment.
- `console.log()` as the first JavaScript statement.
- Sequential execution: code runs one line at a time, top to bottom.

## Prerequisites

## Worked Examples (teacher-led in class)

### Worked Example 1 — "Hello Console" live demo (10 min)
1. Open DevTools on the projector.
2. Type `console.log("hello")` — press Enter. Point at output.
3. Change to `console.log("Mr. Smith's 4th period class")` — discuss quotes as "the thing inside is treated as text."
4. Type `console.log(5 + 3)` — discuss "no quotes means it's math."
5. Ask: "What do you think happens if I type `console.log("5" + "3")`?" Run it. Discuss briefly; tell students "we'll explain this next week."

### Worked Example 2 — SDLC applied to a familiar app (15 min)
Draw the 5-phase cycle on the board. Pick an app students actually use (Instagram, Spotify, Roblox, YouTube). For each phase, ask students to guess what happened:
- **Design** — whiteboard sessions on what problem they're solving
- **Development** — engineers writing the code
- **Testing** — what happens before a new feature ships (automated + beta testers)
- **Deployment** — pushing the update to the App Store / Play Store / web
- **Maintenance** — scheduled maintenance notices, bug fixes, new features

Then ask students to name another app and walk through it together.

## Challenges (optional stretch)

- **Challenge 1:** Using ONLY `console.log` (no variables), print a 3-line ASCII banner with your name. Screenshot the output.
- **Challenge 2:** Pick an app you use daily. Write 3–5 sentences guessing which SDLC phase its team is in RIGHT NOW and why. Extra credit if posted to class discussion.
- **Challenge 3:** In DevTools, type `document.title` and press Enter. What did you see? Try `document.body.innerText.length`. Report back — no need to understand it yet.

## Assignments

### A1.1 — Software Development Life-Cycle Writeup
**SLO 1 PRIMARY ARTIFACT (dual-enrollment documentation)**

| | |
|---|---|
| Type | Written (graded) |
| Points | 20 |
| Est. time | 30 min |
| Due | End of Week 1 |

**Prompt:** In approximately one page (250–400 words), describe the software development life-cycle in your own words.

**Part 1 (10 pts) — Describe the phases.** For each of the five phases below, write 1–2 sentences explaining what happens during that phase and why it matters:
1. **Design (Planning & Requirements)** — Figuring out what to build and how it should work
2. **Development (Coding)** — Writing the actual code that makes the software work
3. **Testing** — Checking that the software works correctly and fixing bugs
4. **Deployment** — Releasing the software so users can access it
5. **Maintenance** — Updating, fixing, and improving the software after release

**Part 2 (10 pts) — Real-world example.** Choose one software product you use (Instagram, Spotify, Google Maps, Roblox, YouTube, Google Docs, etc.) and walk through how you think it went through each of the five phases. Best-guess reasoning is fine — no research required.

**Format:**
- Length: 250–400 words (≈ one page, single-spaced)
- Headings/numbered sections so each phase is clearly labeled
- Your own words (no copied internet definitions)
- Typed submission (document or text entry)

**Rubric:**
| Criteria | Excellent | Satisfactory | Needs Improvement |
|----------|-----------|-------------|------------------|
| Phase descriptions (10 pts) | All 5 phases accurately described in own words | 3–4 phases described, or vague | Fewer than 3 phases, or copied |
| Real-world example (10 pts) | All 5 phases walked through with specific detail | 3–4 phases, or generic example | Fewer than 3 phases |

**SLO mapping:** SLO 1 primary documentation artifact. **Teacher retains digital + hardcopy in SLO evidence binder.**

## Vocabulary

| Term | Definition |
|------|-----------|
| **Program** | A set of instructions that tells a computer what to do |
| **Programming language** | A formal language used to write programs (e.g., JavaScript, Python) |
| **Software** | Programs and data that run on a computer |
| **Hardware** | The physical parts of a computer (screen, keyboard, processor) |
| **SDLC** | Software Development Life-Cycle: the process of planning, creating, testing, and maintaining software |
| **Console** | A text-based tool where you can type and run code, and see output |
| **`console.log()`** | A JavaScript command that prints a value to the console |
| **String** | A text value in JavaScript, surrounded by quotes: `"hello"` |
| **Boolean** | A value that is either `true` or `false` |
| **Concatenation** | Joining two strings with `+` |
| **Sequential execution** | Code runs one line at a time, top to bottom |

## Teacher Notes

- **Keep it conceptual this week.** Resist going deep on syntax. The goal is comfort with the *idea* of programming, not mastery of JavaScript.
- **Use apps students actually use.** Instagram, Spotify, Google Maps, Roblox, YouTube — avoid abstract waterfall diagrams.
- **Do not mention shplay or JSCAD yet.** Mentioning them steals motivation from later quarters. Students should feel curious by Friday — don't give away what's coming.
- **A1.1 is the SLO 1 artifact.** File hardcopy in the teacher SLO evidence binder for dual-enrollment.
- **Karel bridges visual → text-based programming.** Don't skip activities 7–9 even if students seem to "get it" already; the scaffolding matters.
- **DevTools may intimidate some students.** Walk through opening it step-by-step. On Chromebooks: `Ctrl+Shift+J`. On Mac: `Cmd+Option+J`.
- **If a student finishes A1.2 in the first 10 minutes**, point them at Challenge 3 (`document.title` exploration).
