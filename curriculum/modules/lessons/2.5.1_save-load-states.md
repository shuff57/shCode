# Module 2.5.1 — Save, Load, and Game States

> **Week 16 · Q2 State and Persistence · 3.5 contact hours (2 sessions) · Environment: q5play in-app editor**
> **SLO focus:** SLO 2 (state machines as structured programming) + SLO 3 (File I/O via A16.1 persistent storage — **covers Butte outline topic File I/O secondary location**).

## Context

Week 16 is the last hard prerequisite for the W18 capstone. Two big ideas:
1. **Persistent storage** — `storeItem` / `getItem` + JSON export. Without this, a game "forgets" every reload.
2. **State machines** — `menu`, `play`, `win`, `lose` as a variable driving `draw()`. Without this, there's no flow, just one endless gameplay loop.

A16.1 is a **File I/O SLO artifact** — students add persistent high scores to their W15 game and prove persistence by closing the browser and reopening.

**Do NOT:**
- Let students implement state via a giant if-chain — push toward `switch`.
- Accept `getItem('x') + 1` bugs — teach `Number()` / `parseInt` coercion explicitly.
- Put `loadJSON` in `setup()` instead of `preload()` — demo the bug if it comes up.

---

## Learning Objectives

Students will be able to:
1. Save data persistently with `storeItem(name, val)`.
2. Retrieve saved data with `getItem(name)` and coerce to correct type.
3. Export game data as JSON using `save(obj, 'filename.json')`.
4. Load JSON data at runtime using `loadJSON(url)` inside `preload()`.
5. Implement a game state machine (MENU, PLAY, PAUSE, WIN, LOSE).
6. Structure `draw()` around `switch (gameState)`.
7. Handle transitions between states cleanly.

## Topics Covered
- q5play persistent storage: `storeItem`, `getItem`, `removeItem`, `clearStorage`.
- JSON serialization: `JSON.stringify` / `JSON.parse`.
- File export: `save(data, 'name.json')`.
- Async loading: `loadJSON(url, callback)` must live in `preload()`.
- Game state as a variable: `let gameState = 'menu'`.
- State dispatch with `switch`.
- Transitions: triggered by input, timer, or collision outcome.

## Worked Examples

### Worked Example 1 — High score with storeItem (10 min)
```js
let score, highScore;

function setup() {
  new Canvas(400, 400);
  score = 0;
  // Read saved high score, coerce string → number
  highScore = Number(getItem('highScore')) || 0;
}

function draw() {
  background('#222');
  text(`Score: ${score}`, 10, 20);
  text(`Best: ${highScore}`, 10, 40);

  if (score > highScore) {
    highScore = score;
    storeItem('highScore', highScore);
  }
}
```
Run, rack up a score, reload the page — the high score persists. Clear with `clearStorage()` in the console to reset.

### Worked Example 2 — Export level as JSON (8 min)
```js
let level = {
  name: "Level 1",
  platforms: [
    { x: 100, y: 300, w: 200, h: 20 },
    { x: 400, y: 250, w: 100, h: 20 }
  ],
  enemyCount: 5,
  startPos: { x: 50, y: 100 }
};

if (kb.presses('e')) save(level, 'level1.json');  // triggers download
```

### Worked Example 3 — Load JSON in preload (5 min)
```js
let levelData;

function preload() {
  levelData = loadJSON('level1.json');  // async — MUST be in preload
}

function setup() {
  new Canvas(400, 400);
  console.log(levelData.name);  // ready here because preload completes first
}
```
Demo the BUG: move `loadJSON` into `setup` — everything breaks.

### Worked Example 4 — State machine (15 min)
```js
let gameState = 'menu';
let score = 0;

function draw() {
  background('#222');

  switch (gameState) {
    case 'menu':
      text('Press SPACE to start', 100, 200);
      if (kb.presses('space')) gameState = 'play';
      break;

    case 'play':
      // game logic here
      text(`Score: ${score}`, 10, 20);
      if (score >= 10) gameState = 'win';
      if (kb.presses('p')) gameState = 'pause';
      break;

    case 'pause':
      text('PAUSED — press P to continue', 90, 200);
      if (kb.presses('p')) gameState = 'play';
      break;

    case 'win':
      text('YOU WIN — press R to restart', 80, 200);
      if (kb.presses('r')) { score = 0; gameState = 'menu'; }
      break;
  }
}
```
Point out: one variable drives the entire flow. Transitions live inside their cases.

## Vocabulary

| Term | Definition |
|------|-----------|
| **Persistence** | Data that survives a page reload |
| **localStorage** | Browser-provided key/value store (~5 MB) |
| **`storeItem` / `getItem`** | q5play wrappers around localStorage |
| **JSON** | JavaScript Object Notation — a text format for structured data |
| **`JSON.stringify`** | Convert object → JSON string |
| **`JSON.parse`** | Convert JSON string → object |
| **State machine** | A system where behavior depends on a current-state variable |
| **`preload()`** | q5play function that runs before `setup()`; use for async loads |

---

## Teacher Notes

- **`getItem` returns strings.** `getItem('x') + 1` becomes `"01"`, not `1`. Teach `Number(getItem('x'))` or `parseInt(getItem('x'))` from minute one.
- **`loadJSON` is async.** It must live in `preload()`. If a student puts it in `setup()`, the JSON will be undefined when they try to use it. Demo the bug live.
- **State machines vs if-chains:** many students default to giant `if/else if` chains. Redirect to `switch` for readability — easier to add a state later.
- **This module is a prerequisite for the capstone.** Do not let students skip it. Capstone rubric requires persistent storage AND multiple states.
