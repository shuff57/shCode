# Module 2.3.2 — Physics Applications

> **Week 14 · Q2 Collections · 3.5 contact hours (2 sessions) · Environment: q5play in-app editor**
> **SLO focus:** Reinforces SLO 3. Consolidation week before the W14 midterm.

## Context

Week 14 is **consolidation, not new concepts**. Students combine inputs, physics, and groups to build a playable scene with a win condition. Two challenge options: Space Jumper (easier, platformer-ish) or Car on a Ramp (harder, dynamics-heavy). Pendulum worked example seeds joints thinking for W17. The S1 Midterm 3 is administered either at the start or end of this week (teacher discretion).

**Do NOT:**
- Introduce new mechanics — everything this week uses already-learned tools.
- Let students restart from scratch when a physics tuning goes wrong — debug by adjusting ONE property.

---

## Learning Objectives

Students will be able to:
1. Combine input, physics, and collision to build a playable scene.
2. Distinguish `kb.presses(...)` (edge-triggered, one-shot) from `kb.pressing(...)` (level-triggered, continuous).
3. Implement a jump using an impulse force or a sudden `vel.y` change.
4. Check whether a sprite is "on the ground" before allowing a jump.
5. Debug interactions between input-driven and physics-driven motion.

## Topics Covered
- `kb.presses('space')` — fires exactly once on each key-down edge.
- Impulse forces for jumping: `player.vel.y = -jumpStrength` or `applyForce(0, -impulse)`.
- Ground detection: `sprite.touching` or overlap with a ground group.
- Static platforms as level geometry.
- Slopes and angular motion (seeds W17 joints).

## Prerequisites
- Modules 2.1.2 (physics), 2.2.1 (classes), 2.3.1 (groups) complete.

### Reading content guidance

#### R1 — Input edges (`2-3-14-reading-input-edges`)

- **`externalLink`:** `/docs/q5play/input` (the in-app `Input` chapter).
- **Topic 1: Level-triggered with `kb.pressing`** — read before `2.3.15 Edge-triggered Input`.
  - **What you'll learn from it:** `kb.pressing(k)` returns `true` every frame while held (~60×/sec); right tool for continuous motion (run, hold-to-charge); the wrong tool for one-shot actions like jump.
  - **Try it:** sprite that moves while ← / → are held using `kb.pressing` — student edits the velocity and confirms hold-vs-tap behavior.
- **Topic 2: Edge-triggered with `kb.presses`** — read before `2.3.15 Edge-triggered Input`.
  - **What you'll learn from it:** `kb.presses(k)` fires exactly once on each key-down; right tool for jump, shoot, fire-on-tap; demoed against the super-jump bug.
  - **Try it:** the same sprite gets `kb.presses('space')` to set `vel.y = -10` once per tap — student compares with swapping to `kb.pressing` and watching the sprite launch.
- **Glossary rows from §Vocabulary:** `Edge-triggered input`, `Level-triggered input`, `Impulse`.

#### R2 — Touching + ground detection (`2-3-17-reading-touching`)

- **`externalLink`:** `/docs/q5play/collisions` (the in-app `Collisions` chapter — same as 2.3.1's R2 base, but the topic split here focuses on `touching`, not `overlaps`).
- **Topic 1: `sprite.touching(other)` per-frame contact** — read before `2.3.18 Ground Detection`.
  - **What you'll learn from it:** `touching` returns `true` while the sprite is in contact this frame (more reliable than `overlaps` for resting contact); pass a Group to test against many sprites; reads cleanly inside an `if` for state-gating.
  - **Try it:** player sprite + a static `ground` sprite under gravity; print `player.touching(ground)` every frame so the student watches the boolean flip mid-fall.
- **Topic 2: Ground-gated jump idiom** — read before `2.3.18 Ground Detection`.
  - **What you'll learn from it:** combining `kb.presses('space')` + `player.touching(ground)` gives a single-jump-per-landing pattern; without the ground check the player jumps in mid-air infinitely; this is the post-W14 "feels right" baseline.
  - **Try it:** the worked-example 2 ground-detection sketch — student tweaks `world.gravity.y` and `vel.y` jump impulse to feel out the tuning.
- **Glossary rows from §Vocabulary:** `Ground detection`, `` `sprite.touching(other)` ``.

## Worked Examples

### Worked Example 1 — presses vs pressing (5 min)
```js
function draw() {
  // WRONG — fires 60 times while held, causes super-jump
  if (kb.pressing('space')) player.vel.y = -10;

  // RIGHT — fires once per press
  if (kb.presses('space')) player.vel.y = -10;
}
```

### Worked Example 2 — Ground detection (10 min)
```js
let player, ground;

function setup() {
  new Canvas(600, 400);
  world.gravity.y = 20;
  ground = new Sprite(300, 390, 600, 20);
  ground.collider = 'static';
  player = new Sprite(100, 300, 30, 30);
}

function draw() {
  background('#222');
  if (kb.pressing('left'))  player.vel.x = -5;
  else if (kb.pressing('right')) player.vel.x = 5;
  else player.vel.x = 0;

  // Only allow jump when touching ground
  if (kb.presses('space') && player.touching(ground)) {
    player.vel.y = -12;
  }
}
```

## Vocabulary

| Term | Definition |
|------|-----------|
| **Edge-triggered input** | `kb.presses(k)` — fires exactly once on each key-down |
| **Level-triggered input** | `kb.pressing(k)` — returns true every frame while held |
| **Impulse** | A sudden, one-frame velocity change (as opposed to continuous force) |
| **Ground detection** | Checking whether a sprite is in contact with a ground surface |
| **`sprite.touching(other)`** | Returns true if the sprite is touching `other` this frame |
