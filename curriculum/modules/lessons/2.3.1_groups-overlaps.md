# Module 2.3.1 — Groups and Overlaps

> **Week 13 · Q2 Collections · 3.5 contact hours (2 sessions) · Environment: q5play in-app editor**
> **SLO focus:** Reinforces SLO 3 (applied implementation) and SLO 4 (collision detection as an algorithm).

## Context

Week 13 transitions students from "one sprite" to "many sprites managed as a collection." The `Group` class is a specialized array with extra methods — the q5play idiom for managing enemies, collectibles, projectiles, platforms, etc. Students also learn `overlaps()` for collision detection and the safe patterns for spawn/despawn logic. The algorithmic thinking required (spawn condition, collision loop, remove-during-iteration) reinforces SLO 4.

**Do NOT:**
- Let students iterate forward with `for (let i = 0; i < group.length; i++)` AND call `remove` inside — the #1 bug this week. Teach iterate-backwards or collect-then-remove up front.
- Introduce `update()` separate from `draw()` — one function is enough for now.

---

## Learning Objectives

Students will be able to:
1. Create a `Group` and add sprites to it.
2. Iterate a group safely, including during removal.
3. Detect overlaps with `sprite.overlaps(group)` (boolean) and `sprite.overlaps(group, callback)` (per-pair).
4. Spawn sprites at random positions using `random()` / `Math.random()`.
5. Schedule periodic spawns using `frameCount % N === 0`.
6. Despawn sprites that leave the canvas.

## Topics Covered
- `new Group()` and how it extends Array.
- Automatic sprite-to-group association (pass the group as parent, or add explicitly).
- Iterating a group (forEach, for-of, classical for).
- `sprite.overlaps(other)` — returns boolean; callback form receives both sprites.
- `sprite.remove()` — despawns and removes from any groups.
- Spawn patterns: random position, timed spawn via `frameCount`, enemy waves.
- Collision detection as an algorithm — conceptual link to SLO 4.

## Worked Examples (teacher-led)

### Worked Example 1 — Create and iterate a group (10 min)
```js
let enemies;

function setup() {
  new Canvas(400, 400);
  enemies = new Group();
  enemies.color = 'red';

  // Spawn 5 enemies at random positions
  for (let i = 0; i < 5; i++) {
    enemies.push(new Sprite(random(50, 350), random(50, 350), 20, 20));
  }
}

function draw() {
  background('#222');
  // Each enemy wobbles
  for (let e of enemies) {
    e.vel.x = sin(frameCount * 0.1 + e.pos.y) * 0.5;
  }
}
```

### Worked Example 2 — Overlap + scoring (10 min)
```js
let player, apples, score;

function setup() {
  new Canvas(400, 400);
  player = new Sprite(200, 350, 40, 20);
  player.collider = 'kinematic';
  apples = new Group();
  score = 0;
}

function draw() {
  background('#222');

  if (kb.pressing('left'))  player.vel.x = -5;
  else if (kb.pressing('right')) player.vel.x = 5;
  else player.vel.x = 0;

  // Spawn an apple every 30 frames
  if (frameCount % 30 === 0) {
    apples.push(new Sprite(random(20, 380), 0, 20, 20));
  }

  // Check overlaps with callback
  player.overlaps(apples, (p, apple) => {
    score++;
    apple.remove();
  });

  // Despawn apples that fell off-screen — iterate BACKWARDS
  for (let i = apples.length - 1; i >= 0; i--) {
    if (apples[i].pos.y > 410) apples[i].remove();
  }

  text(`Score: ${score}`, 10, 20);
}
```

Point out: the `overlaps` callback handles despawn cleanly; the manual backwards loop is for "off-screen" cleanup.

### Worked Example 3 — The remove-during-iteration bug (5 min, projector)
Demonstrate the BUG intentionally:
```js
// BAD — don't do this
for (let i = 0; i < apples.length; i++) {
  if (apples[i].pos.y > 410) apples[i].remove();  // skips the next apple after each removal
}
```
Show students the visual: apples appear to "skip" getting removed. Explain index shift. Then fix:
```js
// GOOD — iterate backwards
for (let i = apples.length - 1; i >= 0; i--) {
  if (apples[i].pos.y > 410) apples[i].remove();
}
```

## Vocabulary

| Term | Definition |
|------|-----------|
| **Group** | A q5play collection that behaves like an array of sprites with shared defaults |
| **Overlap** | When two sprites' bounding boxes intersect |
| **Spawn** | Create a new sprite during gameplay |
| **Despawn** | Remove a sprite during gameplay |
| **Iterate backwards** | Loop from `length - 1` down to `0` to safely remove items |
| **Callback** | A function passed as an argument to another function (e.g., the overlap handler) |

## Teacher Notes

- The remove-during-iteration bug will catch 80% of students. Front-load the fix.
- `overlaps(other, callback)` is cleaner than manual overlap loops. Lead with the callback form.
- Groups have shared defaults (set `.color` on the Group to color all members). Mention as a time-saver.
- This module reinforces Q1 W8 arrays — students who struggled with arrays in Q1 get a second shot in a motivating context.
