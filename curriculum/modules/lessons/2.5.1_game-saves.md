# Module 2.5.1 — Game Saves

> **Q2 Game Saves · 3.5 contact hours (2 sessions) · Environment: q5play in-app editor**
> **SLO focus:** SLO 3 (File I/O via persistent storage — **covers the Butte outline File I/O secondary location**).
> **Audience:** introductory CS students — for most, this is first encounter with persistent storage *and* JSON serialization. **Granularity bar applies** (`sub-module-spec-conventions.md` §2a): one new concept per lesson.

## Context

This unit makes the q5play game world durable. Three big ideas:
1. **Single-value persistence** — `storeItem` / `getItem` for one key at a time, with `Number(...)` coercion to dodge the type-coercion trap.
2. **Structured persistence** — `JSON.stringify` / `JSON.parse` round-trip for whole-game state (position, score, inventory).
3. **Save UX** — multiple slots, New Game vs Continue on the title screen, and auto-save on level / checkpoint.

A16.1 is the **File I/O SLO artifact** — students ship a complete save system (slots + continue + autosave) on top of their Unit 2.4 game.

**Audience.** Most students are seeing persistent storage AND JSON serialization for the first time. Per the granularity bar, every reading and try-it owns exactly **one** atomic concept; integration happens only inside the worked examples and A16.1.

**Do NOT:**
- Accept `getItem('x') + 1` bugs unchallenged — the type-coercion reading at 2.5.5a is the dedicated antidote; demo the bug live.
- Put `loadJSON` in `setup()` instead of `preload()` — covered as a single-concept reading at 2.5.13.
- Compound `storeItem` + JSON serialization + slot management into one lab — A16.1 is the *only* integration moment; intermediate steps stay single-concept.

> **Cross-unit handoff:** state machines + Continue-restores-the-right-state belong in **Unit 2.6 (Game States)**, not here. The title-screen Continue work in this unit only *detects* a save and routes to "load this slot's data" — wiring it into a state machine is 2.6.1's job (A16.2).

## Learning Objectives

Students will be able to:
1. Save a single value with `storeItem(name, value)`.
2. Retrieve a saved value with `getItem(name)` and explain that the return type is always a string.
3. Coerce a stored value back to a number using `Number(...)` (or `parseInt(...)`).
4. Convert an object to a JSON string with `JSON.stringify(obj)`.
5. Convert a JSON string back to an object with `JSON.parse(str)`.
6. Round-trip a structured value through storage (`stringify → storeItem → getItem → parse`).
7. Remove a single saved value with `removeItem(name)` and wipe storage with `clearStorage()`.
8. Use named slot keys (`'slot1'`, `'slot2'`, `'slot3'`) to manage multiple saves.
9. Delete a single slot, and confirm-before-overwriting a non-empty slot.
10. Detect whether any save exists and render a Continue option on the title screen accordingly.
11. Trigger auto-save on a milestone (level complete, checkpoint, or timer).
12. Load JSON from a URL using `loadJSON(url)` inside `preload()` and explain why it must live there.

## Topics Covered

Each bullet is a single atomic concept and corresponds 1:1 to a Numbered Lesson List slot (§Numbered Lesson List).

**Single-value persistence:**
- `storeItem(name, value)` writes one key.
- `getItem(name)` reads one key; the result is always a string.
- `Number(getItem(...))` (or `parseInt`) is the fix for numeric values.

**Structured persistence:**
- `JSON.stringify(obj)` converts an object → text string.
- `JSON.parse(str)` converts a text string → object.
- Round-trip pattern for whole-game state.

**Save UX:**
- Multiple named slots (`'slot1'`, `'slot2'`, `'slot3'`).
- `removeItem(name)` deletes one slot; `clearStorage()` wipes everything.
- Title-screen save detection → New Game vs Continue.
- Confirm-before-overwrite affordance.
- Auto-save on level / checkpoint / timer.

**File I/O (secondary):**
- `loadJSON(url)` is async; MUST live in `preload()`.

## Prerequisites
- Module 2.4.1 complete — students have a Unit 2.4 game (platformer, side-scroller) to bolt saves onto.
- Arrays + JSON-object-literal familiarity from Q1 fundamentals.

## Environment Setup

Standard q5play in-app editor. `storeItem`, `getItem`, `removeItem`, `clearStorage`, `loadJSON`, and `preload()` are all built into the q5play global API. Use the browser's DevTools **Application → Local Storage** panel to inspect what got written; show it once at the start of Session 1 so students can self-audit their saves.
