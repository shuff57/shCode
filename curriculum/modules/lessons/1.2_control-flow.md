## Context

Module 1.2 teaches branching (`if`/`else`, comparison + logical operators, `switch`), the idea of an algorithm, and loops (`for`, `while`/`do…while`). Audience: first-time programmers in weeks 4–6 of Q1. This is the **full-parity rebuild** that brings 1.2 up to Unit-2 granularity — every concept gets the reading → worked-example → isolated-lab loop, not just a reading.

This rebuild **renumbers the whole module onto one clean integer spine** and **retires the legacy multi-concept console labs** (`conditionals`, `loops`, `algorithm-practice`, `intro-algorithms`), which collided-numbered with the readings, bundled 3 concepts each, taught ternary, and carried non-zero points. Pre-launch, so slug renames are acceptable (data-continuity note in §Carry-overs).

**Do NOT:**
- **Do NOT teach the ternary operator** (`a ? b : c`). It violates the beginner-JS-only rule (`reading-conventions.md` §4). `if`/`else` only.
- **Do NOT bundle concepts.** One `if`-form, one operator, one loop per lesson. If a lab needs "and", split it.
- **Do NOT use q5play / `Canvas` / `Sprite` / `setup()` / `draw()` anywhere.** Console track: `console.log`, named vars, plain `for`, `if`/`else`.
- **Do NOT assign non-zero points.** Every `points`/`totalPoints`/`passingScore` is `0`; green-to-advance.
- **Do NOT invent video URLs.** `videoUrl: ""`, teacher curates.

## Learning Objectives

Students will be able to:
1. Write an `if` statement that runs a block only when a condition is true.
2. Add `else` and `else if` branches to cover every case.
3. Use comparison operators (`< > <= >= === !==`) and explain `===` vs `==`.
4. Combine conditions with `&&`, `||`, and negate with `!`.
5. Choose `switch` for multi-way branching on one value.
6. Define "algorithm" as a precise, ordered set of steps.
7. Implement a simple algorithm (max, even/odd, sum) from pseudocode.
8. Write a `for` loop with init/condition/increment.
9. Iterate an array with a `for` loop.
10. Write a `while` loop and explain `while` vs `do…while` and the infinite-loop trap.

## Topics Covered

*Conditionals:* `if` · `else` · `else if` chain · comparison operators · `===` vs `==` · `&&` · `||` · `!` · `switch`/`case`/`break`/`default`
*Algorithms:* algorithm (definition) · pseudocode → code · find-max · even/odd · sum-to-N
*Loops:* `for` (init/condition/increment) · array iteration with `for` · `while` · `do…while` · infinite-loop trap

## Worked Examples (teacher-led) — new `preview: "example"` lessons

Each is a `content.md` walkthrough: `**Goal:**` line, numbered `## Step` sections each with a ```` ```js live console ```` block, `## Key takeaways`. Beginner JS only, under ~80 lines. (`example-conventions.md`.)

### WE1 — Tracing an if/else chain (1.2.4)
Goal: predict which branch fires before running. Steps: set `let score = 85;` and run the grade-tier chain; change to 55, re-run; add a value that hits `else`. Takeaways: top-to-bottom, first-true-wins.

### WE2 — What each comparison returns (1.2.8)
Goal: every comparison is just `true`/`false`. Steps: `console.log(5 > 3)`; `console.log(5 === 5)`; the `5 === "5"` (false) vs `5 == "5"` (true) contrast. Takeaways: `===` checks type too; prefer it.

### WE3 — Combining conditions (1.2.11)
Goal: `&&`/`||`/`!` glue conditions. Steps: `age >= 13 && age <= 19` teen check; `day === "Sat" || day === "Sun"` weekend; negate with `!isRaining`. Takeaways: `&&` needs both, `||` needs either, `!` flips.

### WE4 — switch vs if-else-if (1.2.15)
Goal: same dispatch, two shapes. Steps: an if-else-if on `let day = "Wed"`; the equivalent `switch`; delete a `break` to show fall-through. Takeaways: `switch` reads cleaner for many cases on one value; `break` matters.

### WE5 — Pseudocode → code (1.2.18)
Goal: turn plain-English steps into JS. Steps: pseudocode comments for "largest of three"; fill code under each comment; run. Takeaways: plan in comments first, then implement.

### WE6 — Tracing a for-loop counter (1.2.23)
Goal: watch `i` move. Steps: `for (let i = 1; i <= 5; i++) console.log(i)`; sum 1..5 into a `total`; print `total`. Takeaways: init once, check each pass, increment at end.

### WE7 — while vs for + the infinite-loop trap (1.2.27)
Goal: `while` when you don't know the count; always change the condition var. Steps: a `while` countdown from 3; a one-shot `do…while`; show (in prose, not run) what omitting `count--` does. Takeaways: every `while` must move toward `false`.

### WE8 — Integration: a tiny menu loop (1.2.29)
Goal: compose a loop + conditionals (the one integration lesson). Steps: an array of menu choices; `for…of`-free plain `for` over it; an `if`/`else if` inside printing a response per choice. Takeaways: loops + conditionals together drive almost every program.
