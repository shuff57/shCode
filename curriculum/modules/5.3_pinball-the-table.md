# Module 5.3: Project — Pinball

**Quarter 2 · the first build · after §5.2 Physics Feel**

## SLO Focus
- **SLO 3:** the module's artifact is a complete, playable game built from the physics the previous two modules taught.
- Reinforces **SLO 2** and **SLO 4**.

## Module Goal
Students plan, then take the pinball scene they already built in 5.2.24 and turn it into a game: something to aim at, a score that counts an event rather than a frame, a way to lose, and a way to start again, then playtest and reflect on it. Everything is built with functions, variables and sprite properties — **no classes anywhere in this module**.

## Pre-requisite snapshot
§5.2 complete: gravity, static bodies, `colliding()`, edge- versus level-triggered input, bounciness and friction, `applyForce`, and the pinball scene at 5.2.24.

## Post-requisite snapshot
Can build a small complete game from parts, and can say what a score is counting. Ready for §5.4, the second build.

**A finished game up front** (added 2026-11-06 as `5.3.0`, so no existing number moved): the screen before the plan
is a play-only reading of the whole pinball game (`5-3-pinball-0-reading-play-the-finished-game`, source `spikes/pinball/script.js`):
a plunger, two flippers, five bumpers, two kickers, popups, sound, three balls, a title and a GAME OVER screen, and a best
score kept with `storeItem`. It asks the student for nothing beyond playing. It deliberately uses things the course
has not taught: flippers are `HingeJoint` (6.13), the screens are a state machine (6.11), the best score is saving (6.10),
and `isSuperFast`, `.shape` and a lives count are taught nowhere. The reading says so in a table of "where you build it",
so a student is never left thinking the unit teaches flippers. The slot is `5.3.0` rather than a renumber because 5.3.1-5.3.7
are cited by number in grader rubrics, Help pointers and script headers; titles sort by number, so `5.3.0` lands first.
Its flippers are driven by `rotationSpeed` **plus** the sideways speed of the bar's middle (turning about an end, not
the middle); setting the spin alone makes the hinge lag and overshoot. The reading's code is the tested sketch.

### The one idea this module is really about
A collision is not an event. `colliding()` is true on every frame two sprites touch, so `if (ball.colliding(bumper)) score += 1` adds sixty points a second. The fix — remember whether you were touching *last* frame — is the same edge-versus-level distinction 5.2.12 taught for keys, one layer down. 5.4.1–5.4.4 build the whole lesson around it.
