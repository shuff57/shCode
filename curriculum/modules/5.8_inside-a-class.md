# Module 5.8: Inside a Class

**Quarter 2 · the last concept module of the object block, immediately after Module 5.7 · the Defender capstone (5.9–5.11) follows**

## SLO Focus
- **SLO 2:** the module's own artifact (5.8.18, the wave spawner) is a class that keeps its own rules and creates and removes other objects while the sketch runs.
- Reinforces **SLO 3** and **SLO 4**.

## Module Goal
Students take a class apart from the inside: where each variable lives, who is allowed to change a property, how one object acts on another, and what belongs to the class rather than to any single instance. They finish by building a wave spawner — objects that create and remove objects while the game runs.

## Pre-requisite snapshot
Module 5.7 complete: methods, `this`, composition over inheritance, an array of instances, the Collectible lab.

## Post-requisite snapshot
Ready for §5.9, the first part of the Defender capstone (5.9–5.11): can keep a rule inside the class that owns the data, can hand one instance to another instance's method, and can create and remove instances while a sketch runs. 5.11 uses these directly (`takeHit` with a floor, `isAlive()`, a method whose parameter is another object, `filter`, `static spawned`). §6.1 Groups and Overlaps comes after the capstone.

### What this module deliberately does not repeat
The first draft of 5.8 was a general "design a class" module. Reading the §5.4 screen bodies killed most of it:

| Was going to be a 5.8 lesson | Already exists |
| --- | --- |
| Design an `Enemy` in a worked example | **5.7.11** Worked Example: Write an Enemy class |
| Plain English to pseudocode for a method | **5.7.7** A Method That Calls a Method |
| Lab: write a class from scratch | **5.7.19** Collectible Class (class, five instances, collect, remove) |
| Lab: add two methods | **5.7.3–5.7.6**, then 5.7.11's `damage` and `render` |
| State inside an instance, `takeHit()` | **5.7.11** (`this.hp` per instance) and `Enemy.damage(n)` |
| Removing dead items from an array | **5.7.19** step 4 |

So 5.8 keeps only what is genuinely untaught: scope **inside** a class (3.2.24 taught local-vs-global in functions only), access, a method that takes another of *your* objects, `static`, and a build that assembles the system.

### The one naming trap
`static` already means something in this course: `new Sprite(x, y, w, h, 'static')` is a **body type** that ignores gravity, taught in 5.2. A `static` class property is a different thing wearing the same word. 5.8.14 says so in its first paragraph.
