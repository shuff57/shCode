# Module 1.4 — Programming Paradigms and Languages

**Quarter 1 · Week 4 · Environment: browser DevTools console**

## SLO Focus
- Reinforces **SLO-2** — structured programming, placed against the other
  paradigms so students can see what discipline it actually imposes.

## Module Goal
Students can say why so many languages exist, tell a low-level language from
a high-level one, say what a paradigm is, name the three structures every
program is built from, tell procedural, object-oriented and functional code
apart on sight, and explain what it means to call JavaScript multi-paradigm.

## Pre-requisite snapshot
Module 1.3 (Documentation and Coding Conventions) complete. Students have
written sequential console code with variables, comments and conventions —
and nothing else. No conditionals, no loops, no functions yet.

## Post-requisite snapshot
Students can name three paradigms and at least one language suited to each,
defend a language choice in terms of the problem being solved, and identify
which structures a described program needs. No new syntax is required of
them.

## Note
Book §1.4 Programming Paradigms and Languages (368 lines). Built 2026-08-16
as a 23-lesson sequence (`1-4-1-slides` … `1-4-23-a1-4-1-two-languages`),
matching module 1.1's density (23 lessons over 253 book lines).

This is a **zoom-out week — no new syntax.** The readings show code in other
paradigms to look at and talk about, never to write. That is deliberate: it
means classes in Q2 moSHion and the array methods in §3.7 land as "oh, that's
the other paradigm from §1.4" rather than as unexplained new vocabulary.
Students have only seen procedural code, so do not grade them on writing
OOP or functional code here.

### Two authoring notes

**Vocabulary follows the book, not the plan.** `curriculum-plan.md` frames
this section as imperative-versus-declarative; the book never uses the word
"declarative" in §1.4 and organises the whole section around
procedural / object-oriented / functional instead. The book is upstream
(BOOK-TO-MODULE §1), so the lessons use the book's three names. "Iteration"
is likewise demoted to a glossary alias for the book's "repetition".

**The functional reading uses `.filter` in its live block**, an idiom
`reading-conventions.md` §4 normally keeps out of beginner readings. That is
the sanctioned exception — the idiom *is* the concept under discussion, and
the student reads and runs it rather than reproducing it. The object-oriented
reading deliberately does **not** show a `class`: the book defers methods to
Chapter 5 and stops at the object literal, so this module does too.
