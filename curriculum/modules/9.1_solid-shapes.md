## Unit Goal
Students make their first solid part by hand, discover that the part is a list
of steps they can go back and change, then read and finally write those steps
as a program. One new idea per lesson.

## SolidCraft OOP pilot, 2026-11-15

The owner reopened work for one script-first pilot, **9.1.12 One Class, Two Parts**
(`9-1-12-lab-one-class-two-parts`). The module stays hidden while it is reviewed;
the earlier eleven lessons still use the older studio and have not been migrated.
No existing lesson id, completion key or numbering changes.

The original shape of the CAD track is in `curriculum-data/jscad-freecad-activities.md`
and `curriculum-plan.md` (Q3 foundations through Q4 synthesis). Keep its progression:
coordinates and shapes → parameters → repeated geometry → reusable part definitions →
measure/build/test → Fits-My-Stuff and its classmate swap test. The old plan called
JSCAD mostly procedural; this pilot deliberately brings the classes students already
used in moSHion into CAD. Do not copy JSCAD imports, `main()`, returned geometry arrays,
`getParameterDefinitions()`, segment settings or its multi-file API into new lessons.
Do not promise its advanced hulls, helical extrusions, text or export formats without
checking the current layer contract.

The pilot assumes JavaScript classes/instances/`this` and the box/hole recipe are
already familiar. One class stores width and position; `build()` adds a box and hole;
two instances differ; changing one instance before building leaves the other alone.
This is reuse and instance state, not a claim that a JavaScript object is a live
SolidCraft body. Later lessons can use arrays of these objects and parameters tied
to a measured item. Inheritance, assemblies and mechanism work wait.

Teacher control uses the existing saved class/per-assignment modes: **Code** keeps
hand tools off; **Both** allows them. The pilot always keeps its script editor.
Students have camera-only input when tools are off, and no toggle of their own.
The script is the saved artifact. Grading receives only a current guarded build and
its per-feature refusals; editing or restoring code invalidates the previous build.
The source cards check the taught syntax, not a full proof of OOP design; the pilot's
independence test is also an explicit student task.

Before release: walk teacher On/Off, two instances and changed dimensions, failed
build vs Check, saved code reopening, and History restoration. The pinned web and
worker assets are required. The local asset linker is not a production deploy packager.

## Sketch-only review pilot (2026-11-16)

`9-1-13-lab-organizer-outline` is a 15-minute 2D milestone for review in the existing
hidden module. Its appended number preserves completion keys; it does not establish
the final order of the new 2D-first course. The learner makes a 60 × 40 mm organizer
base outline, changes measurements, checks it, and saves/reopens editable work.

The lesson mounts the unmodified pinned SolidCraft app beside a script editor. Run
builds native 2D geometry, dimensions and constraints from reSHape Script. Teachers
can also enable its native Sketch toolbar and canvas for hand editing. Our wrapper
keeps the view on XY, hides the global menus and workspace switcher, intercepts
Finish/Cancel and blocks unrelated shortcuts so the Model tools cannot be opened.
The teacher's tools-on setting permits native sketch editing; tools-off covers input
while preserving the design. This is a classroom UI restriction, not a security
boundary against developer tools.

`sketch.json` now contains the complete native SolidCraft document (format 48),
including its parameters, points, curves and constraints, plus a versioned evaluated
geometry/solver snapshot. `script.js` contains the source to rebuild the plan. Older
native-only marker files are preserved, with a Start script action that opens the
lesson starter without replacing the native design. V1 recipes and the private
reference are migrated to native geometry, then rebuilt from their saved script. Save flushes pending native changes before making the existing lesson snapshot;
History and Reset also capture native work first. Reopening imports the exact native
file through SolidCraft's normal file-open path. Temporary OPFS transfer files use
random per-session names and are removed after transfer. The native iframe is
credentialless: its normal OPFS/localStorage recovery files live in a temporary
partition scoped to the lesson page. It cannot reopen a different page's native
recovery files. shCode's existing account-scoped lesson files are the source of
saved work. The pilot requires credentialless iframe support (current Chrome/Edge);
unsupported browsers keep saved work and show an explanation instead of loading
an editor with shared native recovery storage. Broader browser support remains
an integration task.

Run before Check; script builds finish the native sketch. Checks require the exact
source that built the current native design. They read evaluated geometry and confirm
four connected axis-aligned edges, then the requested width/depth. The complete native
design is saved even when it contains curves the pilot checker cannot interpret;
unsupported geometry cannot pass. This is one rectangle milestone, not a general
profile or constraint grader. Native dimensions and constraints remain editable.
Optional AI feedback receives the finished geometry, native constraint count, solver
report and student explanation. Its response is tied to a SHA-256 evidence version.
The server recomputes geometry checks against its own lesson criteria; it does not
certify a server-run CAD build. Feedback never writes a grade or changes completion.
Image input and course-wide migration remain follow-up work. The module stays hidden
pending teacher review.

The native browser walk drew the rectangle through SolidCraft's toolbar, added native
60 mm and 40 mm dimensions, confirmed seven constraints and zero remaining DoF,
finished the sketch, and passed 3/3. Native Save/reopen retained the full document;
changing the native width dimension to 55 failed only the width criterion, and
History restored the native 60 × 40 version with both dimensions and zero DoF. The
teacher pause fixture disabled editing and preserved the scene. The earlier
custom-control walk is superseded by this native workflow. The local server has no
AI binding and displays unavailability; production transport, streaming, malformed
evidence, mismatched versions and no grade writes are checked through the real Pages
Function with a mock AI binding, not a live model response.

Native-specific verification: `scripts/test-solidcraft-native.mjs` checks complete
native round-trips, malformed/3D files, stale/unfinished evidence, native files through
the production save/read and History code, and OPFS transfer cleanup. With `--kernel`
it also migrates legacy rectangles, circles and lines through the actual pinned
solver and compares the rectangle profile to independent area arithmetic.
`scripts/test-cad-feedback.mjs` covers both legacy and native evidence. The existing
3D pilot, runtime routing, AI stream and Workers AI transport regressions also pass.


### Script-driven 2D update (2026-11-16)

The Organizer Outline pilot now places `script.js` beside the native SolidCraft
viewport, with Run and Ctrl/Command+Enter. The source is reSHape Script, evaluated only
in an opaque `allow-scripts` iframe using the same bundled interpreter as 3D. The
existing sketch mapper converts one bounded XY sketch into native SolidCraft commands;
3D features and other planes are refused before replacing the open sketch. The starter
makes a 50 × 30 outline; learners change its inputs to 60 × 40. The default is code
mode, and the teacher controls optional native hand tools.

Native records retain `scriptSource` only while the complete design still matches its
last successful script build. Code changes, unfinished edits, native hand changes,
failed runs and stale reports cannot pass the script-bound criteria. Run preserves
previous native work in History before replacing it; a failed native build reopens the
previous native file and keeps the edited source. Old native-only files remain editable
and saved, but need a script Run before this lesson's Check. Hand edits do not rewrite
source. AI feedback remains tied to the current source-built geometry.

The new `scripts/test-solidcraft-sketch-script.mjs` exercises the actual bundled
interpreter through the opaque-frame protocol, checks source binding and rejects 3D,
wrong-plane and oversized output. With `--kernel` it builds procedural and class-based
sketches on the pinned native engine, verifies dimensions and independently calculated
area, and confirms that no solid body is produced. Native persistence, feedback and
the 3D pilot have separate regression coverage. Browser interaction for this update
has not been re-run.
