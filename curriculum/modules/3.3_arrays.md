# Module 3.3: Arrays

## Module Goal
Students store a list in an array, read it by index, mutate it by index, add and remove items from either end, walk it with a loop, pass it into and build one from a function, and work with a list of lists.

## Pre-requisite snapshot
Module 3.2 (Parameters and Return Values) complete.

## Post-requisite snapshot
Students can hold many values in one variable, process them in turn, and pass whole lists through functions — the shape Module 3.7 (Array Methods) builds on next.

## Note
**Days: 2.** The built lessons' `estimateMins` sum to 213 minutes (3.5 hours), which is exactly
two class days at about 1.75 hours each (`sub-module-spec-conventions.md` §1.1). The 40-minute
capstone is the only long item, so 3 days would leave slack nobody needs. The retired
`weeks:` field was dropped (the spec no longer has one); each lesson's `week` is 8, set on
3.3.1 and 3.3.11 on 2026-10-06 where it had been left null.

**The chart rule.** 3.3.11 is a practice chart, not graded. It carries a weighted 20-point
rubric (two criteria at 7, three at 2, pass at 14), so a wrong loop shape still fails it, and
`grading.formative: true` keeps it out of the course grade (no Written category, no maxScore,
never "missing"). It still shows as started or complete.

Book §3.3 Arrays. **All 18 lessons are built** (3.3.1–3.3.18, see the list above).

Nothing was rewritten; the lessons were renumbered and their `unit` label
corrected.

**Status stays `draft`.** The lessons exist, but this spec has not been brought up to

### ⚠ Folder numbers do not match title numbers here

The Numbered Lesson List above is the slot map: its **Slot** column is the title number, its
**Slug** column is the folder (the id). **Do not rename a folder to match its title.**

These lessons keep their original folder names, because `lesson_state.lesson_id`
is the folder name and renaming one orphans student progress. Order comes from
the number in `lesson.json.title`. See `BOOK-TO-MODULE.md` §7.3.

### Where shCode and book §3.3 differ on purpose (reviewed 2026-10-03)

- **`shift`/`unshift` come after loops.** Book §3.3.4 puts them right after
  `push`/`pop`, before loops (§3.3.5). shCode has them at 3.3.6, after the loops
  reading, because 3.3.7's queue lab needs a loop to show the queue working. No lab
  between them needs either method.
- **`.join()` is taught with `.split()`** (3.3.8), as in the book (§3.3.2).
- **`.at(-n)` is not taught.** The book teaches it in §3.3.2; nothing in shCode
  needs it (the `length - 1` idiom is taught as a loop bound, 3.3.11), so no lab may
  require it and no reference solution may cite it.
