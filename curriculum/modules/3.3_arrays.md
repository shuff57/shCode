# Module 3.3: Arrays

## Module Goal
Students store a list in an array, read it by index, mutate it by index, add and remove items from either end, walk it with a loop, pass it into and build one from a function, and work with a list of lists.

## Pre-requisite snapshot
Module 3.2 (Parameters and Return Values) complete.

## Post-requisite snapshot
Students can hold many values in one variable, process them in turn, and pass whole lists through functions — the shape Module 3.7 (Array Methods) builds on next.

## Learning Objectives

Students will be able to:
1. Store a list in an array, read an item by index (the first is index 0), and read the count with `.length` (3.3.2).
2. Change an item in place with index assignment, `arr[i] = x` (3.3.3, 3.3.4).
3. Walk an array with a `for` loop or `for...of`, and keep a running total in an accumulator (3.3.5, 3.3.12).
4. Spot and fix an off-by-one error at the end of a loop (3.3.6).
5. Add and remove at the end with `push` and `pop`, at the front with `unshift` and `shift`, and choose between them (3.3.2, 3.3.7–3.3.9).
6. Split text into an array with `.split` and count its items (3.3.10, 3.3.11).
7. Trace a loop over an array on a flow chart (3.3.14).
8. Pass an array into a function and read it without changing it (3.3.15, 3.3.16).
9. Seed an accumulator with the first item to find the smallest value (3.3.18).
10. Build and return a new array that is filtered or changed, and leave the original untouched (3.3.17, 3.3.19).
11. Read and update a nested array with `grid[row][col]` (3.3.20–3.3.22).
12. Combine arrays, loops, comparisons and functions in one program (3.3.24).

## Topics Covered

*Reading and changing a list*
- Array, index, `.length`, and the last item at `length - 1`
- Index assignment: `arr[i] = x`
- `push` and `pop` at the end, `unshift` and `shift` at the front, and what each one returns

*Walking a list*
- `for` and `for...of`, and the accumulator
- The off-by-one error: `<=` against `<`, and `arr[arr.length]`
- `.split` to make an array from text, `.join` to make text from an array

*Arrays and functions*
- An array parameter, read without changing it
- Seeding a running best with the first item
- The build-a-new-list pattern: empty array, push, return

*Lists inside lists*
- Nested arrays, `grid[row][col]`, and `grid.length` counting rows

## Prerequisites

- Module 3.2 (Parameters and Return Values): parameters, `return`, and the print-versus-return difference.
- `for` loops and `if` (Modules 2.1 and 2.2), and string `.length` and indexing (Module 2.2).

## Vocabulary

| Term | Definition |
|---|---|
| Array | A variable that holds an ordered list of values |
| Index | The position of an item in an array; the first item is index 0 |
| length | The number of items currently in the array; the last index is length minus 1 |
| push and pop | push adds an item to the end; pop removes the last item and gives it back |
| shift and unshift | unshift adds an item to the front; shift removes the first item and gives it back |
| Off-by-one error | A loop that runs one round too many or too few, such as i <= arr.length instead of i < arr.length |
| Accumulator | A variable that collects a running result across loop rounds, such as total |
| Seed | The starting value of an accumulator; for a smallest or largest, the first item rather than 0 |
| Build-a-new-list pattern | Empty array, push each match or changed value, return the new array |
| Nested array | An array whose items are themselves arrays; a grid is read as grid[row][col] |

## Teacher Notes

**Misconceptions to look for**
- **Off-by-one at `length`.** `i <= arr.length` runs once too often and prints `undefined`; nothing crashes, so students do not see it as an error. 3.3.5 and 3.3.6 are built for this. The checkpoint quiz asks about it first.
- **Index versus count.** An array of 3 items has indexes 0, 1 and 2. Students write `arr[3]` for the third item, or `arr[arr.length]` for the last. Ask them to draw the boxes and number them.
- **`shift`/`unshift` versus `push`/`pop`.** Students mix up which end each one touches. Say the pairs together: push and pop work at the end, unshift and shift work at the front. `pop` and `shift` also give back the item they remove. Writing `arr = arr.push(x)` throws the array away, because `push` returns the new length.
- **Mutation versus returning a new array.** A student who pushes onto the parameter changes the caller's array too. That is the reason 3.3.16 and 3.3.19 insist the original is untouched. Ask: "After the call, what does the original array hold?"
- **Seeding the accumulator with 0.** `smallest` seeded with 0 returns 0 for an all-positive array. 3.3.18 uses an all-positive array so this fails visibly.
- **Forgetting the `return` in the new-array function.** The same missing-return fault as in Module 3.2. The result is `undefined`.
- **Nested index order.** `grid[r][c]` reads row first, then the cell in that row. Students swap them. `grid.length` counts rows, not total values.

**How the array labs are checked.** The array labs (3.3.4, 3.3.8, 3.3.12 and 3.3.22) start from a given array and a few lines of setup, and the grader runs the student's script and checks the array it ends with, not just the words in the code. So a student who prints the right numbers without changing the array still sees a red requirement, and the message says which value it expected. The labs are practice and show as done, never as missing. Two to three hints sit on each requirement; point students to them before you give the answer.

**What to look for while circulating.** A student who prints inside the loop in place of building and returning an array. It looks right in the console and fails the runtime test. Point them back to the print-versus-return reading (3.2.16).
