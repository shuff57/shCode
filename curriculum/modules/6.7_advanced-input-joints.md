# Module 6.7 — Advanced Mechanics

**Quarter 2 · ~3.5 contact hours**
**Environment:** moSHion in-app editor.

> **Renumber note:** Was Unit 2.6 before Unit 2.5 was split into 2.5 (Game Saves) and 2.6 (Game States). Cascaded to 2.7.

## SLO Focus
- **SLO 3** primary (implement + debug a complex interactive system)
- Final content unit before the capstone

## Unit Goal
Students learn moSHion's most expressive mechanics — mouse input, joints (`DistanceJoint` + `HingeJoint`), `applyForce` impulses, and the slingshot composition that pulls them together — then ship a two-player local game (A17.1 Pong-Sumo) that exercises all of it plus `bounciness` push-collision tuning. Most students won't fully master joints; aim for "understand enough to pick one for the capstone." `SliderJoint` is challenge-only.

## Pre-requisite snapshot
- Classes (2.2), groups (2.3), animation/camera (2.4), saves (2.5), state machines (2.6) — everything needed to build a complete game.
- `applyForce`, `bounciness`, and mouse input have NOT been formally taught yet (they were cut from 2.1.2 scope) — this unit introduces them fresh.

## Post-requisite snapshot
- Can read the cursor (`mouse.x` / `mouse.y`) and detect held vs one-shot clicks (`mouse.pressing` vs `mouse.presses`).
- Can drag a sprite (snap pos to cursor + zero vel).
- Can create a `DistanceJoint` and a `HingeJoint`, and remove a joint at runtime.
- Can apply a directional impulse with `applyForce` using a vector from sprite A to sprite B.
- Has implemented the slingshot pattern (joint + drag + release + force).
- Has shipped a two-player game with separate input schemes, tuned push-collision (`bounciness`), state-machine flow, and at least one joint.
- Has a 1–2 page capstone design doc in hand for Day 1 of Unit 2.8.
