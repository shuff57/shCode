# Module 7.3: Inside a Class

**Quarter 2 · the last concept module of the object block, immediately after Module 7.2 · the Defender capstone (7.4–7.6) follows**

## SLO Focus
- **SLO 2:** the module's own artifact (7.3.18, the wave spawner) is a class that keeps its own rules and creates and removes other objects while the sketch runs.
- Reinforces **SLO 3** and **SLO 4**.

## Module Goal
Students take a class apart from the inside: where each variable lives, who is allowed to change a property, how one object acts on another, and what belongs to the class rather than to any single instance. They finish by building a wave spawner — objects that create and remove objects while the game runs.

## Pre-requisite snapshot
Module 7.2 complete: methods, `this`, composition over inheritance, an array of instances, the Collectible lab.

## Post-requisite snapshot
Ready for §7.4, the first part of the Defender capstone (7.4–7.6): can keep a rule inside the class that owns the data, can hand one instance to another instance's method, and can create and remove instances while a sketch runs. 7.6 uses these directly (`takeHit` with a floor, `isAlive()`, a method whose parameter is another object, `filter`, `static spawned`). §6.6 Groups and Overlaps comes after the capstone.

### What this module deliberately does not repeat
The first draft of 7.3 was a general "design a class" module. Reading the §5.4 screen bodies killed most of it:

| Was going to be a 7.3 lesson | Already exists |
| --- | --- |
| Design an `Enemy` in a worked example | **7.2.11** Worked Example: Write an Enemy class |
| Plain English to pseudocode for a method | **7.2.7** A Method That Calls a Method |
| Lab: write a class from scratch | **7.2.19** Collectible Class (class, five instances, collect, remove) |
| Lab: add two methods | **7.2.3–7.2.6**, then 7.2.11's `damage` and `render` |
| State inside an instance, `takeHit()` | **7.2.11** (`this.hp` per instance) and `Enemy.damage(n)` |
| Removing dead items from an array | **7.2.19** step 4 |

So 7.3 keeps only what is genuinely untaught: scope **inside** a class (3.2.24 taught local-vs-global in functions only), access, a method that takes another of *your* objects, `static`, and a build that assembles the system.

### The one naming trap
`static` already means something in this course: `new Sprite(x, y, w, h, 'static')` is a **body type** that ignores gravity, taught in 5.2. A `static` class property is a different thing wearing the same word. 7.3.14 says so in its first paragraph.
