# Module 2.5: Handling Errors with try/catch

**Quarter 1 · Week 7 · Environment: browser DevTools console**

## SLO Focus
- Reinforces **SLO 3** (design/implement/test robust programs): error handling is
  the "test against bad input" half of that SLO, deepened again in §9.3.

## Module Goal
Students can explain what a runtime error does to a running program, tell it apart
from a syntax error, wrap risky code in `try...catch`, read `err.name`/`err.message`,
raise their own errors with `throw` when a value breaks the program's rules, and use
`finally` for cleanup that must run either way. This is intro-level only: custom
error types, input-validation design, and the DevTools debugger workflow are §9.3's
job.

## Pre-requisite snapshot
Module 2.4 (Loop Control and Nested Loops) complete. Cumulative toolkit entering this
module: variables, types, strings, operators, `if`/`else`, `for`/`while`/`do...while`,
`switch`, `break`/`continue`, nested loops. No functions, no arrays (chapter 3).

## Post-requisite snapshot
Students can wrap risky code in `try...catch`, report `err.message` instead of
swallowing an error, throw their own errors when input breaks the program's rules
(not the language's), and use `finally` for cleanup. §9.3 deepens this with custom
error types and input-validation design; §9.3 explicitly does not re-teach basic
`try/catch` syntax.

## What this module added
Built from book §2.5 Handling Errors with try/catch (single meeting, Thu Sep 24,
2026, week 7: last teaching day of chapter 2 before the Ch 2 Group PA and Ch 2
Test). 27 lessons: 1 slides, 8 readings, 3 worked examples, 2 diagrams, 11 console
labs, 1 graded lab (**A2.5.1**, `2.5.26`), 1 challenges bundle (`2.5.27`). Lessons
`2.5.10`/`2.5.11` exist specifically because the team lead flagged empty-catch-block
swallowing as a bad habit that must be explicitly taught, not implied: this reframes
"red console error" from "you broke it" (chapter 2's running theme) to "something you
can plan for."
