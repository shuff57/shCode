# Closed Profiles

**Sequence update, 2026-11-16:** the [current lesson progression](../../CAD-LESSON-PROGRESSION.md)
starts with 2D drawing and 2D OOP before any 3D construction. This earlier draft is a
content reference to adapt to that sequence; its candidate slot numbers and original
3D prerequisites are not new build assignments.

Students learn what a sketch must describe before it can become a solid: a plane, a
closed boundary and dimensions that express intent. The core is a rectangle with an
anchored corner and meaningful side lengths. A prepared pull makes the result visible;
writing extrusion logic is the next module's task.

Proposed slots only, outside the live module loader. Concept sources are book §8.2
coordinates/profiles and §9.1's profile-to-solid idea, plus the current friendly-sketch
examples in reshape-cad. This source join is provisional until the module mapping is
approved. The old JSCAD 2D geometry API is not interchangeable with a constrained sketch.

## Outcomes and prerequisites

Students can locate sketch points in a plane, distinguish a seeded drawing from a
constrained dimension, identify a closed boundary, anchor one point, dimension a
rectangle and explain a free or conflicting condition. A fixed view of an already
built part is not sufficient evidence that the sketch expresses its intended sizes.

Prerequisites: chapter 9 source/recipe/rebuild concepts, mm and coordinate pairs,
variables and method calls. Return values/member handles are needed for the friendly
sketch interface. Revisit them briefly without combining this with new OOP vocabulary.

Atomic ideas: sketch plane; coordinate pair; connected endpoints; closed boundary;
seed geometry vs a rule; anchor; length dimension; a remaining freedom; conflicting
vs redundant rules. Leave arc construction, tangency, trimmed profiles, offsets and
sketching on arbitrary picked faces out of the required core.

## Lesson authoring briefs

**10.1.1–4:** choose the top plane only. The teacher supplies a finished wrapper that
turns the rectangle into a visible solid; the student works on its outline. Do not
teach alternate planes, extrusion distance and camera controls as additional new
concepts in the rectangle lesson. Coordinate changes must be large and unambiguous.

**10.1.5–6:** the open case is a deliberate gap with a named fix, checked on the actual
host. It must not depend on an almost-zero gap the engine silently welds. Sharing the
same endpoint/reference expresses connection; numerical coincidence alone is a weaker
claim. Keep the guard's own refusal sentence. If the chosen script does not produce
that diagnostic, choose another measured example before authoring the lesson.

**10.1.7–8:** a rectangle can have the requested size and still move. Ask what a length
says and what it does not say. Use point/edge identifiers from the example, not raw
kernel face indices or internal solver record numbers.

**10.1.9–12:** separate the initial coordinates that seed geometry from the constraints
that specify it. Anchor one taught corner, then add one width and one depth dimension
in separate labs. The friendly rectangle supplies its ordinary connectivity and
horizontal/vertical relationships; students are not asked to rediscover all of them
in one screen. The report must be interpreted using the independent sketch-check
wording that the host actually provides, not a promised universal “green” state.

**10.1.13–14:** remaining freedom describes allowed motion, not automatically a wrong
shape. A redundant rule and an incompatible rule are different diagnoses; introduce a
redundant-rule comparison only as a teacher extension after the core conflict example.
The known tangency/contact gap is outside this core: do not turn a tiny residual into
a claim that every possible contact is exact.

**10.1.15–16:** the integration uses already-practiced anchoring and two dimensions.
A supplied pull of fixed height keeps the assessment on sketch intent. Chapter 10.2
will make the pull distance and material-removal operation the student-owned work.
No new fillet, hollow, curved-wall cut or outline transformation is required here.

## Teacher reference

This uses the current host's friendly sketch vocabulary. Its rectangular pattern is
based on the measured example gallery; the exact teaching fixtures still need their
own host/solver checks before they become required lab work.

```js
const sk = sketch('top');
const rectangle = sk.rectangle([0, 0], [30, 20]);
sk.at(rectangle.bottom.a, [0, 0]);
sk.length(rectangle.bottom, 30);
sk.length(rectangle.right, 20);
const blank = extrude(sk, 6);
```

Ask which statements give size, which gives position and which turns the profile into
material. The last line is supplied during this module. Coordinate dimensions and
constraint dimensions deliberately agree here; later debug cases vary the seed.

## Assessment and runtime checks

| Case | Evidence needed before release |
| --- | --- |
| Untouched/incomplete starter | Cannot pass all current-build criteria |
| Correct anchored/dimensioned rectangle | Requested size and report through the actual friendly-sketch host |
| Correct dimensions, wrong position | Size may pass while position/intent task does not |
| Explicitly open profile | Honest refusal or no-profile result, with the intended fix demonstrated |
| Conflicting dimensions | Preserved intent or an honest refusal; never silently drop a requested rule |
| Under-constrained shape | Student names an allowed motion; an attractive solid alone is insufficient |
| Restored/edited source | Old solid cannot satisfy a current-build criterion |

Use an independent rectangular-prism calculation for the supplied pull, together with
its measured box; do not bless an arbitrary mesh number as the answer. Some sketch
intent criteria require a prediction/explanation in addition to the existing `model`
checker. Add a bounded checker or use teacher evidence; do not label source regexes a
complete constraint-system test.
