## Instructions

In approximately **one page** (250-400 words), describe the **software development life-cycle (SDLC)** in your own words.

Your response must include **two parts**:

### Part 1: Describe the Phases (10 points)

Describe each of the five phases of the SDLC. For each phase, write 1-2 sentences explaining what happens during that phase and why it matters.

The five phases are:

1. **Design (Planning & Requirements)** — Figuring out what to build and how it should work
2. **Development (Coding)** — Writing the actual code that makes the software work
3. **Testing** — Checking that the software works correctly and fixing bugs
4. **Deployment** — Releasing the software so users can access it
5. **Maintenance** — Updating, fixing, and improving the software after release

### Part 2: Real-World Example (10 points)

Choose **one real software product** that you use (examples: Instagram, Spotify, Google Maps, Roblox, YouTube, Google Docs). Walk through how you think that product went through each of the five SDLC phases.

You do not need to know the actual history — use your best reasoning. For example:
- **Design:** "The Instagram team probably started by deciding they wanted to build an app for sharing photos with filters..."
- **Development:** "Programmers wrote the code for the camera, filters, and the feed..."
- And so on for each phase.

## Tips for Success

- **Start with the phases.** Write about each phase first, then choose your example.
- **Be specific in Part 2.** Don't just say "they tested it." Say *what* they might have tested and *how* — "They probably had people try posting photos to see if the upload worked on slow connections."
- **It's okay to guess.** You're not expected to know exactly how Instagram was built. You're showing you understand the process.
- **Proofread.** Check spelling and that your writing makes sense before submitting.

## Example Excerpt (do NOT copy this — write your own)

> **Testing:** After the developers wrote the code for Spotify's shuffle feature, testers probably tried it with different playlist sizes — a playlist with 3 songs, 50 songs, and 1,000 songs — to make sure it worked in all cases. They also might have checked what happens if you try to shuffle an empty playlist. When they found bugs, the developers went back and fixed them before releasing the update.

This excerpt works because it names a specific feature, describes a realistic testing scenario, and shows understanding of why testing matters.
