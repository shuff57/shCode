§3.1.1 — A button you have already pressed

Calling a Function

You have been calling functions since your very first program. console.log("Hello") calls the log function; Math.sqrt(16) calls sqrt. A function is a named, reusable block of code that performs a task when called.

Think of a vending machine: you press a button, and the machine does its job and hands you a result. You never need to know how it works inside — only which button to press.

When you call one, the program pauses, jumps to the function's code, runs it, and comes back to the spot it left. The parentheses are the tell — Math.PI is a value you read; Math.sqrt(16) is a job you order.

§3.1.2 — Adding to the language

Defining a Function

Calling a function is only half the story. You can also define your own, using the function keyword.

function functionName() {
  // body statements
}

The first line is the header: the keyword, a name, and parentheses. The code between the braces is the body.

In JavaScript the braces mark where the body starts and stops. Indenting is for humans — a line you indent but leave outside the braces is outside the function, no matter how it looks.

§3.1.2 — Two conventions worth naming

The Name, and the Order

Two things make a definition readable to the next person: how you name it, and the order you write things in.

Use camelCase for the name — printWelcome, not print_welcome or PrintWelcome. First word lowercase, each later word capitalized, no underscores.

JavaScript scans the whole file before running anything, registering every function declaration, so a call on line 1 can reach a definition on line 3. That scan-first behavior is called hoisting. Do not lean on it: define first, call after.

§3.1.2 — The central idea

Definition 3.1.1: Function Definition

Definition 3.1.1 — Function Definition

A function definition creates a new function. It has the function keyword, a name, parentheses, and a body wrapped in curly braces.

function functionName() {
  // body statements
}
function functionName() {
  // body statements
}

The header names it; the body between the braces is what actually runs when you call it.

Here is what happens when JavaScript runs this:

  1. It reads the function line and stores the definition. It does not run the body yet.
  2. It skips past the body and keeps reading.
  3. It reaches printWelcome(); — a call. It jumps back into the body.
  4. It runs both console.log() statements.
  5. It returns to the line after the call. The program ends.

Notice the name: printWelcome, not print_welcome. JavaScript convention is camelCase — first word lowercase, each later word capitalized, no underscores. You saw this in Section 1.3 with variable names, and it applies to functions the same way.

§3.1.3 — Why bother writing them

Benefits of Functions

Why write functions at all? Three reasons, each one answering a real problem.

  1. Modularity — a function groups the code for one task in one place.
  2. Reusability — call it as often as you like; three distances is three calls, not three copies.
  3. Maintainability — change one body instead of hunting down every copy.

You have reused other people's functions all along — console.log(), prompt(), Number(). Writing your own is the step from being a user of code to being an author of it.

Key Terms (1 of 2)

function

A named, reusable block of code that performs a task when called.

function call

§3.1 — Conclusions

What to carry forward

The one idea

A function is a named, reusable block of code that runs when you call it. A function call jumps into the body and returns to the line after the call; a function definition uses the function keyword, a camelCase name, parentheses, and a brace-wrapped body.

The common mistake

Confusing a definition with a call. Defining a function only stores it — without parentheses after a name, nothing runs. Close behind: assuming indentation puts a line inside the body when the braces say otherwise.
