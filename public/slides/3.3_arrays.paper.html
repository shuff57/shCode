§3.3.1 — Thirty names is thirty problems

When One Name Is Not Enough

Every variable so far has held exactly one value. That is fine until you need several of the same kind of thing — three test scores, say:

let score1 = 88;
let score2 = 92;
let score3 = 79;

Fine for three. Now imagine a class of thirty — thirty names to invent, and no way to write a loop over them, because score1 and score2 are unrelated names as far as JavaScript is concerned. What you actually want is one name for the whole collection, and a way to ask for the first, the second, or the twenty-ninth.

§3.3.2 — One name, three values

Making a List and Reading From It

Write the values inside square brackets, separated by commas — one name, three values:

let scores = [88, 92, 79];

console.log(scores[0]);   // 88
console.log(scores[2]);   // 79

The number in square brackets after the name picks which element you want. The values are called elements, and their order is part of the data — the first element stays first until you change it.

§3.3.2 — Counting starts at zero

Indexes and length

Counting from zero is the part everyone trips on. Read the index as how far from the start, not as a place in a queue: the first element is zero steps from the start, so it is scores[0].

The length property is the number of elements, so the last element is always at length - 1 — three elements have indexes 0, 1, 2. Read past the end and JavaScript does not stop the program or report an error; it hands back undefined, which is exactly why the bug is so easy to miss.

§3.3.2 — The central idea

Definition 3.3.3: length

Definition 3.3.3 — length

The length property of an array is the number of elements it holds. Because indexes start at 0, the last element is always at index length - 1.

That - 1 is worth saying out loud: three elements, indexes 0, 1, 2. The length is one more than the last index, every time.

JavaScript also offers a shortcut for counting from the end:

Definition 3.3.3: length.

The number of elements an array holds, so the last index is always length - 1. The shortcut at(-1) reads the last element, counting backward from the end.

§3.3.3 — Assign through the index

Changing What Is in a List

An element is assigned to just like a variable — put the indexed name on the left of the =:

let colors = ["red", "green", "blue"];

colors[1] = "yellow";
console.log(colors);   // ["red","yellow","blue"]

The array did not grow — the middle slot now holds something else. An array can hold values of different types at once, [42, "hello", true], though in practice a list is usually one kind of thing.

Context Pause — the quietest bug here

An index that does not exist

An out-of-range index is one of the quietest bugs in this chapter. Nothing turns red. You get undefined, and it travels — add it to a number and you get NaN several lines later, in code that looks innocent. When a calculation on array data comes out NaN, suspect an index before you suspect the arithmetic.

§3.3.4 — Four methods, two ends

Adding and Removing at the Ends

An array's size is not fixed. Four methods change it, one for each combination of which end and add or remove:

  • push(value) — adds to the end.
  • pop() — removes from the end, and returns it.
  • unshift(value) — adds to the start.
  • shift() — removes from the start, and returns it.

The two removers hand back what they removed, so let last = stack.pop(); reads naturally — the same double job return does in Section 3.2.

§3.3.5 — This is what arrays were for

Walking Through a List

A for loop from Chapter 2 can count indexes from 0 up to length - 1:

for (let i = 0; i < scores.length; i++) {
  console.log("Score " + i + ": " + scores[i]);
}

Read the header carefully: it starts at 0 because that is the first index, and continues while i < scores.length — less than, not less than or equal. Writing i <= scores.length runs one extra round and reads scores[3], which is undefined.

§3.3.5 — A loop that does not count

The for...of Loop

Often you do not care about the index — you just want each value in turn:

for (let score of scores) {
  console.log(score);
}

No counter and no condition, so it cannot run off the end. Choose by what the body needs: use for...of when you need the values only, and the counting for when you need the position or want to change elements in place — for...of hands you a copy, not a way back into the slot it came from.

§3.3.6 — One parameter holds the whole list

Arrays and Functions

An array goes into a function like any other value:

function highest(numbers) {
  let best = numbers[0];

  for (let n of numbers) {
    if (n > best) {
      best = n;
    }
  }

  return best;
}

Starting best at numbers[0] rather than at 0 is deliberate: a list of temperatures below freezing would never beat 0, and the function would wrongly answer 0. A function can also hand an array back — start empty, push what qualifies, and return the result. When nothing qualifies, return [] rather than undefined, so the caller can loop over the answer without checking first.

Context Pause — an array is not copied

What the function can change

One thing to watch for, which Section 3.6 takes up properly. A number handed to a function is copied, so the function cannot change the caller's copy. An array is not copied — the function receives a way back to your array, so a push inside a function is visible outside it. Example 3.3.3 sidesteps this by building a brand-new result and leaving the input untouched.

§3.3.7 — Grids, boards, tables

Lists Inside Lists

An element can itself be an array, which is how you store a grid, a board, or a table of rows:

let grid = [[1, 2], [3, 4], [5, 6]];

console.log(grid[2][0]);   // 5
console.log(grid.length);  // 3

Read grid[2][0] left to right: grid[2] is the third inner array, [5, 6], and [0] takes its first element. grid.length is 3 — the number of rows, not the number of numbers; the outer array knows nothing about how long its rows are. A nested loop visits every cell.

Glossary — terms introduced in this section

Key Terms (1 of 2)

Array

An ordered collection of values stored under a single name, written with square brackets.

Element

One value inside an array.

Index

The position of an element, counting from 0; read it as how far from the start.

length

The number of elements in an array; the last index is always length - 1.

push / pop

Add to the end of an array, and remove from the end returning what was removed.

unshift / shift

Add to the front of an array, and remove from the front returning what was removed.

Glossary — terms introduced in this section

Key Terms (2 of 2)

at()

Reads an element, accepting negative positions so at(-1) is the last element.

for...of loop

A loop that runs once per element and hands you the value, with no counter to get wrong.

Off-by-one error

Running a loop one round too many or too few, usually from <= where < was meant.

Accumulator

A variable set before a loop and updated inside it, holding a running total or a list being built.

Two-dimensional array

An array whose elements are themselves arrays, used for grids and tables.

§3.3 — Conclusions

What to carry forward

The one idea

An array is one name for an ordered collection of values, reached by an index that starts at 0. length counts the elements, so the last index is always length - 1, and a for...of loop walks the values without a counter to get wrong.

The common mistake

An off-by-one loop condition. i <= arr.length is still true at i equal to the length, so it runs one extra round and prints undefined. The cure is to say the condition aloud: keep going while i is a real index. The same quiet undefined reaches you from any out-of-range index, and travels into NaN several lines later.
