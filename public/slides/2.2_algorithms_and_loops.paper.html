§2.2.1 — You already know these

What Is an Algorithm?

An algorithm is a sequence of precise instructions that operate on data. A recipe is one:

  1. Preheat the oven to 375 degrees.
  2. Mix flour, sugar, butter, and eggs in a bowl.
  3. Stir in chocolate chips.
  4. Drop spoonfuls onto a baking sheet.
  5. Bake for 10 minutes.

Follow the steps exactly and you get cookies. Skip one, or do them in the wrong order, and you get something else. Step-by-step, in order, nothing left to guess — that is the whole definition.

Insight Note — the gap a computer cannot fill

What the recipe does not say

Notice what the recipe does NOT say: how big a spoonful is, or how hard to stir. A person fills those gaps without thinking. A computer cannot -- every instruction has to be precise enough that there is nothing left to guess. Most beginner bugs are a step that was clear to you and ambiguous to the machine.

§2.2.1 — The central idea

Definition 2.2.1: Algorithm

Definition 2.2.1 — Algorithm

An algorithm is a finite sequence of well-defined, precise instructions that takes some input, performs a computation, and produces an output. Every algorithm must be clear enough that a computer (or a person) can follow it without guessing.

Definition 2.2.1: Algorithm.

Finite, precise, input → computation → output. If a step needs guessing, it is not yet an algorithm.

§2.2.2 — From plan to code

Programs Implement Algorithms

A computer cannot follow a recipe written in English. A program is the same algorithm written in a formal language the machine can execute — JavaScript, here.

Telling a friend

“Wake me up in 10 minutes.” Marisol fills in every gap you left without noticing she did.

Telling a computer

It executes a finite, pre-defined set of instructions exactly as written. Every detail has to be spelled out.

That gap is why programming feels different from talking. The algorithm is what you mean; the program is what you actually said.

§2.2.3 — The ideas travel

Common Ideas Across Languages

Every language is different, but a few ideas show up in all of them. Learn those few and you never start from scratch.

The shared building blocks

Strings, numbers, conditionals, and loops. The abstraction of string data alone lets you work with human-readable text without managing each character by hand.

Three spellings, one algorithm: start at 1, keep going while you are at 5 or below, add 1 each time. The steps are the thing you choose; the syntax is how you write them down. Work the plan out before you start typing.

§2.2.4 — The most powerful idea in the chapter

Introduction to Loops

To print the numbers 1 through 100 without a loop you would write 100 console.log statements. With a loop you write the instruction once and say how many times to repeat it.

A loop has three key parts

  1. Start — where does the count begin?
  2. Condition — when should we stop?
  3. Update — how does the count change each time?

§2.2.4 — All three on one line

The for loop

In JavaScript the for loop puts start, condition, and update together in the header:

for (let i = 1; i <= 5; i++) {
  console.log(i);
}
  • let i = 1 — start at 1.
  • i <= 5 — keep going as long as i is 5 or less.
  • i++ — add 1 to i after each round.

Insight Note — where loops go wrong

Check the condition first

The condition is where loops go wrong most often. i <= 5 runs five times; i < 5 runs only four. Changing one character changes the answer, so when a loop prints one too many or one too few, check the condition before anything else.

§2.2 — Figure 2.2.1

The loop, unfolded

A for loop unfolded. Start, condition, update are three separate boxes; the loop is the arrow returning to the condition.

The condition is tested before the body every time, including the very first. The update is a box the arrow passes through on its way back -- which is why changing i <= 5 to i < 5 removes one whole trip around the circuit.

§2.2.4 — The central idea

Definition 2.2.3: Loop

Definition 2.2.3 — Loop

A loop is a programming construct that repeats a block of code as long as a specified condition remains true.

for (let i = 1; i <= 5; i++) {
  console.log(i);   // runs while i <= 5
}

Definition 2.2.3: Loop.

Start, condition, update. When a loop misbehaves, check those three parts in that order.

§2.2.4 — Worked example

Example 2.2.5: A Loop You Cannot Count in Advance (3/3)

Six goes 3, 10, 5, 16, 8, 4, 2, 1 -- eight steps, and it climbs to 16 on the way to 1, which is more than a little strange for a rule that is supposed to be shrinking things.

Now change n to 7 and run it again. Seven takes sixteen steps and reaches 52. Try 27, which takes 111 steps and climbs past 9000.

That is the difference this example exists to show. Nothing about the number 27 tells you it will take 111 steps. There is no sum you can do first. The loop is indefinite -- the condition decides when to stop, and the only way to learn the count is to run it.

This is why while is written the way it is. A for loop puts start, condition and update on one line because you usually know all three when you write it. A while loop states the condition alone, because it is the only part you are sure of.

Context Pause — an open question

A loop nobody can promise stops

Nobody knows whether this rule reaches 1 for every starting

number. It has been checked by computer far past any number you would type in,

and it has always come back to 1, but "always so far" is not a proof and this

has been open since the 1930s. It is a fair thing to find unsettling: you can

write a loop in four lines and not be able to promise it ever stops.

§2.2.5 — Patterns worth knowing by name

Canonical Algorithms

A canonical algorithm is a well-known algorithm that showcases a design principle useful across a wide variety of problems.

Sorting, the classic

Many ways to sort a list of numbers, and each one teaches a different principle. Some are simple but slow; others fast but harder to understand.

Why study them

The patterns transfer. Syntax changes from language to language; the logic — the algorithm — stays the same.

This chapter focuses on the ideas, not the programming details. The first canonical algorithm you meet is a search.

§2.2 — Figure 2.2.2

Two ways out of a loop

Linear search. The break is the arrow leaving the loop from inside the body, rather than from the condition at the top.

Two different arrows arrive at the not found check. One comes off the top of the loop -- i ran out and nothing matched. The other comes out of the middle of the body: that is the break, taken because we found it and left early. A loop that can only exit from the top can never stop early, however much of the list is left.

Glossary — terms introduced in this section

Key Terms

Algorithm

A finite sequence of precise, well-defined instructions that takes input, performs a computation, and produces output.

Program

An implementation of an algorithm written in a formal programming language that a computer can execute.

Loop

A programming construct that repeats a block of code as long as a condition remains true.

for loop

A loop that combines initialization, condition, and update in one line.

Canonical algorithm

A well-known algorithm that demonstrates design principles applicable across many problems.

String

A data type representing a sequence of characters (letters, digits, punctuation, spaces).

Linear search

A canonical algorithm that checks each item in a list one at a time until the target is found or the list ends.

§2.2 — Conclusions

What to carry forward

The one idea

An algorithm is a precise, finite plan; a program is that plan written in a language a computer can run. A loop repeats a block of code — start, condition, update — so a few lines can do a hundred rounds of work.

The common mistake

An off-by-one condition. i <= 5 runs five times; i < 5 runs four. When a loop prints one too many or one too few, or never stops, read the condition and the update before you touch anything else.
