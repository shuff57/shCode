§3.2.1 — A function that can only say one thing

Passing Information In

Every function in §3.1 did exactly one fixed thing — printHeader() printed the same header every time it was called. That is useful, but limited: a function that can only ever say one sentence is not much more than a shortcut.

Instead, leave a blank in the function for the caller to fill:

function greet(name) {
  console.log("Hello, " + name + "!");
}

greet("Marisol");
greet("Dev");
greet("Priya");

One function, three greetings. The name inside the parentheses is the blank; when you call greet("Dev") the value "Dev" is placed into it, and for the length of that call name behaves like a variable holding "Dev".

§3.2.2 — The empty box and what you write in it

Parameters and Arguments

These two words get used interchangeably in conversation and mean different things precisely.

Parameter

The name listed in a function's definition, inside the parentheses. It acts as a variable in the body, and has no value until the function is called.

Argument

The actual value handed to the function at the call, assigned to the matching parameter for the duration of that call.

A way to keep them straight: the parameter is the empty box drawn on the form, the argument is what somebody writes in it.

§3.2.2 — Position, not name

Order Matters

A function with several parameters matches them to arguments by position, not by name. The first argument goes to the first parameter, always.

function describe(name, age) {
  console.log(name + " is " + age + " years old.");
}

describe("Dev", 19);
describe(19, "Dev");

The second call is not an error. JavaScript does exactly what it was told — name became 19 and age became "Dev" — and produces a nonsense sentence instead of a crash.

JavaScript also lets you pass nothing. A parameter left unmatched holds undefined, so greet() prints Hello, undefined!. A fallback written in the definition, name = "friend", is used only when that argument is missing.

A function that can be applied

Context Pause — a whole category of bug

Same types, silent swap

This is a whole category of bug. A function taking (width, height) called as (height, width) produces a number, not an error — the wrong number, silently. When two parameters have the same type, nothing in the language can catch the swap for you. Name them precisely, and check the order at the call site when a result is mysteriously wrong.

§3.2.3 — Information back out

Getting a Value Back with return

Parameters send information in. return sends a value back out — and that is the difference between doing the arithmetic and letting the caller use it.

function doubleAndPrint(n) {
  console.log(n * 2);
}

function doubleAndReturn(n) {
  return n * 2;
}

doubleAndPrint(5);                                // 10
const result = doubleAndReturn(5);
console.log("I can use this: " + (result + 1));   // I can use this: 11

Both functions computed 10. Only the second one handed it back, so the caller could store it in result and do arithmetic with it. The first threw the number away the instant it was displayed.

Because a returning call is a value, it can sit anywhere a value can: square(3) + square(4) works because each call becomes its number — 9 + 16 is 25.

§3.2.3 — The central idea

Definition 3.2.3: return

Definition 3.2.3 — return

The return statement ends a function immediately and sends a value back to the code that called it. That value becomes the result of the function call, and can be stored in a variable or used directly in an expression.

return is what makes a function call an expression — something with a value — rather than just an instruction. That is why a call can appear anywhere a value can:

square(3) + square(4) works because each call becomes its number — 9 + 16.

Definition 3.2.3: return.

Because the call is a value, it can be stored, compared, added, or passed straight into another call.

§3.2.4 — Two jobs at once

return Ends the Function

return does two jobs at once: it hands back a value, and it stops the function right there. Anything after it does not run.

function check(n) {
  return n * 2;
  console.log("This line never runs.");   // unreachable
}

console.log(check(5));   // 10

That is not a limitation; it is useful. A function can return early as soon as it knows the answer:

function describeNumber(n) {
  if (n < 0) {
    return "negative";
  }
  if (n === 0) {
    return "zero";
  }
  return "positive";
}

There is no else anywhere, and none is needed. Once a return runs, the function is finished — so reaching the line after an if already tells you that if was false.

§3.2.5 — The most common misunderstanding

Printing Is Not Returning

This is the single most common misunderstanding about functions, and it is worth slowing down for. console.log shows a value to a human; return gives a value to the program.

function addAndPrint(a, b) {
  console.log(a + b);
}

const total = addAndPrint(2, 3);
console.log("total is: " + total);   // total is: undefined

The 5 appears — the arithmetic was correct — but total is undefined, because addAndPrint never returned anything. The number was displayed and then discarded.

The fix is one word: return a + b;. A function that finishes without executing a return produces undefined — and using that in arithmetic gives NaN. As a rule, return the result and let the caller decide whether to print it.

§3.2.6 — Small functions into big programs

Building With Returned Values

Because a call to a returning function is a value, calls can be fed straight into other calls. This is how small functions build up to big programs.

function double(n) {
  return n * 2;
}

function addTen(n) {
  return n + 10;
}

console.log(double(addTen(5)));   // 30
console.log(addTen(double(5)));   // 20

The inner call runs first. addTen(5) becomes 15, then double(15) becomes 30. Reversing the order gives a different answer, which is worth checking whenever nested calls surprise you.

Example 3.2.2 stacks three returning functions — subtotal, withTax, format — into one line, format(withTax(subtotal(4.5, 3))). None of them prints anything, which is exactly what lets the chain exist. Functions that return compose; functions that print do not.

Glossary — terms introduced in this section

Key Terms

Parameter

A name listed in a function's definition, acting as a variable inside the function body; it has no value until the function is called.

Argument

The actual value handed to a function when it is called, assigned to the matching parameter by position.

return

A statement that ends a function immediately and sends a value back to the caller.

Return value

The value a function call produces, usable in a variable, an expression, or another call.

Early return

Returning as soon as the answer is known, which removes the need for else branches.

Default parameter

A fallback value written as name = "friend" in the definition, used only when that argument is missing.

undefined

What a function call produces when the function finished without executing a return.

Composition

Using the value returned by one function directly as the argument to another, as in double(addTen(5)).

§3.2 — Conclusions

What to carry forward

The one idea

A parameter is the name listed in a function's definition; an argument is the value passed at the call, matched position by position. return ends the function and hands a value back, which is what makes a call usable in a variable or a larger expression.

The common mistake

Using console.log where return was needed. The number appears on screen and the function looks correct, but the call produces undefined — and any arithmetic on it becomes NaN. When a variable holding a result is undefined, look for the missing return.
