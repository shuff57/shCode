## Copied from that commit by `npm run sync:moshion`

- `moshion.js`, with ONE line changed: the empty-catalog fallback returns
  `base: '/moshion/textures/'` here where the repo says `base: 'textures/'`, because shCode
  serves the engine at `/moshion/`. The sync re-applies it (`UP_LINE`/`OUR_LINE` in
  `scripts/sync-moshion.mjs`) and stops if the repo's line ever changes.
- `docs/moshion.d.ts` and `planck.min.js`, byte for byte.
- The docs: the repo's built `docs/data/moshion-docs.js` (from its `docs/content/`) becomes
  `lib/moshion-docs-shared.generated.ts`. The docs are written once, in the moshion repo.

## Kept as shCode's own (never copied over from the repo)

- `extras.js`: what needs shCode's server, so it cannot live in the engine. Account saves
  (`save`/`load`/`saved` with `'remote'`), online rooms (`online`) and `multiplayer()`.
  Loaded after `moshion.js` by `runner.html` and by `scripts/moshion-harness.mjs`, so a sketch
  behaves the same headless. Its globals are defined only where a sketch has no name of its
  own (`provide()`). Tests: `scripts/test-moshion-extras.mjs`, `scripts/test-moshion-multiplayer.mjs`.
- `runner.html`: shCode's preview host (`components/MoshionPreview.tsx` talks to it), with the
  storage, rooms and font bridges the repo's runner does not have. Upstream runner behaviour is
  ported by hand (from `3f1e70a`: the `randomSeed(...)` line after `extras.js`).
- `textures/` (126 textures, more than the repo's 105) and its `textures.js`/`textures.json`,
  generated by `scripts/make-moshion-textures.py` with base `/moshion/textures/`;
  `scripts/check-moshion-textures.mjs` checks them against the PNGs.
- `assets/`: the 8-bit sound palette, generated by `scripts/make-moshion-sounds.mjs` (the same
  files as upstream since `f259b22`), the tiles and the other pictures.
- `fonts/`: written by `scripts/fetch-moshion-fonts.mjs` (run by hand, output committed).
- `docs/LICENSE.md`: the licence notes for the engine, planck.js and the assets.
- shCode's own docs pages and notes on shared pages: `lib/moshion-docs-shcode.ts`.

## To resync

1. Land the change in the moshion repo first (engine, typings or `docs/content/`), and run its
   `node scripts/build-docs.mjs` so `docs/data/moshion-docs.js` is current.
2. Here: `npm run sync:moshion`. It reads `origin/main` (or `MOSHION_REF=<branch>` for a branch
   still under review), never the repo's working tree. It copies the files above, regenerates
   the editor's autocomplete, runs the moSHion gates (the docs, every docs example and lesson
   sketch, the extras, the autocomplete, docs coverage) and stamps this file.
3. If `scripts/test-moshion-docs.mjs` says the repo changed a page that
   `lib/moshion-docs-shcode.ts` overrides, read the new text, fix the override, and update its
   `basedOn` hash.
4. Commit, then deploy. `npm run deploy` runs `sync-moshion --check` first and refuses while this
   copy differs from upstream `main` (`MOSHION_ALLOW_BEHIND=1` overrides it for an urgent
   shCode-only fix).
